# สั่ง sync ข้อมูลจากตู้

ใช้เมื่อผู้ใช้บอกว่าข้อมูลไม่อัปเดต ขอดึงข้อมูลใหม่ หรือขอ backfill ยอดขายย้อนหลัง

⚠️ **skill นี้เปลี่ยนแปลงข้อมูลจริง** (เขียนลง Supabase) — ก่อนสั่งรันครั้งแรกในบทสนทนา
ให้ยืนยันกับผู้ใช้ก่อนว่าจะสั่งอะไร โดยเฉพาะ backfill ที่ระบุช่วงวันที่

## คำสั่ง

```bash
cd "c:/Projects/divisionX Card" && py deploy/agents/trigger_workflow.py <job> [options]
```

| ต้องการ | คำสั่ง |
|---|---|
| ดูรายการงานทั้งหมด | `--list` |
| สต็อกหน้าตู้ ทุกยี่ห้อ | `stock` |
| สต็อกเฉพาะยี่ห้อ | `vms-stock` / `ww-stock` / `payif-stock` |
| ยอดขายเมื่อวาน ทุกยี่ห้อ | `sales --days 1` |
| backfill ยอดขาย | `ww-sales --from 2026-08-01 --to 2026-08-03` |
| เช็คผลรันล่าสุด | `--status vms-stock` |

## ข้อควรรู้ก่อนสั่ง

- **backfill ยอดขายห้ามเกิน 5 วันต่อครั้ง** — ข้อมูลจากตู้อาจถูกตัด สคริปต์กันไว้แล้วและจะ error
  ถ้าผู้ใช้ขอช่วงยาวกว่านั้น ให้แบ่งสั่งทีละไม่เกิน 5 วัน แล้วบอกผู้ใช้ว่าแบ่งเป็นกี่รอบ
- workflow ทำงานบน GitHub Actions ใช้เวลา **~1-3 นาที** — คำสั่งส่งแล้วจบทันที ไม่รอผล
  ถ้าผู้ใช้อยากรู้ผล ให้เว้นสักครู่แล้วสั่ง `--status <job>` หรือให้เขาถามซ้ำทีหลัง
- ยอดขาย sync แบบ upsert → สั่งซ้ำช่วงเดิมได้ ไม่เกิดข้อมูลซ้ำ
- ต้องมี `GH_PAT` (scope `workflow`) ใน `deploy/.env.local` — ถ้าเจอ error 401/403 แปลว่า token
  หมดอายุหรือ scope ไม่พอ ให้บอกผู้ใช้ไปออก PAT ใหม่ อย่าพยายามแก้เอง

## หลัง sync เสร็จ

ชวนผู้ใช้ดูผลต่อด้วย skill `dvx-stock` (ของเหลือรายช่อง) หรือ `dvx-sales` (ยอดขาย)
