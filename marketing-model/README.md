# marketing-model

ตัวสร้างคอนเทนต์การตลาดสำหรับธุรกิจอสังหาริมทรัพย์ไทย (ขายฝาก · จำนอง · ประเมินทรัพย์ · ซื้อขาย)

รับโจทย์หนึ่งชุด แล้วคืน **พาดหัว · แคปชั่น · บรีฟภาพ · สคริปต์วิดีโอ · แฮชแท็ก · CTA ·
คำแนะนำช่องทาง · payload สำหรับ automation · คำเตือนความเสี่ยง** ครบในครั้งเดียว

โมดูลนี้ถอดมาจากระบบคอนเทนต์ที่ใช้งานจริงของอีกโปรเจกต์หนึ่ง โดยเก็บเฉพาะ "วิธีคิด"
ที่ไม่ผูกกับสินค้าเดิม แล้วเขียนเนื้อหาใหม่ทั้งหมดให้เป็นธุรกิจอสังหาริมทรัพย์ไทย

---

## คุณสมบัติที่ตั้งใจออกแบบไว้

| | |
|---|---|
| **ไม่ต้องมี API key** | `runMarketingModel()` เป็นฟังก์ชันธรรมดา ไม่ async ไม่เรียกเน็ต ได้ข้อความไทยใช้ได้จริงทันที |
| **ไม่ผูกกับ LLM เจ้าไหน** | ถ้าจะใช้ AI ให้ส่ง fetcher เข้ามาเอง โมดูลนี้ไม่มี endpoint ไม่มี SDK ไม่มีคีย์ |
| **ไม่ผูกกับ UI/framework** | JavaScript ล้วน ไม่มี React ไม่มี DOM ไม่แตะ `fs` / `process.env` / ฐานข้อมูล |
| **ผลลัพธ์เดิมสำหรับอินพุตเดิม** | ความหลากหลายมาจาก hash ของอินพุต ไม่ใช่ `Math.random` → ทดสอบได้ ผู้ใช้ไม่งง |
| **มีด่านตรวจความเสี่ยงในตัว** | จับคำรับประกันการอนุมัติ/ผลตอบแทน คำขั้นสุด ข้อมูลส่วนบุคคล และอักษรลาวที่ปนมาในข้อความไทย |
| **ไม่มีความลับในไฟล์** | ไม่มี token ไม่มี path เฉพาะเครื่อง ไม่มี URL ภายใน |

## ติดตั้ง

ไม่มี dependency ใด ๆ — ก๊อปโฟลเดอร์ `marketing-model/` ทั้งโฟลเดอร์ไปวางใน AssetX Estate
เช่น `src/lib/marketing-model/` แล้วใช้ได้เลย (ต้องการ Node 18+ หรือเบราว์เซอร์สมัยใหม่)

ตรวจว่าก๊อปมาครบและยังทำงานถูก:

```bash
cd src/lib/marketing-model
node selftest.mjs      # ต้องขึ้น "ผ่าน 97 · ไม่ผ่าน 0"
```

## ใช้งานใน AssetX Estate

### 1. หน้า `/marketing` — สร้างคอนเทนต์ทันทีที่กด

```jsx
import { useState } from "react"
import { runMarketingModel, getOptions } from "../lib/marketing-model"

const OPTIONS = getOptions()   // ไว้ทำ dropdown โดยไม่ต้อง hardcode

export default function MarketingStudio() {
  const [form, setForm] = useState({
    objective: "lead_owner",
    audience: "เจ้าของที่ดินที่ต้องการสภาพคล่อง",
    offer: "ประเมินทรัพย์เบื้องต้นฟรี",
    assetType: "ที่ดินเปล่า",
    province: "ชลบุรี",
    channel: "facebook",
    tone: "trustworthy",
    contentType: "educate",
  })
  const [result, setResult] = useState(null)

  return (
    <div>
      {/* ...ฟอร์ม... */}
      <button onClick={() => setResult(runMarketingModel(form))}>สร้างคอนเทนต์</button>

      {result && (
        <>
          {result.meta.blocking && <Alert type="error">แก้คำเตือนก่อนจึงจะโพสต์ได้</Alert>}
          {result.warnings.map((w, i) => <li key={i}>{w}</li>)}

          <h2>{result.headline}</h2>
          <pre>{result.caption}</pre>
          <p>{result.hashtags.map(h => "#" + h).join(" ")}</p>
          <p>{result.channelRecommendation}</p>

          <details><summary>บรีฟภาพ</summary><pre>{result.imagePrompt}</pre></details>
          <details><summary>สคริปต์วิดีโอ</summary><pre>{result.videoScript}</pre></details>

          <button
            disabled={result.meta.blocking}
            onClick={() => saveToQueue(result.automationPayload)}
          >
            ส่งเข้าคิวโพสต์
          </button>
        </>
      )}
    </div>
  )
}
```

ไม่มีอะไรต้องรอ ไม่มี loading state ไม่มีทางที่โควตาจะหมด

### 2. ตรวจความซ้ำกับโพสต์เก่า (แนะนำ)

```js
const recent = await fetchRecentCaptions(8)          // ดึงจาก DB ของ AssetX เอง
const out = runMarketingModel(form, { recentCaptions: recent })
// out.meta.duplicate = { similar: true, score: 0.72, match: {...} }
```

เจอซ้ำแล้ว **ไม่ทิ้งให้อัตโนมัติ** — ขึ้นป้ายเตือนให้คนตัดสิน (ของที่ใช้ได้จะได้ไม่หายเงียบ ๆ)

### 3. ให้ AI ช่วยเขียน (ต้องทำฝั่ง server เท่านั้น)

โมดูลไม่รู้จัก provider — ส่งฟังก์ชัน `generate` เข้ามาเอง

```js
// server/routes/marketing.js — ห้ามเอาโค้ดนี้ไปไว้ฝั่งเว็บ เพราะมี API key
import { runMarketingModelWithLLM } from "../lib/marketing-model/index.js"

const generate = async ({ system, user }) => {
  const res = await fetch("https://api.openai.com/v1/chat/completions", {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.OPENAI_API_KEY}`,   // อยู่ฝั่ง server เท่านั้น
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      model: "gpt-4.1",
      response_format: { type: "json_object" },
      messages: [{ role: "system", content: system }, { role: "user", content: user }],
    }),
  })
  const json = await res.json()
  return json.choices[0].message.content     // คืน string หรือ object ก็ได้
}

app.post("/api/marketing/generate", async (req, res) => {
  const out = await runMarketingModelWithLLM(req.body, { generate })
  res.json(out)
})
```

เปลี่ยนไปใช้ Gemini / Claude / โมเดลในองค์กร = แก้แค่ในฟังก์ชัน `generate`

**LLM ล้มหรือคืนของผิดรูป → ตกกลับไปใช้ข้อความจากเทมเพลตเงียบ ๆ แล้วใส่คำเตือนแทน**
ขั้นเสริมพังต้องไม่ทำให้ทั้งงานพัง

เลือกได้ว่าจะให้ช่วยส่วนไหน: `{ generate, parts: ["caption"] }` (ค่าปริยายคือทั้งสามส่วน)

### 4. อยากยิง LLM เองโดยไม่ผ่านโมดูล

```js
import { getPrompts } from "../lib/marketing-model"
const { caption, imageBrief, videoScript } = getPrompts(input)
// แต่ละตัวคือ { system, user, responseShape } เอาไปยิงเองได้ตามสะดวก
```

### 5. ด่านกันโพสต์พลาด — เรียกจาก **ทุกทาง** ที่โพสต์ได้

```js
import { canPublish } from "../lib/marketing-model"

const PUBLISHABLE = ["facebook"]        // ช่องที่ต่อ API โพสต์อัตโนมัติแล้วจริง ๆ

const gate = canPublish(row, { publishableChannels: PUBLISHABLE, requireSchedule: isCron })
if (!gate.ok) return reject(gate.reason)
```

⚠️ อย่าเช็คเงื่อนไขเหล่านี้ซ้ำในหน้าเว็บหรือใน route แยกกัน — วันหนึ่งสองที่จะไม่ตรงกัน
แล้วหน้าจอจะบอกว่า "จะโพสต์เอง" ทั้งที่ถึงเวลาแล้วเงียบ (หรือกลับกัน ซึ่งแย่กว่า)

## โครงไฟล์

| ไฟล์ | หน้าที่ | แก้บ่อยแค่ไหน |
|---|---|---|
| `index.js` | จุดเข้าใช้งาน + ประกอบร่างผลลัพธ์ + ตัวช่วยตัดคำไทย | นาน ๆ ครั้ง |
| `templates.js` | **ข้อมูลล้วน** — ช่องทาง รูปแบบคอนเทนต์ โทน แฮชแท็ก CTA ประโยคตั้งต้น พาดหัว | บ่อยที่สุด |
| `rules.js` | ด่านความเสี่ยง (กฎหมาย/โฆษณา/ข้อมูลส่วนบุคคล/อักษรเพี้ยน) + ด่านกันโพสต์พลาด | เมื่อเจอเคสใหม่ |
| `scoring.js` | ตรรกะตัดสินใจ — เลือกช่องทาง ให้คะแนน วัดความซ้ำ | เมื่อมีข้อมูลจริงจากการยิงแอด |
| `prompts.js` | ตัวประกอบคำสั่ง LLM (ไม่เรียก API เอง) | เมื่อเปลี่ยนวิธีสั่งโมเดล |
| `examples.json` | ตัวอย่างพร้อมใช้ 7 เคส + ผลที่ควรได้ | เมื่อเพิ่มรูปแบบใหม่ |
| `selftest.mjs` | ตรวจตัวเอง 97 ข้อ ไม่ใช้ไลบรารีใด ๆ | รันทุกครั้งที่แก้ |
| `schema.md` | โครงข้อมูลเข้า/ออก + รหัสคำเตือนทั้งหมด | — |

**คนที่ไม่เขียนโปรแกรมแก้ `templates.js` ได้** — เป็นข้อมูลล้วน ไม่มีตรรกะ
อยากเปลี่ยนคำพูดของแบรนด์ เพิ่มแฮชแท็ก เพิ่มช่องทาง ให้มาแก้ที่นี่ที่เดียว

## ข้อจำกัดที่ต้องรู้ก่อนใช้

1. **ไม่ใช่คำแนะนำทางกฎหมาย** — ด่านตรวจเป็นตัวกรองเบื้องต้นด้วย regex
   จับ "คำที่มักมีปัญหา" ได้ แต่ไม่เข้าใจความหมาย **ทุกชิ้นต้องผ่านสายตาคนก่อนโพสต์เสมอ**
   และเรื่องที่อ่อนไหวจริงควรให้ที่ปรึกษากฎหมายดู

2. **ตัวเลขทุกตัวต้องมาจาก `propertyData`** — ถ้าไม่ส่งมา ระบบจะไม่ใส่ตัวเลขใด ๆ เลย
   (ตั้งใจ) เพราะตัวเลขที่เดาขึ้นเองในธุรกิจนี้คือความเสียหายที่แก้ทีหลังไม่ได้

3. **ข้อความจากเทมเพลตคือ "ร่างที่ใช้ได้" ไม่ใช่ "งานที่ดีที่สุด"** — ถ้าต้องการคอนเทนต์
   ที่คมและเฉพาะเจาะจงกว่านี้ ให้ต่อ LLM (ข้อ 3 ด้านบน) โครงและกฎทั้งหมดถูกส่งเข้า prompt แล้ว

4. **`suggestedSchedule` คืนเป็นช่วงเวลา ไม่ใช่ timestamp** — โมดูลไม่รู้จัก timezone
   ของระบบปลายทางโดยตั้งใจ ให้ AssetX แปลงเป็นเวลาจริงเอง

5. **น้ำหนักการเลือกช่องทางมาจากประสบการณ์ ไม่ใช่ข้อมูลของ AssetX** — ใน `scoring.js`
   เป็นจุดแรกที่ควรแก้เมื่อมีตัวเลขจริงจากการยิงแอดแล้ว

6. **ยังไม่รองรับภาษาอื่น** — ข้อความทั้งหมดเป็นไทย และตัวตัดคำเขียนสำหรับภาษาไทยโดยเฉพาะ

7. **ไม่มีระบบจำสถานะ** — โมดูลไม่มีฐานข้อมูล ไม่จำว่าเคยสร้างอะไรไป
   การเก็บคิว สถานะอนุมัติ และประวัติโพสต์เป็นหน้าที่ของ AssetX

## ถ้าจะให้โพสต์อัตโนมัติจริง — สิ่งที่ต้องต่อเพิ่ม

โมดูลนี้จบที่ `automationPayload` เท่านั้น ส่วนที่เหลือต้องทำฝั่ง AssetX (ทั้งหมดเป็น server-side):

| ขั้น | สิ่งที่ต้องทำ |
|---|---|
| **เก็บคิว** | ตารางคอนเทนต์ที่มีอย่างน้อย: `status` (draft/pending/approved/scheduled/posted/rejected) · `channel` · `caption` · `scheduledAt` · `postId` · `postUrl` · `reviewVerdict` |
| **อนุมัติ** | หน้าจอให้คนกดอนุมัติ — **อย่าให้ AI เปลี่ยนสถานะเอง** ให้ AI เสนอความเห็นได้เท่านั้น |
| **ตั้งเวลา** | กันตั้งเวลาย้อนหลัง · กันสองโพสต์ชนกัน (แนะนำเว้นอย่างน้อย 45 นาที) |
| **โพสต์จริง** | ต่อ API ของแต่ละแพลตฟอร์ม (Facebook Graph API / LINE Messaging API) — ต้องมี access token ฝั่ง server · **เรียก `canPublish()` ก่อนยิงทุกครั้ง** |
| **ตัวจับเวลา** | cron หรือ scheduled function เรียกทุก ~15 นาที · จำกัดจำนวนโพสต์ต่อรอบเพื่อจำกัดความเสียหายถ้าตั้งเวลาผิดยกล็อต |
| **เก็บผล** | ดึงยอดเอ็นเกจเป็น snapshot หลายจุดเวลา (ไม่ใช่คอลัมน์เดียว) เพราะเอ็นเกจโตตามเวลา — เทียบ "24 ชม.แรก" จึงจะยุติธรรมกับทุกโพสต์ |
| **สร้างภาพจริง** | ส่ง `imagePrompt` เข้าโมเดลสร้างภาพ **แล้วซ้อนข้อความไทยทับทีหลัง** ห้ามให้โมเดลเขียนภาษาไทยเอง (สะกดเพี้ยนเสมอ) |

## logic ที่ยกมาจากระบบเดิม

ไม่ได้ย้ายโค้ดมาทั้งดุ้น — สิ่งที่ยกมาคือ **บทเรียนที่แลกมาด้วยของจริง** แล้วเขียนใหม่ให้เข้ากับธุรกิจนี้

| สิ่งที่ยกมา | อยู่ที่ไหนในโมดูล | ทำไมถึงมีค่า |
|---|---|---|
| ตัดพาดหัวไทยไม่ให้ขาดกลางคำ | `index.js` → `cutThai` / `splitHeadline` | ไทยไม่เว้นวรรคระหว่างคำแต่เว้นที่ขอบวลี · ห้ามจบด้วยสระหน้า (เ แ โ ใ ไ) หรือตัดหน้าสระบน-ล่าง ไม่งั้น "ถึงกับ" จะขาดเป็น "ถึงก"+"ับ" ซึ่งอ่านไม่ออกเลย |
| จับอักษรลาว/เขมร/พม่าที่ปนในข้อความไทย | `rules.js` → `findForeignChars` | บล็อกลาว (U+0E80) อยู่ติดกับไทย (U+0E7F) รูปร่างคล้ายจนตาคนอ่านผ่าน — เคสจริงคือโมเดลสะกด "เสียง" ด้วยอักษรลาวสองตัวแล้วผ่านทุกด่าน |
| แยกไอเดียภาพออกจากการวาดภาพ | `prompts.js` → `buildImageBriefPrompt` | โมเดลวาดไม่รู้ว่าโพสต์พูดเรื่องอะไร มันจึงวางสินค้าบนแท่นให้ทุกครั้ง · "ถ้าไอเดียนี้ใช้กับโพสต์ไหนก็ได้ ให้ทิ้งแล้วคิดใหม่" |
| ห้ามให้โมเดลเขียนข้อความในภาพ | `templates.js` → `IMAGE_RULES` | ปัญหาไม่ใช่แค่สะกดผิด แต่คือ "ข้อความที่ไม่เคยผ่านด่านตรวจคำเกินจริงขึ้นภาพได้" |
| ให้เลือก 2 รูปแบบ ไม่ใช่ยัด 1 และไม่ใช่ให้ทั้งหมด | `prompts.js` → `formatChoiceBlock` + `when`/`avoid_when` | บังคับแบบเดียวแล้วเจอหัวข้อไม่เข้ากันจะได้คอนเทนต์ที่ฝืนจนคนอ่านงง · ให้ทั้งหมดเท่ากับไม่ได้บังคับอะไรเลย |
| หยิบหลักการเขียนทีละชิ้น ไม่ยัดทั้งคลัง | `prompts.js` → `craftBlock` | ให้ framework มาทั้ง 8 แบบพร้อมกัน = ไม่ได้บังคับให้ใช้แบบไหนเลย และโมเดลเล็กจะจมข้อมูลจนลืมโจทย์ |
| ตารางคำผิด → คำที่ใช้แทนได้ | `rules.js` → `SAFER_PHRASES` | กฎชุดเดียวกันต้องเข้าทั้ง prompt คนเขียนและ prompt ผู้ตรวจ — เดิมให้ผู้ตรวจฝ่ายเดียว ผลคือทุกชิ้นถูกเขียนผิดก่อนแล้วค่อยจับทีหลังเสมอ |
| ถ้าไม่ป้อนตัวเลขจริง ห้ามเขียนตัวเลข | `prompts.js` → `COMPLIANCE_BLOCK` + `buildSpecs` | โมเดลจะเดาตัวเลขทุกครั้งที่ไม่มีข้อมูล — ตรวจคิวจริงเคยเจอตัวเลขแต่งขึ้น 4 จาก 13 ชิ้น |
| วัดความซ้ำด้วย Jaccard บน 4-gram | `scoring.js` → `similarity` | ไทยตัดคำไม่แน่นอน การเทียบทั้งสตริงแพ้ทันทีเมื่อสลับประโยค · ต้องถอดแฮชแท็ก/อีโมจิก่อนเทียบ เพราะสองโพสต์ที่ต่างแค่อีโมจิคือ "ซ้ำ" ในสายตาคนอ่าน |
| เจอซ้ำแล้วเตือน ไม่ทิ้งเอง | `index.js` → `duplicate_caption` | การทิ้งอัตโนมัติทำให้ของที่ใช้ได้หายไปเงียบ ๆ |
| ด่านกันโพสต์พลาดอยู่ในโมดูลกลางเดียว | `rules.js` → `canPublish` | เช็คจาก `postId` ไม่ใช่ `status` (status แก้ด้วยมือได้) · เรียงด่านจาก "ย้อนไม่ได้" ไป "ย้อนได้" · `drop` บล็อกเฉพาะตัวตั้งเวลา ไม่บล็อกคน |
| หนึ่งบรรทัด = หนึ่งฉาก | `templates.js` → `VIDEO_BEAT_GUIDE` + `buildVideoScript` | ทำให้คนเขียนคุมจังหวะภาพได้เองโดยไม่ต้องเรียนตัดต่อ — กด Enter คือสั่งเปลี่ยนภาพ |
| สคริปต์วิดีโอห้ามมีอีโมจิ/แฮชแท็ก/วงเล็บกำกับฉาก | `prompts.js` → `buildVideoScriptPrompt` | ทุกบรรทัดจะถูกอ่านออกเสียง ปล่อยผ่านแล้วจะได้เสียงอ่านว่า "แฮชแท็ก…" ซึ่งพังทั้งคลิปโดยกว่าจะรู้ก็เรนเดอร์ไปแล้ว |
| ผลลัพธ์ต้องเดิมสำหรับอินพุตเดิม | `scoring.js` → `hashSeed` / `pickStable` | `Math.random` ทำให้ทดสอบไม่ได้ และผู้ใช้งงว่าทำไมกดซ้ำแล้วเปลี่ยน |
| ขั้นเสริมพังต้องไม่ทำให้ทั้งงานพัง | `index.js` → fallback ของ `runMarketingModelWithLLM` | LLM ล้มแล้วยังต้องมีของให้ผู้ใช้เห็น |

**สิ่งที่ไม่ได้ยกมาเลย:** เนื้อหาสินค้าเดิม · ชื่อแบรนด์เดิม · การเชื่อมฐานข้อมูล ·
การเรียก API ของผู้ให้บริการใด ๆ · token และความลับทุกชนิด · path เฉพาะเครื่อง
