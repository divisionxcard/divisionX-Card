# ระบบสร้างภาพโปสเตอร์

## 🔴 กฎข้อแรก — เห็นของแปลกในภาพ อย่าเพิ่งโทษโมเดล

**เช็ควัตถุดิบที่เราป้อนเข้าไปก่อนเสมอ**

เคสจริง 20 ส.ค. 2026: ภาพออกมามีลายน้ำ "DIVISION X CARD" ปั๊มบนหน้าซอง
สรุปทันทีว่าโมเดลแปะเอง แล้วเขียนคำสั่งห้าม overlay เพิ่มเข้าไป

**ผิด** — ซูมดูรูปต้นทางใน Supabase แล้วพบว่า**รูปของเรามีลายน้ำอยู่แล้ว**
โมเดลแค่ลอกมาตามที่สั่งให้ลอกให้เหมือน คำสั่งที่เพิ่มไปจึงขัดกับคำสั่งเดิม
และอาจทำให้โมเดลเริ่มแก้ซองแทนที่จะลอก

คลังรูปซองไม่สม่ำเสมอ: **OP กับ EB มีลายน้ำทุกใบ · FB / MLP / MLBB / NRT ส่วนใหญ่สะอาด**
OP กับ EB คือกลุ่มที่ใช้ทำโพสต์บ่อยที่สุด

> ถ้าไม่ซูมดูรูปต้นทาง จะนั่งแก้ prompt ไปเรื่อย ๆ โดยไม่มีวันแก้ได้

---

## 🔴 กฎข้อสอง — ลำดับใน prompt เปลี่ยนผลลัพธ์จริง

ไม่ใช่แค่ความเรียบร้อยของโค้ด **สิ่งที่อยากให้ชนะต้องอยู่ท้ายสุด**

พิสูจน์แล้วด้วยการยิงสองรอบ เนื้อหา prompt เหมือนกันทุกตัวอักษร ต่างแค่ตำแหน่ง:

| ลำดับ | ผลลัพธ์ |
|---|---|
| ไอเดียภาพขึ้นก่อน → กฎแบรนด์ 29 ข้อตามหลัง | **ซองสองใบลอยเฉย ๆ** กฎข้อ "สินค้าต้องกิน ≥60% ของเฟรม" ชนะ |
| กฎแบรนด์ขึ้นก่อน → **ไอเดียปิดท้าย** | ภาพแบ่งจอ สองฝั่งคนละบรรยากาศ ตรงกับเนื้อหา |

ตอนนี้ `buildPrompt()` วางไอเดียไว้ท้ายสุดพร้อมประโยค
*"This idea outranks every stylistic preference above"*

**อย่าย้ายมันขึ้นไปข้างบนเพื่อความสวยงามของโค้ด**

```
แคปชั่นที่อนุมัติแล้ว
  → planVisual()            คิดไอเดียภาพ (lib/artDirector.js · gpt-5.4 · หลักสตางค์)
  → buildPrompt()           ประกอบ prompt
  → /images/edits           วาดจริง (gpt-image-2 · ~$0.17–0.21/ใบ)
  → Supabase Storage
```

**ขั้นคิดไอเดียถูกมากเทียบกับขั้นวาด** → ทดสอบไอเดียได้ฟรี ๆ ก่อนค่อยยิงภาพ
เขียนสคริปต์เรียก `planVisual()` ตรง ๆ แล้วดูผล ไม่ต้องเสีย $0.20 ทุกครั้งที่ลอง

## กับดักที่เคยทำให้พังจริง

### 1. fallback ที่กลืน error แล้วเดินต่อเงียบ ๆ

`askOpenAI()` วนลองโมเดลหลายตัว เจอ 400 ที่ข้อความมีคำว่า `model` จะ `continue`

เอกสาร OpenAI ระบุว่า **`gpt-image-2` ห้ามส่ง `input_fidelity`** แต่โค้ดส่งไปทุกโมเดล
error ที่ได้คือ *"The model 'gpt-image-2' does not support the 'input_fidelity' parameter"*
ซึ่ง**มีคำว่า model** → เข้าเงื่อนไข → เลื่อนไป `gpt-image-1.5` เงียบ ๆ

**ผลคือภาพทุกใบมาจาก gpt-image-1.5 ไม่เคยเป็น gpt-image-2 เลยสักใบ**
แล้วทีมสรุปว่า "gpt-image ทำไม่ได้" ทั้งที่ไม่เคยเรียกตัวที่ตั้งใจจะใช้ติดเลย

→ ตอนนี้ route คืน `attempts[]` กับ `usage` ออกมาทุกครั้ง **ดูทุกครั้งว่าภาพมาจากโมเดลไหนจริง**

### 2. dead config — คีย์ที่มีในไฟล์แต่ไม่มีใครอ่าน

เจอมาแล้ว 5 ตัว:

| คีย์ | ผลตอนที่ตายอยู่ |
|---|---|
| `style.with_reference` | คำสั่ง "ห้ามวาดซองใหม่" ไม่เคยถูกส่ง → โมเดลวาดซองปลอม |
| `style.scenes` | 9 ฉากแยกตามรูปแบบโพสต์ ไม่เคยถูกใช้ |
| `content_format` | ไม่เคยส่งเข้า prompt |
| `skus.franchise` | มีข้อมูลครบ 9 ค่าย ไม่เคยถูกใช้ |
| `art_direction.json` | สร้างไว้แล้วเป็นไฟล์ลอยอยู่วันนึง |

> **เพิ่มคีย์ใหม่ในไฟล์ตั้งค่าแล้วต้อง grep ยืนยันว่ามีโค้ดอ่านจริง** ไม่งั้นมันจะดูเหมือนทำงานอยู่

### 3. คำสั่งขัดกันเองใน prompt เดียว

โหมด `full` เคยสั่ง `thai_rule` ("วาดข้อความไทยนี้ให้ตรงทุกตัวอักษร")
แล้วต่อท้ายด้วย `negative` ที่มี `"no text, no letters, no words"` — ทำพร้อมกันไม่ได้

→ แยกเป็น `negative_always` กับ `negative_no_text` แล้ว **ห้ามรวมกลับ**

### 4. โมเดลเติมข้อความไทยที่ไม่ได้อนุมัติ

`facts_rule` เดิมพูดถึงแค่ "ตัวเลข" ไม่ได้ห้าม "คำ" โมเดลจึงแถมป้ายไทยมาเอง

**ปัญหาไม่ใช่ว่ามันเขียนผิด** — รอบที่เจอมันเขียนถูกด้วยซ้ำ
แต่แปลว่า**ข้อความที่ไม่เคยผ่านด่านตรวจคำเว่อร์ขึ้นภาพได้** (ดู `dvx-content` → `overclaim`)

→ เพิ่มบล็อก **TEXT LOCK** ห้ามเด็ดขาด ยิงจริงแล้วเหลือแค่บรรทัดที่อนุมัติ

### 5. ธีมค่ายเดียวยัดให้ทุกโพสต์

`route.js` เคยฮาร์ดโค้ด *"a One Piece nautical theme"* ไว้ในทุก prompt
บวกกับ `poster_concepts` default = `treasure` (ล่าสมบัติ One Piece)

→ โปสเตอร์ **Dragonball FB-09** ออกมามีสมอ คลื่น เข็มทิศ นกนางนวลเต็มใบ

**⚠️ ตัดแค่ `decor` ไม่พอ** — ชื่อคอนเซปต์เองคือ "ล่าสมบัติ One Piece" ซึ่งถูกส่งไปทั้งบรรทัด
ต้องตัดทั้งบล็อกเหลือแค่ทิศทางสีเมื่อค่ายไม่ตรง

ลายเดินเรือ**ผูกกับตัวตู้จริงเท่านั้น** (ตู้พิมพ์ลายนั้นจริง) ห้ามลามเป็นกรอบ/พื้นหลัง

### 6. ชื่อไฟล์ไม่ตรงชนิดตอนส่ง multipart

รูปซองใน Supabase มีทั้ง WebP และ JPEG แต่โค้ดเคยตั้งชื่อ `ref0.jpg` ให้ทุกอย่างที่ไม่ใช่ PNG

## ข้อจำกัดที่ยังแก้ไม่ได้ — อย่าสัญญากับเจ้าของ

**"ตัวอักษรไทยถูก 100%" รับประกันไม่ได้ถ้าโมเดลเป็นคนวาด**

เอกสาร OpenAI ยังลิสต์ Text Rendering เป็น Limitation และไม่เคยเอ่ยถึงภาษาไทยเลยสักคำ
ทดสอบผ่าน 2-3 ใบไม่ใช่หลักฐานว่าผ่านตลอด

**คำว่า 100% จะจริงเชิงโครงสร้างก็ต่อเมื่อ Chromium เป็นคนวางตัวอักษร**
→ นั่นคือ `poster_mode: "art"` (AI วาดแค่ฉาก เทมเพลตวางข้อความ) หรือ `poster_render.py`

`image_style.json` ตั้ง `poster_mode: "full"` เพราะเจ้าของชอบแบบนั้น **ห้ามสลับเองโดยไม่ถาม**

**ซองที่ได้เป็นการวาดซ้ำที่เหมือนมาก ไม่ใช่การแปะรูปจริง** — ตัวหนังสือบนซองถูกครบ สีตรง
แต่ลายอาร์ตไม่ใช่พิกเซลเดียวกับต้นฉบับ ถ้าต้องการเป๊ะระดับพิกเซล ต้องใช้เทมเพลตแปะ

---

## รูปตู้จริงยังไม่เคยถูกใช้

`route.js` แนบรูปตู้เฉพาะตอน `concept` เป็น `machine_luck` หรือ `real_machine`
แต่**หน้าเว็บไม่เคยส่ง `concept` มาเลย** → ตกไปที่ default ทุกครั้ง

**โมเดลจึงไม่เคยเห็นรูปตู้จริงสักครั้ง วาดจากจินตนาการล้วน** ช่องกับกล่องเลยไม่เหมือนของจริง

## วิธีตรวจภาพที่ AI แก้ให้ ก่อนเอาเข้าระบบ

ให้วางเป็นชื่อใหม่ก่อน **ห้ามทับของเดิม** แล้ววัดด้วย `PIL.ImageChops.difference`

```
เคสแก้เลขในแบนเนอร์: ต่างจากเดิม 274 พิกเซลจาก 902,486 = 0.03%
→ แก้เฉพาะจุดจริง
```

**ถ้าเปอร์เซ็นต์ความต่างเกิน ~25% แปลว่าโมเดลวาดใหม่ทั้งใบ ให้ตีกลับ**

แล้วครอปเทียบทีละจุด (หัวเรื่อง · ไอคอน · แถบล่าง) ยืนยันว่าภาษาไทยไม่เพี้ยน

⚠️ **อย่าลืมไฟล์เวอร์ชันย่อ** — `srcSet` ชี้ไฟล์ `-800.jpg` ให้จอเล็ก
ถ้าเปลี่ยนแต่ตัวเต็ม คนดูจากมือถือจะเห็นของเก่า และไม่มีใครสังเกตเพราะเดสก์ท็อปถูกแล้ว
