# แผนระบบอัปเดตโพสต์อัตโนมัติ — เปรียบเทียบ 3 ระดับ

ช่วยตัดสินใจว่าจะทำ "auto-post" แบบไหน · อิงสถานะจริง: มีเพจ FB + LINE OA + GitHub Actions + ระบบเตือน Telegram อยู่แล้ว

## ⚠️ หลักสำคัญก่อนเลือก
- **auto ได้ดี:** โพสต์ตามปฏิทิน (ของใหม่/รีวิว/สาขา/โปร/โพล) — ตั้งล่วงหน้าได้
- **ไม่ควร auto:** **Reels เปิดซองสด** (ตัวเร่งผู้ติดตามหลัก) ต้องถ่ายจริง จังหวะจริง → คนทำ
- → ทางที่ดีจริงคือ **hybrid**: auto ส่วนประจำ + คนทำส่วน live

## 🔍 จุดที่คนมักเข้าใจผิด
- **ระดับ 1 ไม่ได้ "ด้อยกว่า" ระดับ 3** — Business Suite ตั้งเวลา **Reels/วิดีโอ** ได้ด้วย ซึ่งระดับ 3 (API) กลับทำยาก → ระดับ 1 ครอบคลุมกว่าในหลายเคส
- **ระดับ 3 ไม่ได้ "ไร้คนดูแล"** — ต้องคอยต่ออายุ Page token + เฝ้า error/policy ของ Meta
- ทั้ง 3 ระดับ **ยังต้องมีคนผลิตคอนเทนต์** (โดยเฉพาะ live pull) — automation แค่จัด "การปล่อย" ไม่ได้สร้างเนื้อหาแทน

## 💡 คำแนะนำ (Roadmap)
1. **เริ่มระดับ 1 ทันที** — Business Suite ตั้งโพสต์ทั้งสัปดาห์ + LINE schedule broadcast → ได้ผล ~80% ฟรี ไม่เสี่ยง
2. **เสริมระดับ 2** — ใช้ Telegram reminder (มีแล้ว) คุมความสม่ำเสมอ + เก็บ caption ล่วงหน้าใน queue
3. **ขยับระดับ 3 เฉพาะเมื่อ** — โพสต์ถี่มาก/หลายเพจ/อยากตัดงานคนออกจริง ๆ (ลงทุน dev + ดูแล token)

> สำหรับร้านขนาดนี้: **ระดับ 1 + 2 พอและคุ้มสุด** · ระดับ 3 เก็บไว้ตอนสเกล

## 🛠️ ถ้าเลือกแต่ละระดับ ผมช่วยอะไรได้
- **ระดับ 1:** คู่มือ step-by-step ตั้ง Business Suite Planner + LINE scheduler + วิธีโหลดปฏิทินทั้งสัปดาห์เข้าไปครั้งเดียว
- **ระดับ 2:** ออกแบบ content queue (Sheet/ตาราง) + ต่อเข้าระบบ Telegram reminder ให้ดึง caption ของวันมาเตือน
- **ระดับ 3:** สร้าง `scheduled_posts` table + GitHub cron + Graph API poster + แนวทางขอ Page token/app review
