# ระดับ 3 — โพสต์ขึ้นเพจเองผ่าน Graph API · คู่มือตั้งค่า

ทำจริงแล้ว: ปุ่ม **“โพสต์ขึ้นเพจ”** ในหน้า `/marketing` โซน *รอโพสต์*
กดครั้งเดียว → ขึ้นเพจพร้อมรูป → บันทึกลิงก์โพสต์กลับเข้าระบบ

เอกสารนี้คือขั้นตอนที่ **เจ้าของต้องทำเอง** (ผมทำแทนไม่ได้ เพราะต้องล็อกอินบัญชี Facebook จริง)
ภาพรวมว่าทำไมถึงเลือกระดับนี้ ดู [[auto-posting-plan]]

## ทำไมถึงคุ้มทำตอนนี้

วัดจากของจริงเมื่อ 2026-08-10: คอนเทนต์ในระบบ **19 ชิ้น · โพสต์จริงไปแค่ 1 ชิ้น**

คอขวดไม่ได้อยู่ที่การคิดคอนเทนต์ (มีไอเดีย 93 ชิ้น มุมครบ 258 มุม) แต่อยู่ที่
**ขั้นตอนเอาไปโพสต์** ที่ต้องทำมือ 5 ขั้น: ก๊อป → เปิดเพจ → วาง → แนบรูป → กลับมากดยืนยัน
ลดเหลือ 1 ขั้นจึงเป็นจุดที่ได้ผลมากที่สุดต่อแรงที่ลง

## ⚠️ ข้อมูลที่แผนเดิมเขียนไว้ผิด — ไม่ต้องผ่าน App Review

[[auto-posting-plan]] เขียนว่าระดับ 3 ต้อง "ขอ Page token/app review" ซึ่งทำให้ดูใหญ่กว่าจริง
เช็กเอกสาร Meta แล้ว (2026-08-10) — **ไม่ต้อง** ถ้าใช้กับเพจตัวเอง:

> “If your app will only be used by app users who have a role on the app itself,
> App Review is not required.”

ขอแค่บัญชีที่ใช้มี role บนแอป (Admin) และเป็นแอดมินของเพจ · **ไม่ต้องส่งรีวิว ไม่ต้องรออนุมัติ**
แต่ **ต้องเผยแพร่แอปเป็น Live** (ต้องมีหน้านโยบายความเป็นส่วนตัว + ข้อกำหนดการใช้งาน — ขึ้นเว็บแล้ว 17 ต.ค. 2026)
ไม่งั้นคนนอกมองไม่เห็นโพสต์ → ขั้น 8

## ⚠️ แก้ไข 17 ต.ค. 2026 — คู่มือนี้เคยสั่งให้อยู่โหมด Development ตลอด ซึ่งผิด

ฉบับเดิมเขียนตรงนี้ว่า *"แอปอยู่โหมด Development ตลอดไปได้ … ไม่ต้องมีนโยบายความเป็นส่วนตัว"*
และขั้น 1 ข้อ 8 สั่งว่า *"อย่ากด Switch to Live เพราะไม่จำเป็น"* — **ผิดทั้งคู่**

- ประโยค App Review ข้างบนพูดถึง **สิทธิ์** (ใครขอ permission ได้บ้าง) ไม่ได้พูดว่า **ใครมองเห็นโพสต์**
- เรื่องใครมองเห็น อยู่ในเอกสาร [App Modes](https://developers.facebook.com/documentation/development/build-and-test/app-modes) ของ Meta:
  > “Any data generated while an app is in Development mode, such as test posts, can only be seen by role users.
  > However, that data will be visible to non-role users once the app is switched to Live mode.”

  และ Meta ประกาศไว้ตั้งแต่ปี 2019 ว่าแอปที่ใช้งานจริงต้องอยู่โหมด Live
- หน้า App Modes เดียวกันเขียนด้วยว่าให้สลับ Live *"after you have completed app development and have completed App Review"*
  — ข้อนี้สำหรับแอปที่ขอสิทธิ์จากคนที่ไม่มี role บนแอป (Advanced Access) · แอปเราใช้แค่บัญชีแอดมินของแอปเอง
  จึงไม่ต้องรีวิว (เอกสาร App Review ข้างบน) · ถ้า Live แล้วโพสต์พัง ดูทางถอยท้ายขั้น 8
- ผลจริง: โพสต์ที่ระบบโพสต์ขึ้นเพจ **5 ชิ้น** (25 ส.ค. – 14 ต.ค. 2026) มีแต่คนที่มี role บนแอปมองเห็น
  ทั้งที่ตัวโพสต์ตั้งเป็นสาธารณะ · ได้ 0–1 รีแอ็กชัน · เจ้าของล็อกอินบัญชีอื่นเปิดโพสต์ #53 (OP-13 top5)
  แล้ว **มองไม่เห็น** (ยืนยัน 17 ต.ค. 2026)
- ที่ไม่มีใครรู้ตัวมา 2 เดือน เพราะทุกการทดสอบทำจากบัญชีแอดมิน ซึ่งเห็นโพสต์ตามปกติ
  → **เช็กว่าคนนอกเห็นไหม ต้องใช้บัญชีที่ไม่มี role บนแอปเสมอ**
- ที่ถูก: ใช้กับเพจตัวเอง **ไม่ต้องส่ง App Review** (ข้อนี้ยังจริง) แต่ **ต้องเผยแพร่แอปเป็น Live**
  และการ Live ต้องมี URL นโยบายความเป็นส่วนตัว + URL วิธีขอลบข้อมูล (+ ข้อกำหนดการใช้งาน ตามเอกสาร Basic Settings)
  → ทำหน้า `/privacy` (`deploy/app/privacy/page.jsx`) กับ `/terms` (`deploy/app/terms/page.jsx`) ไว้แล้ว ดูขั้น 8

## ขั้นตอน

### 0 · สมัครบัญชีนักพัฒนา (ถ้ายังไม่มี)

**ด่านที่ติดจริงตอนทำ (2026-08-10): ขั้น Verify account ส่ง SMS ไม่ออก**
ขึ้นว่า *"คุณสามารถดำเนินการนี้ให้เสร็จได้ในศูนย์บัญชีเท่านั้น"* แล้ววนอยู่ตรงนั้น

สาเหตุ: บัญชี Facebook **ยังไม่มีเบอร์มือถือที่ยืนยันแล้ว** หน้าสมัครจึงส่ง SMS ให้ไม่ได้
ต้องไปเพิ่มเบอร์ที่ศูนย์บัญชีก่อน แล้วค่อยกลับมา

```
accountscenter.facebook.com/personal_info
→ ข้อมูลติดต่อ → เพิ่มข้อมูลติดต่อใหม่ → เพิ่มเบอร์มือถือ
→ ไทย (+66) + เบอร์ (ตัด 0 นำหน้า) → กรอกโค้ด SMS
→ กลับไปหน้าสมัคร รีเฟรช
```

- **เบอร์เปลี่ยนทีหลังได้** และ**ไม่กระทบ token** — token ผูกกับแอป+สิทธิ์บนเพจ ไม่ได้ผูกกับเบอร์
  (สาเหตุที่ทำให้ token ตายมีแค่: ถอดแอป · security checkpoint · **เปลี่ยนรหัสผ่าน** · หมดอายุ/ถูกเพิกถอน)
  ถ้าจะเปลี่ยน ให้ **เพิ่มเบอร์ใหม่ก่อน แล้วค่อยลบเบอร์เก่า**
- ไม่อยากใช้เบอร์เลย → หน้าเดียวกันมีตัวเลือกยืนยันด้วย **บัตรเครดิต**
- ขั้น *About you* เลือก **นักพัฒนา** (มีผลแค่หน้าจอที่ Meta จะโชว์ให้ ไม่เกี่ยวกับสิทธิ์)

### 1 · สร้างแอปบน Meta

⚠️ Meta เปลี่ยนขั้นตอนนี้ไปแล้ว — **ไม่มีให้เลือก "ประเภทแอป" อีกต่อไป** ใช้ระบบ *กรณีการใช้งาน* แทน

1. เข้า **developers.facebook.com** → *My Apps* → **Create App**
2. **รายละเอียดของแอพ** — ชื่ออะไรก็ได้ เช่น `DivisionX Card`
3. **กรณีการใช้งาน** — 6 อันที่ Meta "แนะนำ" ไม่มีอันที่ต้องใช้เลยสักอัน
   กดกรอง **การจัดการเนื้อหา (5)** แล้วติ๊ก **2 อัน**:
   - ☑ **จัดการทุกอย่างบนเพจของคุณ** ← ตัวที่ปลดสิทธิ์ `pages_manage_posts`
   - ☑ **จัดการการส่งข้อความและเนื้อหาบน Instagram** ← เผื่อไว้สำหรับ IG
   > อย่าติ๊กหมดทุกอัน · token ที่ได้จะถือสิทธิ์เกินจำเป็น (เปิดไลฟ์ในชื่อเพจ / ตอบ DM ลูกค้า)
   > วันไหน token หลุด ความเสียหายเท่ากับสิทธิ์ที่มันถืออยู่ · เพิ่มกรณีทีหลังได้ แค่ต้องออก token ใหม่
4. **ธุรกิจ** — เลือก *"ฉันยังไม่ต้องการเชื่อมต่อพอร์ตโฟลิโอธุรกิจ"*
   (จำเป็นตอนขอ Advanced Access หรือใช้ข้อมูลที่ไม่ใช่ของเรา · ตามเอกสาร Meta **การเปิดแอปเป็น Live ไม่ต้องใช้**
   — ฉบับเดิมเขียนว่าต้องใช้ตอน Live ด้วย · แก้ 17 ต.ค. 2026 · แต่ถ้าหน้า Go live บังคับยืนยันธุรกิจ
   จะต้องเชื่อมพอร์ตโฟลิโอ → หยุดคุยกันก่อน ดูหัวข้อ "ด่านที่อาจเจอ" ในขั้น 8)
5. **ข้อกำหนด** — ไม่มีช่องให้กรอก · ในกล่องจะขึ้นว่า *"ไม่มีข้อกำหนดที่ระบุ"*
   = ยืนยันอีกชั้นว่าไม่ต้องผ่าน App Review (ข้อนี้คือข้อกำหนดตอนสร้างแอป — รายการที่ต้องทำก่อน Live อยู่ขั้น 8)
6. **ภาพรวม** → กด *สร้างแอพ*
7. เข้าแอป → **Settings → Basic** → จดไว้ 2 ค่า
   - **App ID**
   - **App Secret** (กด Show)
8. **อย่าจบที่โหมด Development** — ทำขั้น 2–7 ให้ครบ แล้ว **ต้องเผยแพร่แอปเป็น Live** ตามขั้น 8
   (ฉบับเดิมสั่งว่า "อย่ากด Switch to Live" — ผิด · ดูหัวข้อแก้ไข 17 ต.ค. 2026 ด้านบน)

### 2 · เปิดสิทธิ์ให้ครบที่ระดับแอปก่อน ⚠️ ขั้นที่เสียเวลาที่สุด

**นี่คือด่านที่ทำให้ติดอยู่เป็นชั่วโมง** — จะขึ้น error นี้ซ้ำ ๆ ไม่ว่าจะลองทางไหน:

```
Invalid Scopes: pages_read_user_content
```

**สาเหตุ:** แอปแบบ *กรณีการใช้งาน* จะพ่วงชุดสิทธิ์ของกรณีนั้นเข้าไปในคำขอเอง
แม้เราไม่ได้ขอ `pages_read_user_content` เลย (พิสูจน์แล้วด้วยการยิง OAuth URL ที่ระบุ
scope เองแค่ 4 ตัว — ก็ยังขึ้น error เดิม) แต่แอปยัง **ไม่ได้เพิ่ม** สิทธิ์ตัวนั้น
Facebook จึงตีกลับว่าไม่ถูกต้อง

**วิธีแก้ — ต้องกด "เพิ่ม" ไม่ใช่หาทางเอาออก:**

```
เมนูซ้าย → กรณีการใช้งาน → จัดการทุกอย่างบนเพจของคุณ → ปรับแต่ง
```
ในตารางสิทธิ์ ให้ทุกตัวที่ใช้ขึ้นสถานะ **"พร้อมทดสอบ"** · ตัวที่ขึ้น `—` พร้อมปุ่ม **+ เพิ่ม**
แปลว่ายังไม่ได้เปิด · กดเพิ่มให้ครบ:
```
pages_show_list · pages_manage_posts · pages_read_engagement
pages_manage_engagement · pages_read_user_content   ← ตัวที่ลืมง่ายสุด
```
(`pages_read_user_content` เป็นสิทธิ์อ่านอย่างเดียว — อ่านโพสต์/คอมเมนต์ที่คนอื่นเขียนบนเพจเรา)

> 💡 `pages_manage_metadata` ไม่ต้องเพิ่มถ้าไม่มี error ถึงมัน

### 3 · สร้าง "การกำหนดค่า" แล้วขอ token

⚠️ แอปแบบใหม่เป็น *Facebook Login for Business* ซึ่ง **เลิกใช้ `scope` แล้ว**
เอกสาร Meta เขียนว่า *"config_id has replaced scope (which should not be used)"*

1. `การเข้าสู่ระบบด้วย Facebook → การกำหนดค่า → สร้างการกำหนดค่า`
   - ประเภทโทเค็น: **โทเค็นการเข้าถึงผู้ใช้**
   - สิทธิ์: ติ๊ก 4 ตัว (`pages_read_user_content` ไม่มีให้เลือกตรงนี้ — ปกติ)
   - กด **สร้าง**
2. ไป **developers.facebook.com/tools/explorer**
   - มุมขวาบนเลือกแอป → แท็บ **Configurations** → เลือกการกำหนดค่าที่สร้าง
   - **Generate Access Token** → *เลือกใช้เพจปัจจุบันและในอนาคต* → อนุญาต (สวิตช์เปิดหมด)
3. ก๊อป token — **อายุแค่ 1-2 ชม.** ต้องรีบเอาไปแลกในข้อถัดไป

> **ทางที่ใช้ไม่ได้แล้ว อย่าเสียเวลาลอง:**
> - `redirect_uri=https://www.facebook.com/connect/login_success.html` — Meta บล็อกแล้ว
>   ขึ้นว่า *"สิ่งนี้จะต้องไม่ใช่ Facebook URL"*
> - ใส่ `scope=` ใน OAuth URL เอง — ถูกพ่วงสิทธิ์ของกรณีการใช้งานเข้ามาอยู่ดี
> - ถ้าจะใช้ OAuth URL ตรง ๆ ต้องตั้ง **ทั้ง** `โดเมนของแอพ` (การตั้งค่าแอพ → ข้อมูลพื้นฐาน)
>   **และ** `URI เปลี่ยนเส้นทาง OAuth ที่ถูกต้อง` (การเข้าสู่ระบบด้วย Facebook → การตั้งค่า)
>   ขาดอย่างใดอย่างหนึ่งจะขึ้น *"ไม่สามารถโหลด URL ได้"*

### 4 · แลกเป็น token ที่ไม่มีวันหมดอายุ

บนเครื่องตัวเอง ที่โฟลเดอร์โปรเจกต์:

```bash
node scripts/fb-token.mjs <APP_ID> <APP_SECRET> <TOKEN_ที่ก๊อปมา>
```

สคริปต์จะแลก 2 ต่อให้ (token สั้น → token ยาว 60 วัน → page token) แล้วพิมพ์ออกมาแบบนี้:

```
── DivisionX Card
   FB_PAGE_ID=1234567890
   FB_PAGE_ACCESS_TOKEN=EAAG...
   สิทธิ์โพสต์: ✅ มี   token: ✅ ไม่มีวันหมดอายุ
```

> ถ้าบรรทัด token ไม่ขึ้น `✅ ไม่มีวันหมดอายุ` **อย่าเพิ่งใช้** — แปลว่าแลกไม่ครบขั้น
> ให้ทำข้อ 3 ใหม่แล้วรันสคริปต์ทันที (token ต้นทางหมดอายุไปก่อนได้)

**ทำจริงสำเร็จเมื่อ 2026-08-10** — เพจ Division X Card · `FB_PAGE_ID=1016536371546877`

**2. เมนูซ้าย → Publish → Go live**
หน้านี้ขึ้นรายการสิ่งที่ยังขาด
- ข้อที่แก้ได้ในหน้าข้อมูลพื้นฐาน (ไอคอน ลิงก์ หมวดหมู่ อีเมล) → ทำให้ครบ
- ข้อที่เป็น **การยื่นขอหรือยืนยันตัวตน** (Business Verification · Advanced Access · App Review · Data handling questions

- ครบแล้วกด **Go live** (หรือ **Publish**) มุมขวาล่าง
> ปุ่มสลับโหมดบนแถบด้านบน (App Mode toggle) เอกสารอธิบายเฉพาะแอปแบบเก่า · แอปเราเป็นแบบ *กรณีการใช้งาน* ใช้เมนู Publish
> — ถ้าไม่มีเมนู Publish แต่มีสวิตช์บนแถบด้านบน ให้สลับเป็น Live แทน · ชื่อเมนูภาษาไทยยังไม่ได้เทียบกับหน้าจอจริง

**ด่านที่อาจเจอในรายการ — ขึ้นข้อไหนในนี้ หยุดก่อนแล้วบอกผม** (ระหว่างนั้นโพสต์มือผ่าน Business Suite ได้ตามปกติ):
- **Data Use Checkup / คำถามการจัดการข้อมูล** — ถามว่าใช้ผู้ประมวลผลข้อมูลรายไหน (ตามหัวข้อ 3 ในหน้า `/privacy`)
  · ใครเป็นผู้รับผิดชอบข้อมูลตามกฎหมาย อยู่ประเทศไหน (ต้องรู้ว่าร้านจดในชื่อบุคคลหรือบริษัท)
  · 12 เดือนที่ผ่านมาเคยมีหน่วยงานรัฐขอข้อมูลไหม · มีนโยบายรับมือคำขอจากหน่วยงานรัฐไหม — ตอบตามจริง
  · สิทธิ์ `pages_read_user_content` กับ `pages_manage_engagement` ได้มาตอนออก token แต่โค้ดไม่ได้ใช้ → ตอบตามจริงว่าไม่ได้ใช้
- **ขอ Advanced Access ของ `public_profile`** · **ยืนยันธุรกิจ (Business Verification)** · **เชื่อมพอร์ตโฟลิโอธุรกิจ** —
  เอกสาร Facebook Login for Business (อัปเดต 15 ต.ค. 2026) บอกว่าอาจต้องมี Advanced Access ก่อน Live
  ซึ่งต้องยืนยันธุรกิจ · ใช้เวลานาน (มีรายงานค้าง *In Review* เป็นเดือน) และเชื่อมพอร์ตโฟลิโอแล้วต้องจัดการบทบาท
  ผ่าน Business Manager → อย่าเพิ่งยื่น/เชื่อมจนกว่าจะคุยกัน
- **บังคับให้เป็น Data deletion callback URL** (ไม่รับลิงก์คำแนะนำ) หรือ **ไอคอน 1024×1024** — เอกสาร Meta เขียนขัดกันเอง
  ถ้าไม่รับ บอกผม จะทำ endpoint / ไอคอนให้
- **ติดเฉพาะส่วน Instagram** → แคปมา **อย่าลบ use case หรือสิทธิ์ออกเอง** (เผื่อทำ IG Reels ทีหลัง)

   (ไม่มีเอกสาร Meta ไหนบอกว่าสลับโหมดแล้ว token ตาย แต่ก็ไม่มีที่ไหนยืนยันว่ารอดแน่ ๆ)
2. เปิดโพสต์ #53 ด้วยบัญชีที่ไม่มี role บนแอปและไม่ใช่แอดมินเพจ (อีกเบราว์เซอร์/โหมดไม่ระบุตัวตน) → ต้องเห็นทั้งรูปและข้อความ
   `https://www.facebook.com/122124553400914175/posts/122133121622914175`
   (มีรายงานว่าโหมด Development บางทีคนนอกเห็นข้อความแต่รูปไม่ขึ้น — ถ้ายังเป็นแบบนั้นหลัง Live ให้แจ้ง)
   · **อย่าเพิ่มบัญชีทดสอบเป็น role ในแอปหรือแอดมินเพจ** ไม่งั้นใช้ทดสอบไม่ได้อีก
3. โพสต์จริงครั้งถัดไป เช็กจากบัญชีคนนอกอีกรอบ · ตั้งแต่ Live ชิ้นที่อนุมัติ+ถึงเวลาที่ตั้งไว้จะขึ้นให้ทุกคนเห็นจริง

**ถ้าโพสต์จากระบบพังหลัง Live** (ขึ้น *"Token ไม่มีสิทธิ์โพสต์"* = error code 10 / 200)
คาดว่าไม่เจอ — แอดมินของแอปใช้สิทธิ์ระดับ Standard Access ได้โดยไม่ต้องรีวิว (มีเคสจริง ต.ค. 2026 ที่ Live แล้วโพสต์ต่อได้)
ถ้าเจอ **อย่าเพิ่งถอนการเผยแพร่เอง** (มีรายงานในฟอรัม Meta ว่าถอนแล้วปุ่ม Publish กดไม่ได้อีก)
· ทางเลือกคือสลับกลับ Development (โพสต์หายจากคนนอกอีก และอาจเผยแพร่ซ้ำไม่ได้) หรือส่ง App Review ขอ `pages_manage_posts`
(ต้องยืนยันธุรกิจ + อัดวิดีโอสาธิต + รอหลายวันถึงหลายสัปดาห์)

**หลัง Live น่าจะมีงานปีละครั้ง: Data Use Checkup** (เอกสาร Meta เขียนไม่ตรงกันว่าแอปที่ใช้แค่ Standard Access ต้องทำไหม
— *"required for developers whose apps have been published live with a use case"* กับ *"not required for … Standard Access"*)
แจ้งเตือนเข้า **Contact email** + หน้าแอป ล่วงหน้า 60 วัน (ย้ำที่ 30 · 10 · 3 วัน)
· **ทำไม่ทันกำหนด แอปถูกระงับจนกว่าจะทำเสร็จ = โพสต์อัตโนมัติหยุด** ไม่มีการต่อเวลา และเปิดกลับอาจต้องยื่นรีวิวใหม่
→ เห็นแจ้งเตือนเมื่อไร ส่งมาทันที

## ระบบกันพลาดที่ใส่ไว้

โพสต์ขึ้นเพจสาธารณะแล้ว **ลบจากหน้าเว็บไม่ได้** จึงกันไว้หลายชั้น:

| ชั้น | กันอะไร |
|---|---|
| กล่องยืนยันก่อนโพสต์ | โชว์แคปชั่น + บอกว่ามีรูปไหม ก่อนกดจริง |
| `post_id` ในตาราง | เคยโพสต์แล้วยิงซ้ำไม่ได้ (Facebook **ไม่กันซ้ำให้** — ยิง 2 ครั้งได้ 2 โพสต์) |
| เช็กสถานะ | ต้อง `approved` ก่อน ยิง API ตรงข้ามขั้นไม่ได้ |
| เช็กช่องว่าง | แคปชั่นที่ยังมี `{ชื่อสาขา}` ค้าง → ปุ่มกดไม่ได้ + route ปฏิเสธ |
| กรณีโพสต์ติดแต่ DB พัง | คืน `post_id` กลับมาพร้อมคำเตือน **“อย่ากดซ้ำ”** ไม่ใช่ error เปล่า ๆ |

### ✅ ผลทดสอบจริงกับเพจ (2026-08-10) — ไม่มีอะไรโผล่บนหน้าเพจ
```
เช็กการเชื่อมต่อ   ✅ Division X Card · ผู้ติดตาม 79
อัปรูปไม่เผยแพร่    ✅ PNG 2.8 MB · photoId=122123698262914175 · published=false
```
ข้อสองเดินเส้นทางเดียวกับตอนโพสต์จริงทุกประการ (ส่งแคปชั่นไทย + ให้ Facebook ไปดึงรูป
จาก Supabase Storage เอง) ต่างแค่ไม่กดเผยแพร่ → พิสูจน์ว่าโพสต์พร้อมรูปทำได้จริง

> ⚠️ (17 ต.ค. 2026) ผลข้อนี้พิสูจน์แค่ว่า token กับรูปใช้ได้ **ไม่ได้พิสูจน์ว่าคนนอกเห็นโพสต์**
> ตอนนั้นแอปยังอยู่ Development โพสต์จริงที่ตามมาจึงเห็นแต่คนที่มี role บนแอป → ขั้น 8

**โหมดทดสอบ** — route รับ `dryRun: true` จะอัปรูปขึ้น Facebook แต่ไม่เผยแพร่
(`published=false` · ไฟล์หายเองใน ~24 ชม. · ไม่แตะ DB) ใช้ตรวจว่า token/รูปใช้ได้จริง
โดยไม่มีอะไรโผล่บนเพจ · **ใช้ได้เฉพาะโพสต์ที่มีรูป** เพราะ `/feed` ไม่มีโหมดนี้

## เมื่อ token ใช้ไม่ได้ขึ้นมา

Page token ไม่มีวันหมดอายุ **แต่ถูกเพิกถอนได้** — เปลี่ยนรหัสผ่าน Facebook, ถอดสิทธิ์แอป,
หรือหลุดจากแอดมินเพจ · ระบบจะขึ้นข้อความบอกตรง ๆ ว่าให้ไปออกใหม่ ไม่ใช่ error อังกฤษดิบ ๆ
วิธีแก้คือทำข้อ 2-4 ใหม่ (ข้อ 1 ไม่ต้องทำซ้ำ)

หลัง Live มีอีก 2 ทางที่ทำให้ token ใช้ไม่ได้ทั้งแอป: **ไม่ทำ Data Use Checkup ทันกำหนด** (แอปถูกปิดจนกว่าจะทำเสร็จ)
และ **แอปไม่เรียก API เลย 90 วัน** (`marketing-metrics.yml` ดึงยอดโพสต์วันละ 4 รอบอยู่แล้ว
ข้อนี้จะเกิดก็ต่อเมื่อ GitHub Actions ตายยาว — เคยตายมาแล้วช่วง ก.ย. 2026)
