# ปฏิทินโพสต์ + ต่อตัวคิดมุมเข้า workflow

## เช็กข้อมูลจริงก่อน แล้วโจทย์เปลี่ยน

เจ้าของขอ *"หน้าปฏิทินเพื่อแสดงรายการโพสต์"* ตามแบบ heroaiengine

ยิงดูข้อมูลก่อนเขียนโค้ด:
```
marketing_content 19 แถว
  มี scheduled_at : 0     ← ไม่มีอะไรในระบบเซ็ตมันเลย
  มี posted_at    : 1
```

**ปฏิทินแบบ "แสดงอย่างเดียว" จะได้ตารางเปล่ามี 1 จุด** — ทำตามคำขอตรงตัวแล้วได้ของที่ใช้ไม่ได้

จึงใส่ตัวกำหนดวันมาด้วย (กล่อง "ยังไม่ได้กำหนดวัน" ข้างปฏิทิน เลือกวันแล้วชิ้นนั้นไปโผล่ในตาราง)
ไม่ใช่การขยายงานเกินคำขอ แต่เป็นสิ่งที่ทำให้ของที่ขอ *ทำงานได้* · ใช้ PATCH เดิมที่รับ
`scheduled_at` อยู่แล้ว ไม่ต้องมี route ใหม่

## เรื่องเวลา — จุดที่ปฏิทินพังง่ายที่สุด

`posted_at` / `scheduled_at` เป็น timestamptz (UTC) แต่คนไทยอ่านปฏิทินตามเวลาไทย

```
โพสต์ตี 1 ของวันที่ 8 (ไทย)  =  18:00 UTC ของวันที่ 7
```
ตัดวันด้วย UTC → โพสต์ไปโผล่ผิดวัน · ไทยไม่มี DST เลยบวกคงที่ 7 ชม. ก่อนตัดวันได้เลย

**แยกเป็น `lib/thaiDate.js` ใช้ร่วมกันทั้ง API และหน้าเว็บ** — ไม่ใช่เพื่อความสวยงามของโค้ด
แต่เพราะสองฝั่งต้องตัดวันด้วยกฎเดียวกันเป๊ะ ถ้า API จัดโพสต์ไว้วันนึงแต่หน้าเว็บวาดอีกวันนึง
คนจะกดหาไม่เจอ · ก๊อปโค้ดไปวางสองที่แล้ววันหลังแก้ไม่ครบ = พังเงียบ ๆ ไม่มี error

### ทดสอบ 31 เคส ผ่านหมด
เน้นเคสขอบที่พังง่าย ไม่ใช่เคสกลาง ๆ ที่ยังไงก็ผ่าน:

| เคส | ทำไมต้องทดสอบ |
|---|---|
| 16:59 UTC = ยังวันที่ 7 · 17:00 UTC = วันที่ 8 แล้ว | จุดตัดวันพอดีเป๊ะ ผิด 1 นาทีคือผิดวัน |
| ขอบเดือนครอบนาทีแรก/สุดท้ายของเดือนไทย | โพสต์วันที่ 1 ตอนเช้าหรือวันที่ 31 ตอนดึกต้องไม่หาย |
| ก่อนขอบ 1 วิ ต้องหลุดออก | ไม่กินโพสต์ของเดือนก่อนหน้ามาแสดง |
| ก.พ. 2028 = 29 วัน · 2027 = 28 วัน | ปีอธิกสุรทิน |
| เลื่อนเดือนข้ามปี ทั้งสองทิศ | ธ.ค.→ม.ค. และ ม.ค.→ธ.ค. |
| เลือกวันแล้วอ่านกลับได้วันเดิม | ไป-กลับผ่าน timestamptz ต้องไม่เลื่อน |
