# เทมเพลตหมดหน้าที่ — AI ขึ้นเป็นทางหลัก

เจ้าของสั่งสั้น ๆ ว่า *"ให้ AI เป็นทางหลักแทนเทม"* ต่อจากที่เคยบอกไว้ว่า
*"ระบบของที่ออกแบบได้มันเป็นรูปแบบเดียวกันหมดทุกคอนเทนต์ ซึ่งเปลี่ยนแค่ข้อความและรูปสินค้า"*

ต่อจาก [[2026-08-27-caption-sku-autolink]] ที่เพิ่งทำให้ระบบรู้ว่าคอนเทนต์แต่ละชิ้นพูดถึงซองไหน

## ทำไมเทมเพลตเคยจำเป็น และทำไมตอนนี้ไม่แล้ว

เหตุผลเดียวที่มีเทมเพลตคือ **ภาษาไทย** — Satori/next-og ที่ใช้ได้บน Vercel
ทิ้งวรรณยุกต์เมื่อซ้อนบนสระบน `"ที่"` กลายเป็น `"ที"` เลยต้องยิงไป GitHub Actions
เพื่อใช้ Chromium จริง (เขียนไว้ใน `poster/route.js` บรรทัด 3-7)

เลยทดสอบข้อนี้ก่อนเป็นอันดับแรก **ยิงจริง 4 ใบ ไม่ใช่อ่านเอกสาร**:

| ทดสอบ | ผล |
|---|---|
| ไทยล้วน ไม่มีรูปอ้างอิง | ✅ ถูกทุกตัว รวมวรรณยุกต์+สระบน/ล่าง |
| ไทย + แนบซอง Pokémon จริง | ✅ ซองตรงของจริงครบ อักษรญี่ปุ่นไม่เพี้ยน |
| OP-17 ที่เพิ่งอัปรูป | ✅ ป้าย OP-17 · 4th Anniversary · 全131種+4種 อ่านออกหมด |
| `gpt-image-1-mini` (ตัวถูกกว่า) | ❌ **วาดซองใหม่** ตัวโปเกมอนเพี้ยน อักษรญี่ปุ่นมั่ว |

ข้อสุดท้ายสำคัญ — mini เร็วกว่า 4.8 เท่า (32 วิ vs 153 วิ) และถูกกว่า
แต่มันไม่ยึดรูปอ้างอิง ซึ่งเป็นสิ่งเดียวที่ห้ามพลาดสำหรับโปสเตอร์สินค้า
**ต้องอยู่กับ gpt-image-2 แม้จะช้ากว่า**

เจอเพิ่มระหว่างทาง: **moderation block เกิดขึ้นจริง** แม้กับโปสเตอร์โปเกมอนธรรมดา
แต่ยิง prompt เดิมซ้ำแล้วผ่านเลย → เป็นการสุ่ม ไม่ใช่ค่าตายตัว retry แก้ได้

## ไม่สลับเลยทันที — audit ก่อน

ปุ่ม AI มีมานานแล้วแต่เป็นลิงก์เทาจางเขียนว่า "ต้องเปิด billing" แทบไม่มีใครกด
ข้อบกพร่องทุกอย่างในเส้นทางนี้จึงไม่เคยทำร้ายใคร **พอเป็นปุ่มหลักคือโดนทุกครั้งที่กด**

ยิง audit 5 มุมขนานกัน แล้วทุกข้อที่เจอส่งให้อีกตัวไป**พยายามหักล้าง**ก่อนเชื่อ

> เจอ 60 ข้อ → ยืนยัน 31 → **ตกไป 29** (เกือบครึ่งเป็นการเดาที่ยืนยันไม่ได้)

ตัวหักล้างมีประโยชน์กว่าที่คิด บางข้อมันไม่ได้แค่ยืนยัน แต่บอกว่า
**"เขารายงานต่ำกว่าความจริง"** เช่นข้อ timeout ที่คนแรกมองไม่เห็นว่า
`AbortSignal.timeout(300000)` อยู่ใน `for (const model of models)`

## ที่แก้รอบนี้

### เวลา — ทั้งโปรเจกต์ไม่เคยตั้ง `maxDuration` เลยสักที่

ค้นทั้ง repo ไม่มี `maxDuration` ในซอร์สแม้แต่ไฟล์เดียว ไม่มี `vercel.json` ด้วย
ทุก route ใช้ค่า default ของแพลตฟอร์มล้วน ๆ ซึ่งต่ำกว่า 150 วินาทีมากถ้าไม่ได้เปิด Fluid

ที่แย่กว่านั้น: `timeout` ตั้งไว้ **300 วิต่อโมเดล** แล้ววนโมเดลสำรองอีก 3 ตัว
= กรณีแย่สุดเกิน 20 นาที ซึ่งไม่มีวันได้คืน response เลย ผู้ใช้เห็นแค่ 504 เปล่า ๆ
ทั้งที่โค้ดอุตส่าห์เก็บ `attempts` ไว้บอกว่าพังเพราะอะไร

→ ตั้ง `maxDuration = 300` + เปลี่ยนเป็น **งบเวลารวมทั้ง request 240 วิ**
เช็กเวลาที่เหลือก่อนยิงโมเดลถัดไป และคำนวณ `signal` จากเวลาที่เหลือจริง

> ตัดสินใจอยู่บน Vercel ต่อ ไม่ย้ายไป GH Actions รอบนี้ เพราะ orgId ขึ้นต้น `team_`
> = แพ็กเกจ Pro ซึ่งตั้งเพดาน 300 วิได้แน่นอนไม่ว่าจะเปิด Fluid หรือไม่
> การย้ายยังต้องให้เจ้าของใส่ `OPENAI_API_KEY` เป็น GitHub Secret ด้วย
> — **ไม่ก๊อปคีย์ไปเองตามที่เจ้าของกำชับ**

### ตอนพัง — key เสียแล้วเว็บบอกว่า "ต้องเข้าสู่ระบบก่อน"

`route` คืน **401** เมื่อ key ของ OpenAI ใช้ไม่ได้ แต่ในระบบนี้ 401 ถูกจองไว้ให้
auth ของ Supabase → `api()` เห็น 401 แล้ว `setAuthState("anon")` ทั้งหน้า

อาการที่เจ้าของจะเห็นคือ "ถูกเตะออกจากระบบ" แล้วไล่ login ใหม่ซ้ำ ๆ
ทั้งที่ปัญหาอยู่คนละเรื่อง → เปลี่ยนเป็น **502 + `code: "provider_auth"`**

เรื่องเดียวกันอีกชั้น: `api()` อ่านแค่ `json.error` ทิ้ง `hint` ทั้งก้อน
แต่**วิธีแก้จริงเกือบทุกเคสอยู่ใน `hint`** เช่น
*"ChatGPT Plus ที่จ่ายรายเดือนใช้กับ API ไม่ได้ คนละบิลคนละระบบ"*
→ ให้ `api()` พก `hint`/`attempts`/`code` ติดมาด้วย แบนเนอร์โชว์เป็นบรรทัดที่สอง

### เงิน — ไม่มีตัวกันกดซ้ำฝั่งเซิร์ฟเวอร์เลย

ตัวกันที่มีคือ `disabled={imaging.has(item.id)}` ฝั่งหน้าเว็บอย่างเดียว
ซึ่งหายทันทีที่รีเฟรช เปิดแท็บที่สอง หรือกดจากคนละเครื่อง
ตอนเป็นปุ่มเทาความเสียหายเป็นศูนย์ พอเป็นปุ่มหลัก **ทุกคลิกคือเงินจริงหนึ่งใบ**

→ มีรูปแล้วกดซ้ำ = **409** แล้วหน้าเว็บถามยืนยันก่อนส่ง `force`

### ข้อความที่โกหกมาตลอด

ปุ่มเขียนว่า *"พื้นหลัง AI (ต้องเปิด billing)"* tooltip อ้าง **Gemini**
ทั้งที่ provider จริงคือ OpenAI และ `poster_mode: full` = มันวาดโปสเตอร์ทั้งใบ
ไม่ใช่แค่พื้นหลัง · ข้อความระหว่างรอบอก *"ปกติ 60-120 วิ"* ทุกทาง
ซึ่งผิดสำหรับ AI เสมอ (จริง 150-200 วิ) → แยกธง `imagingKind` แล้วบอกตามทางที่ใช้จริง

## ที่ยังไม่แก้ (รู้แล้วแต่จงใจปล่อยไว้)

จาก 31 ข้อที่ยืนยัน รอบนี้แก้ 8 ข้อที่จะโดนทันทีเมื่อเป็นทางหลัก ที่เหลือ:

- **พาดหัวยาว 150-184 ตัวอักษรถูกส่งให้ AI เขียนลงภาพ** ขัดกฎแบรนด์ข้อ 8/19/24 เอง
  และความเสี่ยงไทยเพี้ยนโตตามความยาว — ฝั่งเทมเพลตมี `split_head()` แต่ฝั่ง AI ไม่มี
- **กฎข้อ 5 (สัดส่วนภาพ)** — prompt สั่ง `square 1:1` ตรง ๆ ใน 3 ที่ ขณะที่กฎห้าม 1:1
- **ป้าย "มีใน N ตู้"** นับตู้ที่ *เคยมี* ไม่ใช่ *มีของให้กดตอนนี้* (ไม่กรอง `remain > 0`)
- **`machine_stock` ไม่ใช้ `fetchAll`** — ชนเพดาน 1000 แถวได้เมื่อตู้เพิ่มขึ้น
- **ไม่บันทึก `usage` ที่ OpenAI ส่งกลับมา** — สอบย้อนต้นทุนต่อใบไม่ได้

## บทเรียน

**ปุ่มที่ไม่มีใครกด = โค้ดที่ไม่มีใครทดสอบ** ทุกข้อข้างบนอยู่ในโค้ดมานานแล้ว
แต่ไม่เคยเป็นปัญหาเพราะเส้นทางนี้แทบไม่ถูกเดิน การเลื่อนอะไรขึ้นเป็นทางหลัก
คือการเปิดโปงทุกอย่างที่ซ่อนอยู่พร้อมกัน — ต้อง audit ก่อนสลับ ไม่ใช่หลังสลับ

**หักล้างมีค่ากว่ายืนยัน** 29 จาก 60 ข้อตกไปเพราะพิสูจน์ไม่ได้
ถ้าเชื่อรายงานแรกทั้งหมดจะเสียเวลาแก้ของที่ไม่ได้พัง เกือบครึ่ง
