# ต่อวงจรการตลาดช่วงท้าย — จุดที่ของค้างมา 3 วันโดยไม่มีใครรู้

## บริบท (why)

วงจรที่ออกแบบไว้คือ **ไอเดีย → AI ร่างแคปชั่น → ตรวจ/อนุมัติ → Telegram → โพสต์ → บันทึก**
เฟส 1+2 ทำถึงขั้น "อนุมัติ" แล้ว แต่พอไล่ดูข้อมูลจริงพบว่า

```
สถานะ: {'pending': 5, 'approved': 9, 'draft': 1}
มี posted_at: 0            ← ทั้งตาราง
```

**อนุมัติค้างไว้ 9 ชิ้นตั้งแต่ 4 ส.ค. ไม่มีอะไรพาไปโพสต์เลย** — กดอนุมัติแล้วการ์ด
หายไปจากหน้าจอ เหมือนงานเสร็จ แต่จริง ๆ คือตกหล่น

## 🔍 สาเหตุ

`marketing_reminder.py` ดึงแคปชั่นจาก `deploy/tasks/content_queue.json`
ซึ่งเป็นไฟล์ static ของระบบเดิม (ระดับ 2) — **ไม่เคยแตะตาราง `marketing_content` เลย**
คือของสองระบบวางคู่กันโดยไม่ได้ต่อกัน

ผลพลอยได้: `posted_at` ว่างทั้งตาราง → กราฟ "โพสต์ช่วยไหม" ในโซน D
ไม่มีข้อมูลจะคำนวณ ขึ้นข้อความว่า "ยังไม่มีโพสต์ที่บันทึกไว้" มาตลอด
ซึ่งอ่านแล้วเหมือนยังไม่ได้เริ่มทำ ทั้งที่ทำไปแล้วแต่ไม่ได้บันทึก

## สิ่งที่ทำ

**1. `marketing_reminder.py` → อ่านจาก DB เป็นหลัก**
- query `status=approved` **และ** `posted_at is null` — เงื่อนไขหลังสำคัญ
  ถ้าใช้แค่ status จะส่งซ้ำของที่โพสต์ไปแล้ว
- ส่งทีละไม่เกิน 3 ชิ้น + บอกจำนวนที่เหลือ (ยิงหมดทีเดียวข้อความยาวจนไม่มีใครอ่าน)
- `content_queue.json` **ลดชั้นเป็น fallback** ใช้เฉพาะตอน DB ไม่มีของ
  → ไม่ให้มีแหล่งความจริง 2 ที่พร้อมกัน ซึ่งเป็นต้นเหตุของปัญหานี้ตั้งแต่แรก
- เดิม `if not tasks: return` — slot ที่ไม่มี checklist จะจบทันที
  ตอนนี้ถ้ามีของรอโพสต์ยังส่งอยู่ดี
- เพิ่ม `--dry-run` พิมพ์ข้อความออกจอ ทดสอบได้โดยไม่ยิงเข้ากลุ่มจริง

**2. workflow** ส่ง `SUPABASE_URL` / `SUPABASE_SERVICE_KEY` เข้าไป (เดิมมีแต่ Telegram)

**3. หน้าเว็บ — โซน "รอโพสต์"**
ปุ่ม **โพสต์แล้ว** / **ก๊อปแคปชั่น** / **เอากลับไปแก้**
กดอนุมัติแล้วการ์ดเด้งลงกล่องนี้ทันที ไม่หายไปเฉย ๆ เหมือนเดิม

## ⚠️ เจอระหว่างทาง — ของที่ "อนุมัติแล้ว" ส่วนใหญ่ยังโพสต์ไม่ได้

8 ใน 9 ชิ้นเป็น **seed จาก `content_queue.json`** (`created_by=human`, `idea_id=null`)
ไม่ได้ผ่านตาใครจริง ๆ และ **5 ชิ้นยังมีช่องว่างค้าง**

| id | ปัญหา |
|---|---|
| #5 | `{ชื่อการ์ด}` `{สาขา}` |
| #6 | `{ชื่อเซ็ต}` `{สรุปสั้น 2-3 บรรทัด}` |
| #9 | `{รางวัล}` `{วัน}` |
| #11 | `{เซ็ต}` `{ชื่อการ์ด}` |
| #7 | เขียนว่า **"มี 11 สาขาแล้ว"** — ตอนนี้ 13 ตู้ ผิดข้อเท็จจริง |

มีแค่ **#16** ที่เป็นของจริง (`created_by=ai`, มาจาก idea 5)

เพิ่มการเตือนช่องว่างทั้งใน Telegram และบนการ์ด (regex `\{[^}]{1,40}\}`)
แต่ **ยังไม่ได้ลบ seed ทิ้ง** — รอเจ้าของตัดสินใจ

## บทเรียน

ตัวเลขที่ดู "ปกติ" (`approved: 9`) อาจแปลว่าของค้าง ไม่ใช่ของเสร็จ
**สถานะปลายทางที่ไม่มีใครเคยแตะ = สัญญาณว่าวงจรขาด** —
ถ้า `posted_at` ว่างทั้งตารางทั้งที่ระบบเปิดมาหลายวัน ต้องสงสัยไว้ก่อน

## ✅ วงจรเดินจริงแล้ว

เจ้าของกด **"โพสต์แล้ว"** ที่ #16 (ตัวที่ AI เขียนจากไอเดีย #5 — ตัวเดียวที่เป็นของจริง)

| ตรวจ | ผล |
|---|---|
| `status` | `approved` → `posted` |
| `posted_at` | `2026-08-07T16:52:14Z` = 23:52 น. ไทย |
| คิวรอโพสต์ | 9 → 8 |
| ยอดขายวันที่ 7 ส.ค. | มี 139 รายการ → หมุดขึ้นกราฟได้ |

**นี่คือ `posted_at` แถวแรกของทั้งตาราง** ตั้งแต่เปิดระบบมา

## 🗑️ ทิ้ง seed ทั้ง 8 — และกับดักที่ตามมาทันที

เจ้าของตัดสินว่า seed ทั้งหมด "ไม่ค่อยมีประสิทธิภาพ" ให้ทิ้ง
→ เซ็ต `rejected` พร้อม `reject_reason` รายตัว **ไม่ได้ DELETE**
เพราะ route ออกแบบไว้ให้เก็บเหตุผลไปป้อนกลับ prompt รอบหน้า และย้อนได้ถ้าเปลี่ยนใจ

**แต่ทิ้งแล้วเกิดปัญหาต่อทันที:** commit ก่อนหน้าเพิ่งตั้ง `content_queue.json`
เป็น fallback ตอนคิวว่าง — ซึ่งไฟล์นั้นคือ**ต้นฉบับของ seed ที่เพิ่งทิ้ง**
พรุ่งนี้เช้าคิวว่างพอดี Telegram จะหยิบ template ชุดเดิมส่งไปให้
**เท่ากับย้อนกลับการตัดสินใจที่เจ้าของเพิ่งทำ**

ตัด fallback ออก · คิวว่างให้ขึ้น "ยังไม่มีคอนเทนต์รอโพสต์" แล้วชี้ไป `/marketing`
ลบ `load_captions()` + `QUEUE` ที่กลายเป็นโค้ดตายด้วย (ไฟล์ json ยังอยู่เป็นคลังไอเดีย)

**บทเรียน: fallback ที่ดูปลอดภัยกลายเป็นอันตรายทันทีที่ของต้นทางถูกปฏิเสธ**
ทุกครั้งที่ลบ/ทิ้งข้อมูล ต้องถามว่ามีทางไหนที่มันกลับมาได้อีกไหม
