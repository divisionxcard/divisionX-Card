## เจอระหว่างทดสอบ (สำคัญกว่าตัวหน้าจอ)

ทดสอบด้วย Chrome จริง (Playwright `channel="chrome"`) + API จำลอง (session ปลอม · อัปโหลดจริงเข้า `video-probe/` แล้วลบทิ้ง)
แล้ว **เอาไทม์ไลน์ที่หน้าเว็บส่งออกจริงไปเรนเดอร์ในเครื่อง** — ถ้าไม่ทำขั้นนี้ บั๊ก 3 ข้อแรกจะไปโผล่ตอนเจ้าของกดครั้งแรก

1. **คลิปที่ไม่มีแทร็กเสียงทำทั้งงานล้ม** — คลิป Flow ไม่มีเสียง แต่ `<video data-has-audio="true">` ทุกชิ้น
   → HyperFrames: *"composition asset(s) do not match their authored media element type (expected: audio)"*
   (ช่วง A ทดสอบผ่านเพราะใช้คลิปที่ปิดเสียง)
2. **keyframe ห่าง 4–8 วิ** ในไฟล์มือถือ/Flow → HyperFrames เตือนว่าข้ามช่วงแล้วภาพค้าง
   → แก้ทั้งสองข้อด้วย `hf_timeline._prep_video`: ตัดเฉพาะช่วง in–out · 30 fps keyframe ทุก 1 วิ · ย่อไม่เกินที่คลุมจอ · ไม่มีเสียง = volume 0
   (ไฟล์เดียวกันหลายชิ้นโหลดครั้งเดียว · ต้นฉบับใหญ่ลบทิ้งหลังหั่น)
3. **ตัวหนังสือในคลิปตัดบรรทัดเร็วกว่าพรีวิว** — ในเทมเพลต `.ov-in` ไม่มี `width: max-content` กล่องจึงถูกบีบตามระยะจุดวางถึงขอบขวา
   ("OP-17 มา / ถึงตู้แล้ว!" ที่ 540 px) · **แก้สไตล์ของทับต้องแก้สองที่** (เทมเพลต + `edit.module.css`)
4. **ความดังเพลงที่ผู้ใช้ปรับไม่ถึงตัวผสม** — `sound.master` ใช้ 22% ตายตัว → เพิ่ม `music_volume=`
5. **Storage รับ ≤ 50 MB/ไฟล์** (แพ็กเกจฟรี · ยิง 60 MB ได้ 413 EntityTooLarge) — route ตั้งไว้ 1 GB
   → วิดีโอที่เกิน **ย่อในเบราว์เซอร์ก่อนส่ง** (`compress.js` · mediabunny@1.61.2 MPL-2.0 · WebCodecs · โหลดเฉพาะตอนใช้)
   ทดสอบ 56 → 44 MB + อัปเสร็จ 16 วิ · route ลดเพดานเหลือ 50 MB ให้ตรงของจริง
6. Next 14.1+ ส่ง `history.replaceState` ต่อให้ `useSearchParams` — ถ้าผูก key ของห้องกับ `?id=` ห้องจะโหลดใหม่ทั้งห้องหลังบันทึกครั้งแรก
   (ประวัติย้อนกลับหาย) → หน้าอ่าน id ครั้งเดียวตอนเปิด
7. ท่าโผล่ของตัวหนังสือตอนหยุดอยู่ตรงจุดเริ่มพอดี = เฟรมแรกที่จางหาย มองไม่เห็นว่าวางไว้ → หยุดอยู่โชว์เต็มตัว เล่นจริงค่อยมีท่า

ผลเรนเดอร์ไทม์ไลน์จากหน้าเว็บ: 14.5 วิ · −14.0 LUFS · ภาพตรงพรีวิวทุกจุด (คลิป Flow หั่น 2 ท่อน + รูปซองพื้นเบลอ + คลิปที่อัป + ซอง/ตัวหนังสือ/โลโก้/ฉากปิด/ซับ)
