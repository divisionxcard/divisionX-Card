## อีกสี่ข้อที่ตรวจเจอ

**1. คลังความรู้ไม่ตามรูปแบบในรอบเขียนใหม่** — `knowledge` คำนวณครั้งเดียวจาก
รูปแบบรอบแรก แต่รอบสอง (ตอนแคปชั่นซ้ำเกิน 0.5) สุ่มรูปแบบใหม่ทั้งคู่แล้วใช้ก้อนเดิม

โดยที่คลัง care ไม่ได้อยู่ใน prompt เลย → โมเดลแต่งวิธีเก็บรักษาขึ้นเอง

ซึ่งคือสิ่งที่ `careBlock()` เขียนกฎห้ามไว้ทั้งย่อหน้าเมื่อวาน เพราะ
**แนะนำผิดแปลว่าการ์ดลูกค้าพังจริง** — กฎอยู่ในบล็อกที่ไม่ได้ถูกส่งไป กฎเลยไม่มีผล

**2. `headline.js` ยังตัดกลางคำไทยได้** — ตัวถอยหลังรู้จักสระบน/ล่างกับวรรณยุกต์
แต่ไม่รู้จัก **สระหน้า เ แ โ ใ ไ** ซึ่งเขียนไว้ *ก่อน* พยัญชนะ

```
"คนไทยชอบสะสมการ์ดกันมากขึ้นเรื่อยๆ..."
  → พาดหัว: "...มากขึ้นเ"     ← สระลอย
  → บรรทัดรอง: "รื่อยๆ..."
```

ตรงกับกรณีที่ไฟล์เขียนห้ามไว้เอง (`"ถึงก" + "ับ"`) — เป็นคนละครึ่งของกฎเดียวกัน

**3. ก๊อปตรรกะแบ่งหน้ามาวางซ้ำ** — `lib/fetchAll.js` เขียนที่หัวไฟล์ว่า
*"ห้ามก๊อปตรรกะนี้ไปวางซ้ำ · โปรเจกต์นี้เคยเจ็บกับ SKU mapper ที่ถูกก๊อปไป 6 ไฟล์"*
แล้วโค้ดนับ "มีใน N ตู้" ก็เขียน loop `.range()` เองอยู่ข้าง ๆ กัน
แถมไม่มี `.order()` ลำดับข้ามหน้าจึงไม่การันตี

**4. ข้อความบอกผู้ใช้ไม่ตรงกับที่เกิดขึ้น** — ตัวยิงซ้ำเมื่อโดนตัวกรองเนื้อหา
ยิงไม่ได้จริงในเคสที่เขียนมาแก้ งบ 270 วิ กับเวลาวาดจริง ~150 วิ = **ยิงเต็ม ๆ ได้รอบเดียว**
บล็อกที่ `stage=output` (เคสที่พิสูจน์มาเมื่อวาน) เหลือเวลาไม่ถึง `MIN_GEN_MS` เสมอ
ด่านเวลาจึง break ออกก่อน แต่ข้อความตอบกลับบอกว่า *"ระบบลองซ้ำให้แล้ว"*

> คำตอบที่ถูกในเคสนี้คือ "กดใหม่" แต่ข้อความเดิมทำให้เข้าใจว่ากดใหม่ก็เท่านั้น
> แก้เป็นนับจำนวนครั้งที่ได้ยิงซ้ำจริง แล้วแยกข้อความตามนั้น

# เพิ่มป้ายเครดิต OpenAI คงเหลือ

> *"ตอนนี้ผมไม่สามารถรู้ได้เลยว่าเครดิตที่จะใช้ให้เอไอสร้างภาพนั้นเหลือเท่าไหร่"*

## ยิงจริงก่อนออกแบบ แล้วพบว่าโจทย์ไม่ใช่อย่างที่คิด

ตั้งใจจะดึงยอดคงเหลือมาแสดงตรง ๆ แต่ทดสอบด้วย key จริงก่อนแล้วพบว่า
**OpenAI ไม่เปิดให้อ่านยอดคงเหลือผ่าน API เลย**

```
GET /dashboard/billing/credit_grants
  → 403 "must be made with a session key (that is, it can only be made from the browser)"
GET /v1/organization/costs        → 403 "Missing scopes: api.usage.read"
GET /v1/organization/usage/images → 403 "Missing scopes: api.usage.read"
```

สองตัวหลังใช้ได้ถ้าเป็น **Admin key** (`sk-admin-…` สร้างแยกจาก key ที่เรียกโมเดล)
แต่ให้แค่ *"ใช้ไปเท่าไหร่"* — *"เหลือเท่าไหร่"* ไม่มีทางรู้จาก API

> ถ้าไม่ยิงทดสอบก่อน คงเขียนโค้ดเรียก `credit_grants` ไปแล้วมาพังตอนขึ้นจริง
> ข้อความ 403 ของมันบอกสาเหตุตรง ๆ ว่า "ต้องเป็น session key จากเบราว์เซอร์เท่านั้น"

## จึงคำนวณเอา

```
คงเหลือ = ยอดที่เจ้าของอ่านจากหน้า OpenAI ณ เวลาหนึ่ง − costs ตั้งแต่เวลานั้น
```

**เก็บเป็น "ยอดที่อ่านได้" ไม่ใช่ "ยอดที่เติม"** — จุดตัดสินใจที่สำคัญที่สุดของงานนี้
ยอดอ่านได้มันแก้ตัวเองทุกครั้งที่บันทึกใหม่ ครอบคลุมทั้งการเติมเงิน เครดิตแถม
เงินคืน และ auto-recharge โดยไม่ต้องรู้ว่าเกิดอะไรขึ้นระหว่างทาง
ถ้าเก็บเป็นยอดเติม ต้องบันทึกให้ครบทุกรายการ **ขาดรายการเดียวเลขผิดตลอดไป**
และเวลาเลขเพี้ยนก็ไม่มีทางกู้กลับ

**นับค่าใช้จ่ายทั้งองค์กร ไม่กรองเฉพาะค่าสร้างภาพ** — สิ่งที่กินเครดิตมีมากกว่าโปสเตอร์
(ตรวจปรู๊ฟใช้โมเดลอ่านภาพ · กดจาก playground เอง) และคำถามจริงของเจ้าของคือ
"เงินในบัญชีเหลือเท่าไหร่" ไม่ใช่ "โปสเตอร์กินไปเท่าไหร่"

## ที่ยังไม่ได้ทำ และรู้ตัว

- **ไม่แปลงเป็นบาท** — ต้องมีอัตราแลกเปลี่ยนซึ่งจะค้างเก่าเงียบ ๆ
  เป็นความผิดพลาดแบบเดียวกับที่เพิ่งไล่แก้ไปเมื่อเช้า
- **ไม่บอกว่า "พอสร้างได้อีกกี่ภาพ"** — ต้องรู้ราคาต่อภาพ ซึ่งระบบ*ไม่เคยเก็บ*
  `usage` ที่ OpenAI ส่งกลับมาทุกครั้งถูกแสดงบนหน้าจอแล้วทิ้ง
  ถ้าอยากได้ ต้องมีตารางบันทึกทุกครั้งที่สร้างภาพก่อน
- **เลขเป็นค่าประมาณ** — bucket ของ costs API กว้างวันละก้อน บันทึกยอดกลางวัน
  แล้วค่าใช้จ่ายของวันนั้นก่อนหน้านั้นอาจถูกนับรวม คลาดเคลื่อนได้ไม่เกิน 1 วัน
  แก้ด้วยการบันทึกยอดใหม่ ซึ่งรีเซ็ตจุดตั้งต้นให้เอง

เจ้าของทำตามแล้วได้ `sk-proj-` มา ซึ่ง**เป็น key คนละตัวกับตัวเดิมจริง**

> คำแนะนำที่ "ถูกแต่กำกวม" แพงกว่าคำแนะนำที่ผิดชัด ๆ เพราะคนทำตามแล้วได้ผลลัพธ์
> ที่ดูเหมือนสำเร็จ จึงไม่ย้อนกลับมาสงสัยขั้นตอนนั้นอีก

ที่ถูกคือ **platform.openai.com/settings/organization/admin-keys**
ได้ `sk-admin-` · เห็นเมนูนี้เฉพาะ Organization Owner

⚠️ ตรวจ prefix เฉพาะตอนที่ยิงแล้วพัง **ไม่ดักก่อนยิง** — ถ้า OpenAI เปลี่ยนรูปแบบ key
