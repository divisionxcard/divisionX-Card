# ย้ายคลังไฟล์วิดีโอ/รูปออกจาก Supabase ไป Cloudflare R2 (23 ต.ค.)

## เจ้าของถาม

> "ถ้าเกิดใช้ซุปเบสเดียวกัน จะทำให้กระทบต่ออายุการใช้งานส่วนที่เก็บดาต้ารายวันลดลงไหม และถ้าหากไม่ต้องการซื้อแพ็กเกจเพิ่ม
> ควรมีวิธีไหนบ้างที่จะสามารถทำแยกเพื่อเก็บเฉพาะวิดีโอหรือรูปภาพได้"

## คำตอบที่ให้ไป (ตัวเลขจากหน้าทางการของ Supabase)

- ไฟล์**ไม่กิน**พื้นที่ฐานข้อมูล 500 MB โดยตรง แต่มี 2 อย่างที่ใช้ร่วมกันทั้งองค์กร: **Storage 1 GB** และ **ดาวน์โหลด (egress) 5 GB/เดือน**
- เกินแล้ว Supabase เตือน → ช่วงผ่อนผัน → **จำกัดการใช้งาน (ตอบ 402 / อ่านอย่างเดียว / หยุดโปรเจกต์)** = ซิงค์ยอดขาย/สต็อกรายวันตาย · เกินซ้ำไม่มีผ่อนผันอีก
- โควตานับ **ทั้ง organization** → สร้างโปรเจกต์ Supabase ที่ 2 ใน org เดิมไม่ช่วย
- วัดจริงตอนนั้น: Storage ใช้ 324 MB (marketing 291 · รูปซอง 24 · รูปสินค้า VMS 9) · ห้องตัดต่อที่เพิ่งทำกับ "เก็บไฟล์ตลอด" จะเต็มเร็ว

เสนอ 4 ทาง (R2 · Backblaze B2 · Supabase org ใหม่ · เก็บถาวรในเครื่อง/Drive) — เจ้าของเลือก **R2** แล้วสมัครเอง

## R2 ที่ตั้งไว้

- bucket `dvx-media` (APAC · Standard · **ส่วนตัว**) · CORS ให้ `division-x-card.vercel.app` + `localhost:3000` (GET/PUT/HEAD)
- คีย์ "Object Read & Write" เฉพาะ bucket นี้ → ใน `deploy/.env.local` · GitHub secrets · Vercel env (ตั้งผ่าน API ไม่พิมพ์ค่า)
- ⚠️ ลิงก์ `r2.dev` จำกัดความเร็ว Cloudflare บอกให้ใช้แค่ทดสอบ · ไม่มีโดเมนของตัวเอง → ใช้ **ลิงก์ลงชื่อ** แทน
- ⚠️ การเปิด R2 ถามเบอร์โทรของ **Link (Stripe)** ที่อีเมลเคยผูกไว้ — ปิดกรอบนั้นแล้วกรอกบัตรตรงได้ ไม่ต้องยืนยัน

## โครงที่ทำ

```
ลิงก์ถาวร = https://division-x-card.vercel.app/media/<key>
  app/media/[...key]/route.js → 302 ไปลิงก์ลงชื่อ R2 (12 ชม.) · CDN จำ 1 ชม. · ไฟล์ไม่ผ่าน Vercel
  ปิด video-edits/ (ร่างงาน) · _selftest/ · ชื่อแปลก/ทะลุโฟลเดอร์ = 404
ตัวเซ็น SigV4 เขียนเอง ไม่ลงไลบรารี: deploy/lib/r2.js (เว็บ) · deploy/agents/r2.py (Python) — แก้วิธีเซ็นต้องแก้สองที่
Facebook ได้ลิงก์ลงชื่อตรง (directUrl) ไม่ต้องพึ่งการตาม redirect ของเขา
เครื่องเรนเดอร์เจอลิงก์ของเรา (ใหม่หรือ Supabase เดิม) → ดึงจาก R2 ด้วยคีย์ตรง
```

ตัวเขียนไฟล์ 13 จุดที่ย้าย: อัปรูปเอง · ภาพ AI · โปสเตอร์ (poster_render · top5_poster) · ฉาก AI (scene_batch · scene_for_content) ·
ชุดข้อมูล 5 ใบ · พื้นหลังโปสเตอร์ 5 ใบ · คลิปที่เรนเดอร์ (publish) · ฟุตเทจ/ภาพพื้นหลังวิดีโอ (hf_bg) · คลิป Flow (broll_import) ·
ห้องตัดต่อ (อัปโหลด + ร่างงาน)

ห้องตัดต่อ: เพดาน 50 MB หายไป (≤ 2 GB/ไฟล์) · วิดีโอเกิน 150 MB ยังย่อเป็น 1080p ก่อน — **เพื่อประหยัดคลังฟรี 10 GB** ไม่ใช่เพราะส่งไม่ได้

## ย้ายของเดิม (`scripts/r2_migrate_marketing.py`)

1. `--copy` 90/90 ไฟล์ 290.9 MB ขนาดตรงทุกไฟล์ (รันซ้ำได้ ข้ามไฟล์ที่มีแล้ว)
2. deploy เว็บที่มี `/media` ก่อน แล้วค่อย `--rewrite` (ลำดับนี้สำคัญ — สลับกันรูปจะเสียช่วงหนึ่ง)
   → `marketing_content.media_url` 30 · `video_jobs.video_url` 6 · `video_jobs.plan` 1 · `tasks/video_broll.json` 1 = 38 จุด
   → ไล่เปิดทุกลิงก์ผ่าน production ได้ 37/37 (สำรองค่าเดิมไว้ในเครื่องก่อนเปลี่ยน)
3. `--purge` ลบต้นฉบับใน Supabase (เฉพาะไฟล์ที่ R2 มีขนาดตรงกัน) — **ไม่รัน: เจ้าของให้เก็บไว้ก่อน** (ไม่มีอะไรอ่านแล้ว ไม่กินโควตาดาวน์โหลด)

## ทดสอบ

- selftest ทั้ง Python/JS: อัป · อ่าน · ลิสต์ · ลบ · CORS (เว็บจริง + localhost) · ชื่อไฟล์มีช่องว่าง · ไฟล์ 58 MB 5.7 วิ
- `/media`: 302 → 200 · range 206 (เลื่อนดูวิดีโอได้) · ร่างงาน/ทะลุโฟลเดอร์ 404
- Chrome จริง: ห้องตัดต่ออัป 2 ไฟล์ (รวม 56 MB ที่เดิมติดเพดาน) เข้า R2 ใน 6.2 วิ · พรีวิวโหลดคลิปจาก R2 ได้ทุกตัว
- เครื่องเรนเดอร์ดึงจาก R2 ทั้งลิงก์ใหม่/เดิม · โปสเตอร์ dry-run หยิบฉาก AI จาก R2 ได้
- **รันจริงบน GitHub Actions** (งาน `5ad37dcf` · ไทม์ไลน์ไม่มีเสียงพากย์ ไม่กินโควตาเสียง): ดึงคลิป Flow จาก R2 → เรนเดอร์ 39 วิ →
  อัปขึ้น R2 → `video_url` = `/media/video/edit-r2-ci-test.mp4` เปิดผ่าน production ได้ (7.0 วิ · 1080×1920) ภาพถูกต้อง
  · ⚠️ รอบนี้ขั้น "Install Python deps + Chromium" ช้า 535 วิ (ไม่เกี่ยวกับ R2 — ติดตามว่าช้าประจำหรือครั้งเดียว)

## ยังไม่ได้ทำ / ข้อควรรู้

- **ต้นฉบับ 290.9 MB ยังอยู่ Supabase ตามที่เจ้าของเลือก** — ใช้ Storage 291 MB จาก 1 GB แต่ไม่มีไฟล์ใหม่ลงที่นั่นแล้ว และไม่มีอะไรดาวน์โหลด
- รูปซอง (`sku-images`) กับรูปสินค้า VMS ไม่ได้ย้าย — เล็ก (33 MB) และหน้า /stock สาธารณะใช้ · ย้ายได้ทีหลังถ้า egress ยังสูง
- R2 ไม่มีเพดานใช้จ่ายอัตโนมัติ — เจ้าของตั้ง Budget Alert ในหน้า Cloudflare แล้ว
- ลิงก์ลงชื่อของ `/media` อายุ 12 ชม. — หน้าเว็บที่เปิดค้างเกินนั้นแล้วกดเล่นวิดีโอต่ออาจต้องรีเฟรช
