# เลือกวิธีทำภาพโพสต์: ให้ ChatGPT ออกแบบ แล้วมีด่านตรวจตัวอักษร

ต่อจาก [[2026-08-18-poster-style-gap]] ที่สรุปว่าระบบทำรูปไม่ถึงที่เจ้าของต้องการ
วันนี้ทดสอบจนได้ข้อสรุปว่าจะเดินทางไหน

## ทดสอบอะไรไปบ้าง (เจ้าของเติมเครดิต OpenAI $10)

| วิธี | ผล |
|---|---|
| gpt-image ทำโปสเตอร์ทั้งใบ | สวย แต่**สะกดไทยผิด** และ**วาดซองขึ้นใหม่** (เขียว→น้ำเงิน · BANDAI→BAP DAI) |
| แนบรูปซองจริงไปด้วย | **ยังวาดใหม่อยู่ดี** ทั้งที่ตั้ง `input_fidelity: high` |
| ให้วาดเฉพาะฉาก (ไม่มีสินค้า/ตัวหนังสือ) | สะอาด ใช้เป็นพื้นหลังได้ → ประกอบกับเทมเพลตแล้วได้ผลดี |
| เจ้าของเอาแคปชั่นให้ ChatGPT ออกแบบเอง | **ดีไซน์ดีที่สุดในทุกแบบที่ลอง** แต่สร้างสินค้าปลอมขึ้นมา |
| ChatGPT + บรีฟจาก Hermes + แนบรูปซองจริง | **ซองจริงถูกทุกใบ** ตู้จริง โทนตรงแบรนด์ ดีไซน์ยังดี |

**ตัวแปรชี้ขาดคือการแนบรูปซองจริง ไม่ใช่ตัวบรีฟ** — ไม่แนบเมื่อไหร่ โมเดลสร้างสินค้าขึ้นเองทุกครั้ง

## บทเรียนสำคัญ: "ตัวอักษรถูก 100%" ทำไม่ได้ด้วยการตรวจ

เจ้าของอยากได้ทั้งดีไซน์สวยและตัวอักษรถูก 100% จึงลองทำตัวตรวจปรู๊ฟด้วยโมเดลอ่านภาพ

วัดกับภาพที่**รู้คำตอบอยู่แล้ว** (ครอปขยายยืนยันด้วยตา):

```
"กันโหดบาก" (ม→บ) พาดหัวตัวใหญ่ที่สุด   ❌ พลาดทุกรอบ 4/4
"โดนจัดไปดัง" (ตั้ง→ดัง)                  ✅ จับได้ทุกรอบ
```

**จับได้ 1 จาก 2 และที่พลาดคือตัวใหญ่ที่สุดในภาพ** — ย้อนแย้งแต่มีเหตุผล:
โมเดลภาษาอ่านคำที่คุ้นเคยแล้ว "เติมให้ถูก" โดยอัตโนมัติ สั่งว่า
*"ถอดตัวอักษรตามที่เห็น ห้ามแก้คำให้ถูกเอง"* แล้วยังพลาดจุดเดิม

> ก่อนหน้านั้นยังเจอปัญหาตรงข้ามด้วย: ส่งภาพเต็มไปตรวจ **1 ใน 3 รอบเตือนผิด**
> (บอกว่า "คือคำตอบ" เขียนเป็น "คือตอบ" ทั้งที่ครอปดูแล้วถูก) แก้ด้วยการซอยภาพ + ขยาย 2-3 เท่าก่อนส่ง

## ทางเลือกที่วางบนโต๊ะ และสิ่งที่เลือก

- **A** เทมเพลตเราล้วน — ไทยถูก 100% แต่ดีไซน์ตายตัว (เจ้าของไม่เอา)
- **B** ChatGPT วาดภาพเปล่าไม่มีตัวหนังสือ แล้วเราวางข้อความทับ — ได้ 100% จริง แต่ต้องลงแรง 4-6 ชม. และคุมตำแหน่งยาก
- **C** ✅ **เลือกอันนี้** — ChatGPT ออกแบบเต็มใบ + ตัวตรวจเป็นตาที่สอง + คนซูมอ่านก่อนโพสต์

เหตุผลที่ C สมเหตุสมผล: จุดที่ตัวตรวจพลาดคือ**พาดหัวตัวใหญ่** ซึ่งเป็นจุดที่คนเห็นง่ายที่สุดพอดี
คนกับเครื่องจึงพลาดคนละแบบ ใช้ร่วมกันได้ผลกว่าเลือกอย่างเดียว

## สิ่งที่ทำในโค้ด

- **ปุ่ม "ตรวจตัวอักษร"** ในหน้า `/marketing` — ใช้กับภาพจากที่ไหนก็ได้ รวมถึงที่ทำใน ChatGPT
  ซอยภาพเป็น 3 แถบซ้อนกัน ขยาย 2 เท่าด้วย canvas ในเบราว์เซอร์ แล้วส่งตรวจทีละแถบ
  (ไม่ต้องลงไลบรารีภาพบนเซิร์ฟเวอร์)
- **ปุ่มดาวน์โหลด** ในหน้าดูรูปเต็มจอ — เดิมไม่มีเลย และ `<a download>` ใช้กับ URL ข้ามโดเมนไม่ได้
  ต้อง fetch เป็น blob ก่อน
- เทมเพลต v2 ปรับ opacity พื้นหลังเป็น 46% ให้ใช้ฉาก AI ได้เต็มที่

**ข้อความในผลตรวจตั้งใจไม่โฆษณาเกินจริง** — เขียนตรง ๆ ว่าจับได้ราวครึ่งเดียว
ถ้าเขียนว่า "ตรวจแล้วปลอดภัย" คนจะเลิกซูมอ่านเอง ซึ่งอันตรายกว่าไม่มีปุ่มนี้

## ปุ่ม "บรีฟทำรูป" (0da0c79)

เมื่อเลือกทาง C แล้ว งานที่เหลือของเจ้าของคือพิมพ์บรีฟให้ ChatGPT ทุกครั้ง — ปุ่มนี้ทำให้แทน
กดแล้วได้ข้อความพร้อมวาง และก๊อปลงคลิปบอร์ดให้เลย

สิ่งที่บรีฟล็อกไว้ ล้วนมาจากจุดที่ทดสอบแล้วพลาดซ้ำ ๆ:

| ล็อกอะไร | เพราะเคยพลาดแบบไหน |
|---|---|
| ห้ามวาดซองใหม่ ต้องใช้รูปที่แนบ | ไม่แนบรูปเมื่อไหร่ โมเดลสร้างสินค้าปลอมทุกครั้ง |
| ห้ามเอาโลโก้ DivisionX แปะบนซอง | เจอจริงในภาพที่เจ้าของลองทำ — เป็นเรื่องเครื่องหมายการค้า |
| จำนวนสาขา/ชุดขายดี ดึงจาก DB | ไม่ให้โมเดลเดาตัวเลข |
| ตัด SKU ที่ของหมดออกจากรูปที่แนบ | เชียร์ของที่หมดหน้าตู้ = เสียโอกาสเปล่า |

**ย้ายตัวเรียก Gemini ที่ทนล้มมาเป็น `lib/geminiText.js`** — route นี้ยิงครั้งเดียวแล้วเจอ 503
ทันทีตอนทดสอบครั้งแรก อาการเดียวกับที่เพิ่งแก้ในปุ่มเขียนคอนเทนต์เมื่อวาน
ทดสอบจริง: flash โดน 503 สองครั้งติด → สลับไป flash-lite สำเร็จ

> ⚠️ ค้าง: `generate/route.js` ยังใช้สำเนาของตัวเอง เพราะแปลง error เป็นข้อความไทยที่ผูกกับ
> ชื่อโมเดลที่ล้ม เขียนหมายเหตุไว้ในไฟล์แล้วว่าถ้าแก้ตรรกะลองซ้ำ ต้องแก้ทั้งสองที่
