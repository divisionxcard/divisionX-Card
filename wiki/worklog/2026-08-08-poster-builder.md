## 🔴 UX ที่ทำพลาด — เจ้าของเจอแต่ปุ่มที่ใช้ไม่ได้

เจ้าของเลือก *"ขอลองแบบไม่เปิด billing ก่อน"* แล้วรายงานกลับมาสองรอบว่า
ยังขึ้น **"สร้างภาพไม่ได้ — บัญชี Gemini ยังไม่ได้เปิด billing"**

สาเหตุคือผมเอง: บนการ์ดมีปุ่มภาพอยู่**ปุ่มเดียว** และเป็นปุ่มพื้นหลัง AI ที่ต้องเปิด billing
ส่วนตัวสร้างโปสเตอร์ที่**ทำงานฟรีอยู่แล้ว ยังไม่มีปุ่ม** ต้องรันจากคอมมานด์ไลน์
เจ้าของจึงไม่มีทางเข้าถึงทางที่ใช้ได้เลย ทั้งที่ผมบอกว่า "ลองได้ไม่จำกัด"

**บทเรียน: ฟีเจอร์ที่ผู้ใช้กดไม่ถึง = ยังไม่มีอยู่จริง**
บอกว่า "ค้างแค่ปุ่ม" ฟังดูเหมือนงานเล็ก แต่สำหรับคนใช้มันคือทั้งหมด

แก้แล้ว:
- ปุ่ม **"สร้างโปสเตอร์"** เป็นปุ่มหลัก (น้ำเงินเต็ม)
- ปุ่มพื้นหลัง AI ลดเป็นลิงก์จาง และเขียนในปุ่มเลยว่า **"ต้องเปิด billing"**
  → ไม่ให้กดแล้วไปเจอ error โดยไม่รู้ตัว
- แถบแจ้งเตือนงาน async + ปุ่มรีเฟรช เพราะงานใช้เวลา 1-2 นาที ถ้าเงียบคนจะกดซ้ำ

## 🔴 รันจริงบน CI ล้ม 2 ครั้งแรก — ปักหมุด Playwright ผิดรุ่น

```
E: Package 'libasound2' has no installation candidate
Failed to install browsers · exit code 100
```

Playwright **1.44.0** สั่งลง `libasound2` ซึ่ง Ubuntu 24.04 (noble) เปลี่ยนชื่อเป็น
`libasound2t64` แล้ว · ผมปักหมุดเลขนี้เพราะไปลอกจาก `deploy/scraper/requirements.txt`

**ที่พลาดจริง ๆ คือ `vms-sync.yml` ซึ่งใช้งานได้มาตลอด ลงแบบไม่ระบุเวอร์ชัน**
= ผมหยิบเลขที่ไม่มีใครใช้จริงบน CI มาใส่ ทั้งที่มีตัวอย่างที่ทำงานได้อยู่ข้าง ๆ

แก้เป็น `playwright>=1.49` — ใช้ขั้นต่ำแทนปักหมุด · ไม่แตะ `requirements.txt`
เพราะ `vms_scraper` ใช้อยู่บนเครื่อง ไม่ควรไปกระทบของที่ทำงานได้

**บทเรียน: ก่อนคัดลอกค่าตั้งค่าจากที่อื่น ดูก่อนว่าที่นั่นใช้จริงในบริบทเดียวกันไหม**
requirements.txt เป็นของเครื่อง dev (Windows) — คนละสภาพแวดล้อมกับ CI (ubuntu)
