## "เรียลไทม์" — ทำไมในหน้าไม่มีคำนี้

ข้อมูลใน `machine_stock` คือยอด ณ รอบซิงก์ล่าสุด (กลางคืน ~00:10 + ที่กดซิงก์ระหว่างวัน · วันนี้ซิงก์ 13:31–14:19)
ถ้าเขียน "เรียลไทม์" ลูกค้าเดินไปแล้วของหมดเพราะมีคนซื้อหลังรอบซิงก์ = เสียความเชื่อใจ
→ ทุกสาขาบอกเวลาอัปเดตของตัวเอง (วันนี้ / เมื่อวาน / 14 ต.ค. — คิดเวลาไทยเอง ไม่พึ่งโซนเวลาของเครื่อง)
· เกิน ~30 ชม. ขึ้นป้ายเบา ๆ "ข้อมูลอาจยังไม่อัปเดต" · ท้ายหน้าบอกว่าหลังเวลาอัปเดตอาจมีคนซื้อไปแล้ว ทักไลน์ถามได้
· ไม่แตะรอบซิงก์/สคริปต์ดึงข้อมูล — เรื่องความสดเจ้าของตัดสินใจแยก

ป้าย "วันนี้/เมื่อวาน" คิดใหม่ในเบราว์เซอร์หลังโหลด (หน้าเป็น ISR 60 วินาที อาจถูกแคชไว้ข้ามเที่ยงคืน)
ตอน hydrate ใช้เวลาเดียวกับที่เซิร์ฟเวอร์สร้างหน้า ข้อความจึงตรงกัน ไม่มีเตือน hydration

## กติกาข้อมูล (ตรวจกับข้อมูลจริง 16 ต.ค.)

ด่านกรองอยู่ที่ `deploy/lib/publicStock.js` (`buildStockView`) — ทุกอย่างที่มันคืนไปอยู่ใน HTML ที่ใครก็เปิดดูได้

- หน้าเป็น server component ดึงด้วย service key ผ่าน `fetchPublic` แบบ /branches /products ([[2026-08-26-rls-wide-open]]) — client component ไม่ import อะไรที่แตะคีย์
- `skus` select แค่ `sku_id,name,franchise,set_code,image_url,image_url_box` — **ไม่มีราคา/ต้นทุนเลย** (RLS กันระดับแถว ไม่ใช่คอลัมน์)
- `machine_stock` select แค่ `machine_id,sku_id,unit,remain,is_occupied,synced_at` — **ไม่ดึง `product_name`** (ชื่อดิบหลังบ้านตู้ เช่น "The Revals") และ `sell_price`
- `config` ของตู้หยิบเฉพาะคีย์ใน `branch` ที่ใช้ — `machine_id_vendor` / `portal_url` ไม่ออกไป · SKU อ้างด้วยเลขแถว ไม่ส่ง `sku_id`
- status แต่ละยี่ห้อตู้คนละแบบ (vms `active/inactive` · worldwide `Normal/Sold Out` · payif `normal/low/out`) → **ไม่ใช้ status ใช้ `remain` ตัวเดียว**
  กรองช่องแบบเดียวกับหน้าสต็อกหน้าตู้ของแอดมิน: มี `sku_id` และ `is_occupied` ไม่เป็น false
- SKU เดียวหลายช่อง → รวม `remain` ต่อ (ตู้, sku_id, unit) · `unit` ตรงกับคำว่า Box ในชื่อทุกแถว (ตรวจ 735 แถว)
- เวลาอัปเดตของสาขา = `max(synced_at)` ของตู้นั้น
- ไล่หน้า `machine_stock` ทีละ 1,000 (ตอนนี้ ~735 แถว เพิ่มตู้อีกไม่กี่ตู้ก็เกิน PostgREST ตัดเงียบ) · ตู้ที่ไม่ public (wwv02) ไม่แสดง
- ดึงไม่ได้ → ขึ้น "ตอนนี้ยังดึงข้อมูลสต็อกไม่ได้" แทนการบอกว่าทุกสาขาไม่มีของ

ตรวจ HTML ที่ได้จริง: ไม่มี `cost_price` `avg_cost` `sell_price` `product_name` `machine_id_vendor` `portal_url` JWT หรือเบอร์เก่า · ไม่มี `<img>` เลยก่อนกาง
(ที่เห็นคำว่า REVALS คือ `set_code` กับชื่อไฟล์รูปใน storage — ใช้ค้นหา/โหลดรูป ไม่ได้แสดง ชื่อที่แสดงคือ "Yu-Gi-Oh The Rivals")

## รูปย่อ — `/api/sku-thumb`

รูปต้นฉบับใน bucket `sku-images` เป็น WebP 1024×1024 ราว 110–165 KB · กางสาขาหนึ่ง ~40–50 รูป = **~5–6 MB** บนเน็ตมือถือในห้าง
`next/image` ช่วยไม่ได้: `next.config.js` ตั้ง `images.unoptimized: true` ทั้งระบบ (ตั้งแต่ เม.ย. แก้รูปไม่ขึ้นบนมือถือ)
และ Next 14.2 บังคับ unoptimized ทุกรูปเมื่อตั้งค่านี้ (`get-img-props.js`) — ไม่แตะค่านี้เพราะกระทบทุกหน้า

→ route ย่อรูปด้วย `sharp` (มีใน dependencies อยู่แล้ว ใช้กับโลโก้โปสเตอร์) เหลือ 96/144 px ~1.7–3.8 KB (เล็กลง ~50 เท่า)
· ดึงได้เฉพาะไฟล์ใน bucket สาธารณะ `sku-images` ของเราเอง ชื่อไฟล์ต้องผ่าน regex เดียวกับฝั่งหน้า (กันถูกใช้เป็นพร็อกซี)
· แคช CDN 1 วัน + ใช้ของเก่าระหว่างย่อใหม่อีก 7 วัน (ตัวอัปรูปในหน้าจัดการ SKU ตั้งชื่อไฟล์ใหม่ทุกครั้ง รูปใหม่ได้ URL ใหม่ทันที)
