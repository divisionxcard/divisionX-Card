# ให้ AI มีหลักการเขียนแบบมืออาชีพ — ชั้นที่ขาดไป

## บริบท (why)

เจ้าของบอกตรง ๆ ว่า *"เรายังไม่มีทักษะในการเขียนคอนเทนต์เลย"*
อยากให้ระบบมีหลักสากลที่กลั่นจากแหล่งต่าง ๆ เพื่อให้ AI เขียนแบบมืออาชีพขึ้น

รอบก่อน ([[2026-08-08-content-anti-repeat]]) เพิ่ม `content_formats` ไปแล้ว —
แต่นั่นตอบแค่ **"จะเขียนเรื่องอะไร"** ยังไม่ได้ตอบ **"เขียนยังไงให้ดี"**
นั่นคือชั้นที่ขาด

## ทำไมแยกไฟล์ ไม่รวมกับ content_voice.json

| | `content_voice.json` | `content_craft.json` |
|---|---|---|
| ตอบคำถาม | เราเป็นใคร พูดยังไง | เขียนยังไงให้คนหยุดอ่าน |
| เปลี่ยนเมื่อไหร่ | ตอนรีแบรนด์ / ปรับโทน | แทบไม่เปลี่ยน (หลักสากล) |

รวมไฟล์เดียวแล้วแก้โทนทีจะเสี่ยงพังหลักการเขียนไปด้วย —
สองอย่างนี้เปลี่ยนคนละจังหวะกัน แยกไว้ปลอดภัยกว่า

## สิ่งที่ใส่ใน content_craft.json

**hooks 6 แบบ** — พร้อมวิธีคิดและข้อควรระวังของแต่ละอัน ไม่ใช่แค่สำนวน
- ช่องว่างความอยากรู้ (Loewenstein 1994) · หักมุมจากที่คาด · ตัวเลขเจาะจง
- ถามตรง · เริ่มกลางเหตุการณ์ · สัญญาว่าจะได้อะไร (หลัก 4U ของ Masterson)

**frameworks 7 แบบ** — มี steps + `watch_out` + `good_for`
- AIDA (Lewis 1898) · PAS · BAB · FAB · listicle · hook-story-offer · APP

**เพิ่มอีก:** กฎ CTA (ขอทีละอย่าง · ห้ามลิงก์ในแคปชั่น) · ธรรมเนียมรายแพลตฟอร์ม ·
สิ่งที่ทำแล้วเอ็นเกจเมนต์ตก 7 ข้อ · self-check 4 ข้อให้โมเดลตรวจงานตัวเองก่อนส่ง

## การผูกเข้ากับรูปแบบโพสต์ — จุดที่ทำให้ทั้งเรื่องทำงาน

```
เกาะข่าว     → hook_story_offer + curiosity_gap
เล่าเรื่อง   → BAB              + in_media_res
ของใกล้หมด   → PAS              + specific_number
จัดอันดับ    → listicle         + specific_number
เทียบให้เห็น → FAB              + pattern_interrupt
...
```

**`craftBlock()` หยิบเฉพาะอันที่ตรงกับรูปแบบรอบนั้น ไม่ยัดทั้งไฟล์** เหตุผล 3 ข้อ:
1. โมเดลเล็ก (qwen / gemini-flash) จมข้อมูลจนลืมโจทย์จริง
2. เปลืองโควตา free tier
3. **ให้ framework มาทั้ง 8 แบบพร้อมกัน = ไม่ได้บังคับให้ใช้แบบไหนเลย** ซึ่งทำลายจุดประสงค์ทั้งหมด

ข้อ 3 สำคัญที่สุดและมองข้ามง่าย — "ให้ข้อมูลเยอะไว้ก่อน" ไม่ได้แปลว่าดีกว่า

## ผลทดสอบ A/B (ข่าวเดียวกัน · รูปแบบ "เล่าเรื่อง" เท่ากัน · Gemini)

**ก่อน** — เปิดด้วยบรรยายทั่วไป ปิดท้ายชวนซื้อ
> จังหวะที่ฉีกซองออกช้าๆ แล้วเห็นขอบการ์ดสะท้อนแสงวิ้งๆ...
> อยากรู้ว่าดวงจะพารุ่งไหม เช็กหน้าตู้สาขาใกล้บ้านแล้วมาจัดเลย!

**หลัง** — เปิดกลางเหตุการณ์ตาม `in_media_res` เดินตาม BAB ครบ ปิดท้ายขอคอมเมนต์ 1 อย่าง
> มือสั่นตั้งแต่ฉีกซอง ลุ้นขอบเงาวับมุมล่างว่าจะใช่การ์ดระดับ Top 10...
> ถ้าให้เลือกกด One Piece ได้ 1 ชุดตอนนี้ อยากกดชุดไหนมากที่สุด? คอมเมนต์บอกกันหน่อย!

ความต่างที่สำคัญคือ **CTA** — ของเดิมชวนซื้อ ของใหม่ขอคอมเมนต์
ซึ่งตรงกับเป้าหมายที่เจ้าของบอก (เอ็นเกจเมนต์) เพราะคอมเมนต์ดันการมองเห็นต่อ
กฎข้อนี้อยู่ใน `craft.cta.rules` — โมเดลทำตามเองโดยไม่ต้องสั่งเป็นราย ๆ

prompt โตจาก 2,768 → 4,710 ตัวอักษร (+70%) รับได้ทุก provider

## กันพัง
`loadCraft()` คืน `null` ถ้าไฟล์หาย/JSON พัง → ระบบยังเขียนได้ตามปกติ แค่ไม่มีหลักกำกับ
**ห้ามให้ฟีเจอร์ทั้งอันตายเพราะไฟล์ตั้งค่าไฟล์เดียว**

เขียนสคริปต์ตรวจ cross-reference ด้วย — `framework`/`hook` ที่ `content_formats`
ชี้ถึงต้องมีจริงใน craft ทั้ง 8 รายการ (ผ่านหมด) เพราะพิมพ์ผิดตัวเดียวจะเงียบ ๆ
ไม่มีหลักเข้า prompt โดยไม่มีใครรู้

## ✅ รัน migration 062 แล้ว — และเจอว่ากลไกยังไม่สมบูรณ์

หลังรัน ตรวจว่าคอลัมน์ `content_format` เขียน/อ่านได้จริง และ query ที่ `fetchRecent()`
ใช้ไม่ต้อง fallback อีกแล้ว — ผ่านหมด

**แต่พอวัดจริงพบว่ายังซ้ำติดกัน 1.9%** สาเหตุอยู่ใน `pickFormat()`:
```js
const pool = fresh.length ? fresh : all   // ← ปัญหาอยู่ตรงนี้
```
พอหน้าต่าง `recent` (8 ชิ้น) เต็มด้วยครบทั้ง 8 แบบพอดี `fresh` จะว่าง
แล้วรีเซ็ตกลับไปสุ่มจากทั้งหมด **เท่ากับกลไกจำใช้ได้แค่ 8 โพสต์แรกเท่านั้น**

แก้เป็น fallback ที่เลี่ยงแค่ 3 อันล่าสุด → เหลือ pool เสมอ ไม่มีทางหยิบซ้ำกับที่เพิ่งใช้

| | ซ้ำติดกัน | ซ้ำใน 3 โพสต์ล่าสุด |
|---|---|---|
| ก่อน migration | 12.3% | 31.3% |
| หลัง + แก้ fallback | **0.0%** | **0.0%** |

### ⚠️ บทเรียนเรื่องวิธีวัด
ตอนแรกรันจำลอง **ครั้งเดียว** แล้วเห็น 0% ทั้งสองฝั่ง เลยเกือบสรุปว่า
"migration ไม่ได้ช่วยอะไร" — ซึ่งผิด มันแค่บังเอิญสุ่มได้ดี
พอรัน 3,000 ครั้งถึงเห็นความต่างจริง (12.3% vs 1.9%)

**ตัวอย่างเดียวของกระบวนการที่มีการสุ่ม ไม่ใช่หลักฐาน** — และอีกจุดที่เกือบพลาดคือ
จำลองลำดับ `recent` กลับด้าน (ของจริง `order created_at desc` = ใหม่สุดอยู่หน้า)
ถ้าไม่แก้ให้ตรง ตัวเลขที่วัดได้จะไม่ตรงกับพฤติกรรมจริงเลย
