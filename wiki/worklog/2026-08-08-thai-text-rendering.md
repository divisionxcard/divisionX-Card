เครื่องมือที่ตั้งใจจะใช้คือ `next/og` (Satori) เพราะมากับ Next 14.2.3 อยู่แล้ว

## ผลทดสอบ — เคสวรรณยุกต์ซ้อนบนสระบน

| คำ | Satori (next/og) | Chromium จริง |
|---|---|---|
| ที่ | **ที** ❌ ไม้เอกหาย | ที่ ✅ |
| นี่ | **นี** ❌ ไม้เอกหาย | นี่ ✅ |
| เกี๊ยะ | ❌ สระอีหาย | เกี๊ยะ ✅ |
| สั่น | ❌ เพี้ยน | สั่น ✅ |
| ผู้ | ✅ | ✅ |
| ญี่ปุ่น | ✅ | ✅ |

**Satori ทิ้งวรรณยุกต์เมื่อต้องซ้อนบนสระบน** (ี + ่)
เพราะมันไม่ได้ทำ text shaping ของสคริปต์เชิงซ้อน แค่วางกลิฟตามลำดับ

คำที่พังคือ **"ที่"** ซึ่งเป็นคำที่พบบ่อยที่สุดคำหนึ่งในภาษาไทย —
แคปชั่นแทบทุกชิ้นมีคำนี้ ปล่อยไปคือโพสต์สะกดผิดทุกใบ

ส่วนที่ผ่าน (ผู้ ญี่ปุ่น) ผ่านเพราะสระอยู่**คนละชั้น** (บน+ล่าง) ไม่ต้องซ้อนกัน
→ ถ้าทดสอบด้วยคำง่าย ๆ อย่างเดียวจะเข้าใจผิดว่าใช้ได้

## สิ่งที่เกือบพลาด
ทดสอบรอบแรกใช้ประโยคยาวขนาดปกติ มองผ่าน ๆ เหมือนอ่านออก
ต้อง**ขยายเป็น 76px แล้วแยกทดสอบทีละคำ**ถึงเห็นว่าวรรณยุกต์หาย
→ บั๊กการเรนเดอร์ตัวอักษรต้องดูที่ขนาดใหญ่ ไม่ใช่ขนาดใช้งานจริง

## ข้อจำกัดทางเทคนิคที่เจอระหว่างทาง
- `next/og` บน **Node runtime พังทั้ง process** (connection closed, try/catch ไม่ติด)
  ต้องใช้ `runtime = "edge"` และโหลดฟอนต์ด้วย `fetch(new URL('./x.ttf', import.meta.url))`
- โฟลเดอร์ขึ้นต้นด้วย `_` ใน App Router เป็น private folder **ไม่สร้าง route** (404)

## ทางออก — ต้องใช้เบราว์เซอร์จริง
Chromium ทำ text shaping ถูกต้องทุกเคส และ **Playwright มีอยู่ในโปรเจกต์แล้ว**
(`deploy/scraper/requirements.txt` · `vms_scraper.py` ใช้อยู่ · workflow ติดตั้ง chromium แล้ว)
ทดสอบบนเครื่องแล้วเปิดได้ (Chromium 125)

เหลือตัดสินว่าจะรันที่ไหน:
| ที่รัน | ได้ | เสีย |
|---|---|---|
| GitHub Actions | ใช้ของที่มีอยู่แล้ว · ไม่มี dependency ใหม่ · ฟรี | รอ 1-2 นาที ไม่เหมาะกับการลองปรับหลายรอบ |
| Vercel + @sparticuz/chromium | กดแล้วเห็นทันที | เพิ่ม dependency ~50MB |
| เรนเดอร์ในเบราว์เซอร์ผู้ใช้เอง | ทันที · ฟรี · ไทยถูกแน่นอน | ต้องมีคนเปิดหน้าเว็บ · อัตโนมัติทีหลังไม่ได้ |
