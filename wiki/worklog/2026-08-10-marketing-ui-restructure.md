# แยกเมนู /marketing + เปลี่ยนเป็นโทนสว่าง

เจ้าของเอาหน้าจอ [app.heroaiengine.com](https://app.heroaiengine.com) มาให้ดู แล้วขอ
*"ปรับโครงสร้างเมนูให้คล้ายกัน เพื่อให้ง่ายต่อการใช้งาน"* · ระหว่างทางบอกเพิ่มว่า
*"ธีมหน้าเว็บอยากได้เป็นโทนสว่าง"*

## เมนูซ้าย — สิ่งที่ต้องแลก และวิธีไม่ให้เสียของ

เดิมทุกโซนกองอยู่หน้าเดียว เลื่อนยาวมาก กว่าจะถึงตัวเลขต้องผ่านการ์ดคอนเทนต์ทุกใบ
แยกเป็น 6 หน้าย่อยใต้เมนู 3 กลุ่ม (วันนี้ / ดูผล / ระบบ)

**แต่การแยกหน้าไม่ได้มีแต่ข้อดี** — ธีสิสเดิมของหน้านี้เขียนไว้ตั้งแต่ต้นว่า
*"เปิดมาต้องเห็นทันทีว่าวันนี้มีอะไรรอกด"* ซึ่งได้มาจากการที่ทุกอย่างอยู่หน้าเดียว
พอแยกหน้าแล้วของที่อยู่หน้าอื่นจะหายไปจากสายตา = แลกความสะดวกมาด้วยการลืมงาน

→ แก้ด้วยการ**ติดตัวเลขคงค้างไว้บนทุกเมนู** (ไอเดีย / รออนุมัติ / รอโพสต์ / งานที่ล้ม)
ยังกวาดตาครั้งเดียวรู้ว่ามีอะไรรอ แต่ไม่ต้องเลื่อนผ่านทั้งหมด

## 🔍 ถ่ายภาพมาดูจริง — เจอ 2 บั๊กที่อ่านโค้ดไม่มีทางเห็น

ทำหน้าตรวจชั่วคราวที่ไม่ต้องล็อกอิน (export `NavRail`/`Shell` ออกมา) แล้วยิง Playwright
ถ่ายภาพ + วัดค่าที่เบราว์เซอร์คำนวณจริง · ลบหน้านั้นทิ้งแล้ว

**1. ตัวหนังสือเมนูที่เลือกอยู่ อ่านไม่ออก**
เขียน `text-gray-900` ไว้ตามสัญชาตญาณว่า "เข้มสุด = เด่นสุด"
แต่ชั้นแปลงธีมมืดใน `globals.css` แปลงเฉพาะ `.text-gray-300` ถึง `.text-gray-800` เท่านั้น
`text-gray-900` ไม่อยู่ในลิสต์ → ค้างเป็น `#111827` จริงบนพื้นกรมท่า
**ผลคือเมนูที่เลือกอยู่กลับมืดกว่าเมนูที่ไม่ได้เลือก — กลับหัวกันเลย**

วัดสีจริงหลังแก้: ตัวที่เลือก `rgb(255,255,255)` บนพื้น `rgb(26,47,82)` · ตัวที่ไม่เลือก `rgb(122,139,168)`
(บทเรียน: คลาส Tailwind ที่ "ดูสมเหตุสมผล" อาจไม่อยู่ในชั้นแปลงธีม ต้องเช็กลิสต์ก่อน)

**2. เมนูไม่ติดหนึบจริง ทั้งที่ใส่ `sticky` ไว้แล้ว**
ใส่ `lg:items-start` ที่ flex container ตามความเคยชิน → คอลัมน์เมนูสูงเท่าเนื้อเมนูพอดี
วัดได้ **408px = 408px** · `position:sticky` เลยไม่มีที่ให้เลื่อน เลื่อนหน้าปุ๊บเมนูหลุดหายขึ้นไปเลย

เอา `items-start` ออก → คอลัมน์สูง 702px มีที่เลื่อน 294px · วัดซ้ำ ค้างที่ y=69 ทุกระยะเลื่อน

> ทั้งสองตัวคอมไพล์ผ่าน ไม่มี error ไม่มี warning — **ถ้าไม่ถ่ายภาพมาดูก็ส่งงานพังไปแล้ว**
> เป็นเหตุผลเดียวกับที่ทำ [[2026-08-10-facebook-auto-posting]] แล้วยิง API จริงด้วย token ปลอม

## โทนสว่าง — ทำไมไม่ถอด dx-theme ออกจาก layout หลักไปเลย

ธีมมืดมาจาก `<body className="dx-theme">` ใน `app/layout.jsx` = **ทุกหน้ามืดหมด**

ถอดออกตรงนั้นไม่ได้ เพราะมี **28 ไฟล์** ใช้คลาส `dx-*` (`.dx-card` `.dx-btn` `.dx-badge`)
ที่นิยามด้วย token สีเข้ม และ **ไม่ได้ gate ด้วย `body.dx-theme`** → ถอดแล้วจะได้
การ์ดมืดบนพื้นขาวปนกันทั้งแอป · สีเน้น `#00D4FF` / `#00FF88` ก็จางจนแทบมองไม่เห็นบนพื้นขาว

ถามเจ้าของก่อนลงมือ → ตกลงเอา **เฉพาะ /marketing** (ทั้งเว็บสว่างเป็นงานคนละขนาด
ต้องแก้ token 24 ตัว + ทำสีเน้นใหม่ทั้งชุด + ไล่ตรวจทุกหน้า)

**MarketingOS เขียนด้วยคลาสสว่างอยู่แล้วทั้งไฟล์** — ที่เห็นเป็นมืดเพราะชั้นแปลงธีมล้วน ๆ
แค่ถอด `dx-theme` ตอนอยู่หน้านี้ก็สว่างทันที ไม่ต้องแก้ component สักบรรทัด

แยกเป็น 2 ชิ้นเพราะแก้คนละจังหวะ:

| ชิ้น | ทำงานตอนไหน | แก้ปัญหาอะไร |
|---|---|---|
| `<script>` ใน `layout.jsx` | เบราว์เซอร์ parse ถึงบรรทัดนั้น = ก่อนเนื้อหาถูกวาด | จอวาบมืดแวบนึงก่อนเปลี่ยนเป็นสว่าง |
| `theme.jsx` (client) | เปลี่ยนหน้าฝั่ง client + ตอน unmount | React ไม่รัน script ที่ฝังแบบนั้น · และ**คืนคลาสตอนออกจากหน้า** ไม่งั้นกดกลับหน้าหลักแล้วขาวทั้งเว็บ |

## ผลตรวจ
- ไม่มี horizontal overflow ทั้ง 1440 / 1024 / 390px
- จอเล็ก = แถบเลื่อนแนวนอนด้านบน · จอใหญ่ = คอลัมน์ซ้ายติดหนึบ
- โทนสว่าง: พื้นหน้า `rgb(249,250,251)` · การ์ดขาว · ปุ่มหลัก `rgb(37,99,235)` ตัวหนังสือขาว
