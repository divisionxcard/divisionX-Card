# สินค้าใหม่ที่เพิ่มเมื่อวานยังไม่เข้าระบบ เพราะ commit ค้างอยู่ในเครื่อง

คำตอบตอนตรวจคือ **ยัง** — และเหตุผลไม่ได้อยู่ในโค้ด แต่อยู่ที่โค้ดไม่เคยออกจากเครื่อง

## ต้นตอ

```
git status -sb  →  ## main...origin/main [ahead 5]
```

commit ทั้ง 5 ตัวของเมื่อวาน (dc2c7b7 · 429f2a3 · 1813c39 · e2d50c0 · 68e3009) **ไม่เคยถูก push**

GitHub Actions checkout จาก `main` บน GitHub ไม่ใช่จากเครื่อง →
ตัวซิงค์ที่รันจริงทุกคืนยังเป็นโค้ดเวอร์ชันก่อนแก้ →
ทุกครั้งที่ซิงค์ มันเขียน `sku_id = null` ทับค่าที่เติมไว้ด้วยมือ

**การซ่อมข้อมูลใน DB จึงมีอายุแค่ถึงการซิงค์ครั้งถัดไป ถ้าโค้ดยังไม่ขึ้น GitHub**

> บทเรียน: งานที่แก้ทั้งโค้ดและข้อมูล ต้องเช็ก `git status -sb` ว่า push แล้วก่อนปิดงาน
> ไม่งั้นจะเห็นภาพลวงว่า "แก้เสร็จแล้ว" เพราะตรวจ DB ทันทีหลังเติมมือแล้วมันถูก

พอเทียบ mapper ทั้ง 6 ไฟล์กับชื่อจริง 145 ชื่อ เจอว่า **ต่อให้ push แล้วก็ยังพัง** —

commit 1813c39 เมื่อวานแตะ `vms_sales_api.py` จริง แต่แก้แค่ `PACKS_PER_BOX`

ทำไมถึงร้ายแรงกว่าฝั่งสต็อก — `vms_sales_api` หา `sku_id` สองทาง:

```
1. slot_lookup จาก machine_stock.sku_id     ← ถูกซิงค์เก่าล้างเป็น null

   ไม่ได้ทั้งสองทาง → continue                ← ทิ้งรายการขายทั้งแถว
```
