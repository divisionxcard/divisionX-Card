# ตรวจคลิปจริงแบบครีเอเตอร์ + ชั้นเสียงใหม่ (23 ต.ค.)

## เจ้าของสั่ง

> "ระบบการสร้างวิดีโอคอนเทนต์ ดูแล้วยังไม่ค่อยสมบูรณ์ … ในฐานะที่คุณเป็นวิดีโอครีเอเตอร์มืออาชีพ ช่วยปรับปรุงจุดบอด"

## วิธีตรวจ — ดูของจริง ไม่เดาจากโค้ด

ดึงคลิปที่ทำเสร็จทั้ง 5 คลิปจาก `video_jobs` (ทั้งหมดเป็น HyperFrames 16–17 ต.ค.) · ดึงเฟรมทุก 1 วิ + ถี่ 4 เฟรม/วิ ช่วง 3 วิแรก ·
วัดความดัง (ebur128) และช่วงเงียบ (silencedetect −35 dB) · ให้ผู้ช่วยทำแผนที่ระบบทั้งเส้น

## ที่แก้แล้ว

1. **`agents/video/sound.py` ชั้นเสียงหลังเรนเดอร์** (เรียกจาก `hf_render.build_video`)
   - **ย่อช่วงเงียบ** > 0.45 วิ เหลือ 0.38 วิ ก่อน whisper จับเวลา — ⚠️ `silenceremove` ของ ffmpeg ตัดได้แค่ท้ายไฟล์
     (ลอง −30…−40 dB ทั้ง rms/peak ช่วงกลางไม่ถูกแตะ) → เขียนเองด้วย silencedetect + atrim/concat · แคชเวลาคำผูก `TIGHT_VERSION`
   - **เอฟเฟกต์เสียงสังเคราะห์** (ตูม ป๊อป ติ๊ก ไต่ระดับ ประกาย ลมวูบ) จากสูตรคณิตศาสตร์ = ไม่มีไฟล์ของใคร ไม่มี Content ID ·
     ลงที่เวลาเดียวกับภาพเฉลย (`at`/`rv`/`cd` ของแต่ละฉาก) + เสียงแรกตรงแสงวาบเปิดคลิป
   - **เพลง** ผ่าน `music.pick_for` (เฉพาะเพลงที่กรอกใบอนุญาต) · หลบเสียงพูดด้วย sidechaincompress — คลังว่าง = ไม่มีเพลง
   - **ความดัง** loudnorm 2 รอบ → −14 LUFS / −1.5 dBTP ทุกคลิป · ภาพ copy · ล้ม = ใช้ไฟล์ที่เรนเดอร์ได้ต่อ
2. **คำเปิดคลิปจัดอันดับ** (`hf_formats.COPY.rank.hook`) สั้นลง (ประเมินจากจำนวนคำว่า ~2.5 วิ · ยังไม่ได้ยิงเสียงจริง) — ที่ไหน/เมื่อไหร่อยู่บนจอแล้ว
3. **`publishContent.blockReason`** กันชิ้นที่แนบวิดีโอ (ไม่ส่งไป `/photos` แล้ว) พร้อมเหตุผล
4. `hf_render` แปลง `--out` เป็น path เต็ม (เจอตอนทดสอบ: path สัมพัทธ์ไปลงในโฟลเดอร์งานของ npx แล้วระบบว่าเรนเดอร์ล้ม)
