# Hermes พูดกลับได้แล้ว — และคอขวดจริงไม่ใช่ที่ Hermes คิด

เจ้าของส่งแชทที่คุยกับ Hermes มาให้ดู พร้อมถาม 2 ข้อ:
1. ช่วยวิเคราะห์ระบบให้ดีขึ้น
2. *"hermes สามารถส่งไอเดียหรือแนวทางมาให้คุณโดยตรงได้เลยไหม เพื่อผมจะได้ไม่ต้อง copy"*

ในแชทนั้น Hermes ตอบเองว่า **"ไม่มี tool ให้ผมเพิ่มไอเดียเข้าคิวได้ครับ"**
— นั่นคือจุดที่ต้องแก้ และมันตอบคำถามทั้งสองข้อพร้อมกัน

## ตรวจตัวเลขที่ Hermes อ้างก่อน

| Hermes บอก | ของจริง |
|---|---|
| คิวไอเดีย 83 ชิ้น | **107** (83 คือเฉพาะ `status='new'`) |
| คอนเทนต์ 24 ชิ้น | **34** |
| โพสต์ไป 1 ชิ้น | **2** |
| news_hook มีแค่ 1 ใน 83 | `source='news'` **19 ชิ้น** |
| "เรามี 13 ตู้" | 13 แถว แต่ **active 12** (wwv02 ปิดแล้ว) |
| "เจาะสาขา" 29 ชิ้น | 30 ✅ ใกล้เคียง |

Hermes อ่านจาก view ที่ถูกกรอง/จำกัดจำนวนแล้วรายงานเป็นยอดรวม
→ **ทิศทางถูก แต่เลขเชื่อไม่ได้** ต้องตรวจก่อนเอาไปตัดสินใจเสมอ

## ข้อสรุปที่ผมไม่เห็นด้วย — และทำไม

Hermes เสนอให้ *"เขียนไอเดียใหม่เข้าไปในคิว"* แต่พอวัดท่อส่งงานทั้งเส้น:

```
ไอเดีย 107  →  เขียนเป็นคอนเทนต์ 34 (32%)  →  โพสต์จริง 2 (1.9%)
                                    ├─ pending  20  ← ค้างมากลาง 13 วัน · เก่าสุด 22 วัน
                                    ├─ rejected 11
                                    └─ draft     1
```

**คอขวดอยู่ที่การอนุมัติ ไม่ใช่จำนวนไอเดีย** — มีไอเดียรออยู่ 83 ชิ้นที่ยังไม่มีใครหยิบ
เติมต้นทางเพิ่มทำให้กองสูงขึ้นเฉย ๆ ไม่ได้ทำให้โพสต์ออกเร็วขึ้นแม้แต่ชิ้นเดียว

## สิ่งที่ Hermes มองไม่เห็น — คุณภาพแหล่งกลับด้านกับปริมาณ

| แหล่ง | สร้างไอเดีย | ถูกใช้จริง | อัตรารอด |
|---|---|---|---|
| `internal` (สัญญาณยอดขาย/สต็อก) | **79** | 8 | **10%** |
| `news` | 19 | 8 | 42% |
| `tiktok` | 9 | 7 | **78%** |

**แหล่งที่ผลิตมากที่สุด ผลิตของที่ใช้ได้น้อยที่สุด** — `internal` คือต้นตอของมุมซ้ำ
"เจาะสาขา" 30 ชิ้นที่ Hermes ทักถูกแล้ว มันวนสร้างมุมเดิมต่อสาขาต่อสัปดาห์

5 มุมแรกกินไป **58%** ของคิวทั้งหมด

## สิ่งที่ Hermes ถูก และมีค่าจริง

- มุมที่เรายังไม่มีเลย: **คอมมูนิตี้/จัดแข่ง** (Nut Card ทำ) · **เก็บรักษา/จัดแฟ้ม** (ไม่มีใครทำในไทย)
- ข้อมูลคู่แข่งเป็นของที่ระบบเราหาเองไม่ได้ — TDPK โพสต์แล้ว engagement แทบเป็นศูนย์
  (26 reactions · **0 คอมเมนต์**) เป็นหลักฐานว่า "แค่โพสต์รูปตู้" ไม่พอ

## แก้: เปิดให้ Hermes เขียนกลับได้ 2 ทาง

แยกตามประเภทของสิ่งที่ส่ง เพราะปลายทางต่างกัน

### 1. `add_marketing_idea` — ไอเดียคอนเทนต์

เข้าคิวเดียวกับที่ระบบเก็บอัตโนมัติ ตัวเขียนคอนเทนต์หยิบไปใช้ได้ทันที
**ไม่ต้องผ่าน Claude Code เลย** ซึ่งดีกว่าที่เจ้าของขอ

ใส่กันพลาดไว้ 3 ชั้น:
- `source` ใช้ `'manual'` ไม่ใช่ `'hermes'` — CHECK constraint ของ migration 060
  อนุญาตแค่ `news/youtube/tiktok/internal/comment/manual` ใช้ค่าที่มีอยู่แล้ว
  จะได้ไม่ต้องทำ migration ให้เจ้าของไปรันเอง
- กันซ้ำด้วย `external_key`
- **เตือนกลับเมื่อคิวยาว** — `new` เกิน 60 จะคืนข้อความบอกให้ไปเคลียร์คอนเทนต์
  ที่ค้างอนุมัติก่อน เพราะนั่นคือคอขวดจริง

### 2. `note_for_dev` — ข้อเสนอเชิงระบบ

ต่อท้าย `wiki/hermes-inbox.md` พร้อมวันเวลาและ checkbox
`CLAUDE.md` สั่งให้อ่านไฟล์นี้ทุกครั้งที่เริ่ม session

> ⚠️ **ส่งแบบ push ไม่ได้จริง ๆ** — Claude Code ไม่ได้รันค้าง มีตัวตนเฉพาะตอนเจ้าของเปิดใช้
> จึงต้องเป็นกล่องที่ทิ้งไว้แล้วอ่านตอนเปิดครั้งถัดไป ไม่ใช่ช่องทางเรียลไทม์
> tool บอกข้อจำกัดนี้กลับไปใน response ด้วย เพื่อไม่ให้ Hermes สัญญากับเจ้าของเกินจริง

ใช้ไฟล์ไม่ใช่ตาราง: ไม่ต้อง migration · เห็นใน git · เจ้าของเปิดอ่านเองได้

## Hermes ได้ tool ใหม่ทันทีโดยไม่ต้องตั้งค่าอะไร

`hermes/config.yaml` ตั้งไว้แบบ `tools: exclude: [sync_data]` = ได้ทุก tool ยกเว้นตัวนั้น
→ tool ใหม่ทั้งสองเข้าให้ Hermes เองตอนเชื่อมต่อรอบหน้า

## ยังค้าง

- **คอขวดจริงยังไม่ได้แก้** — 20 คอนเทนต์ค้างอนุมัติ กลาง 13 วัน
  ต้องรู้ก่อนว่าติดที่ขั้นตอน UI หรือเจ้าของไม่มีเวลาไล่ดู
- `internal` ผลิตไอเดียใช้ได้แค่ 10% ควรจำกัดมุมซ้ำต่อรอบ
  (Hermes ฝากข้อเสนอนี้ไว้ในกล่องแล้วตอนทดสอบ)
- มุมคอมมูนิตี้/เก็บรักษา ยังไม่มีในคิว — รอ Hermes เสนอเองผ่าน tool ใหม่
