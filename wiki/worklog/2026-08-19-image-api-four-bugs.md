# ภาพจาก API ไม่ดีเพราะเรียกผิด ไม่ใช่เพราะ API ทำไม่ได้

เจ้าของถามว่า "ต่อ API กับ ChatGPT เพื่อทำภาพให้ได้ตามต้องการได้ไหม"
คำตอบคือ **ต่อไว้นานแล้ว แต่ไม่เคยเรียกให้ถูกเลยสักครั้ง**

## ข้อสรุปเดิมเชื่อไม่ได้ เพราะวัดจากโค้ดที่มีบั๊ก 4 จุดพร้อมกัน

[[2026-08-18-poster-style-gap]] สรุปว่า "แนบซองจริงแล้วโมเดลยังวาดซองใหม่อยู่ดี
ทั้งที่ตั้ง input_fidelity: high" → เจ้าของจึงเลิกใช้ API แล้วไปสั่ง ChatGPT ด้วยมือ

พอไล่โค้ดจริงพบว่าการทดสอบรอบนั้นวัดอะไรไม่ได้เลย:

### บั๊ก 1 — ทุกภาพมาจาก gpt-image-1.5 ไม่เคยเป็น gpt-image-2 สักใบ

`route.js` ส่ง `input_fidelity` ไปทุกโมเดลโดยไม่เช็ก แต่เอกสาร OpenAI ระบุว่า
**gpt-image-2 ห้ามส่งพารามิเตอร์นี้** (มันทำ high fidelity ให้เองอยู่แล้ว)

ยิงจริงเพื่อยืนยัน — request ที่ถูกปฏิเสธไม่คิดเงิน:

```
gpt-image-2   + input_fidelity → HTTP 400
  "The model 'gpt-image-2' does not support the 'input_fidelity' parameter."
gpt-image-1.5 + input_fidelity → HTTP 200 สร้างภาพได้
```

ตัวดัก fallback เขียนไว้ว่า `/model|not found|does not exist|unsupported/i && status===400`
ข้อความ error ข้างบน**มีคำว่า "model"** → เข้าเงื่อนไข → `continue` → เลื่อนไป gpt-image-1.5 **เงียบ ๆ**

เงื่อนไขนี้กว้างเกินไปโดยไม่มีใครรู้ เพราะคำว่า model โผล่ในข้อความ error แทบทุกแบบ

### บั๊ก 2 — คำสั่ง "ห้ามวาดซองใหม่" เป็น dead config

`with_reference` ใน `image_style.json` เขียนไว้อย่างดีว่า *"Use the provided product photo
EXACTLY as-is — do not redraw..."* แต่ **ไม่มีโค้ดบรรทัดไหนอ่านคีย์นี้เลย**

grep ทั้ง repo เจอแค่ที่นิยามในไฟล์ JSON ที่เดียว

นี่คือประโยคเดียวกับที่บรีฟฝั่ง ChatGPT ทำมือมี — และนั่นคือรอบที่ได้ซองจริง

### บั๊ก 3 — พรอมต์สั่งขัดกันเองทุกครั้งในโหมด full

```
บรรทัด 96:  thai_rule       → "วาดข้อความไทยนี้ให้ตรงทุกตัวอักษร"
บรรทัด 105: negative        → "no text, no letters, no words, no typography"
```

`negative` ถูกต่อท้าย**ทุกโหมด** ทั้งที่ข้อแรกในลิสต์เป็นข้อห้ามที่ใช้ได้เฉพาะโหมด `art`
โมเดลจึงได้คำสั่งสองอย่างที่ทำพร้อมกันไม่ได้ในพรอมต์เดียว

### บั๊ก 4 — ชื่อไฟล์ไม่ตรงชนิด

รูปซองใน Supabase มีทั้ง WebP และ JPEG แต่โค้ดตั้งชื่อ `ref0.jpg` ให้ทุกอย่างที่ไม่ใช่ PNG

## ผลหลังแก้ — ยิงจริง gpt-image-2

`n=2` จากคำสั่งเดียว (ใบเดียวแยก "ใช้ได้" กับ "ฟลุก" ไม่ออก) · 1024x1536 · quality high
แนบซองจริง FB-03 · ไม่ส่ง input_fidelity · เปิด with_reference · ตัด negative ที่ขัดกัน

**ต้นทุนจริงที่วัดได้ $0.171/ใบ** (อ่านจาก `usage`: input 2,070 tokens · output 10,976 tokens)
— ตัวเลขนี้ไม่มีในเอกสาร OpenAI ต้องยิงจริงถึงจะรู้

| เกณฑ์ (ตั้งไว้ก่อนดูภาพ) | ผล |
|---|---|
| ตัวอักษรบนซองถูกครบ | ✅ FB03 · 対象年齢9才以上 · DRAGON BALL SUPER CARD GAME · FUSION WORLD · 怒りの咆哮 · 全143種 · ブースターパック · BANDAI · 日本語版 · MADE IN JAPAN ถูกหมด ทั้ง 2 ใบ |
| สีและเลย์เอาต์ซอง | ✅ ตรงกับของจริง |
| ตัวอักษรไทย | ✅ "กดเองได้ 24 ชั่วโมง" / "ในห้างใกล้บ้าน ไม่ต้องต่อคิว" ถูกทุกตัว ทั้ง 2 ใบ รวมวรรณยุกต์ที่ซ้อนบนสระบน (ชั่ ห้ ใกล้ บ้ ไม่ ต้ ต่) |

เทียบกับรอบก่อนที่ได้ **"BAP DAI" · ซองเขียวกลายเป็นน้ำเงิน · ซองที่โมเดลแต่งขึ้นเอง**

## ⚠️ สิ่งที่ยังพูดไม่ได้

**ซองเป็นการวาดซ้ำที่เหมือนมาก ไม่ใช่การแปะรูปจริง** — ตัวหนังสือถูกครบ สีตรง เลย์เอาต์ตรง
แต่ลายอาร์ตโกคูไม่ใช่พิกเซลเดียวกับต้นฉบับ ถ้าวันไหนต้องการความเป๊ะระดับพิกเซล
ทางเดียวที่รับประกันได้คือให้เทมเพลตแปะรูปจริง (`poster_render.py` ทำได้อยู่แล้ว)

**"ไทยถูก 100%" ยังรับประกันไม่ได้** — 2 ใบผ่านไม่ใช่หลักฐานว่าผ่านตลอด
เอกสาร OpenAI ยังลิสต์ Text Rendering เป็น Limitation และไม่เคยเอ่ยถึงภาษาไทยเลยสักคำ
คำว่า 100% จะจริงเชิงโครงสร้างก็ต่อเมื่อ Chromium เป็นคนวางตัวอักษร ไม่ใช่โมเดล

## บทเรียน

**อย่าสรุปความสามารถของเครื่องมือจากผลลัพธ์ ถ้ายังไม่ได้ยืนยันว่าเรียกมันถูก**
ทั้งทีมเชื่อมาหนึ่งวันเต็มว่า "gpt-image ทำไม่ได้" ทั้งที่ไม่เคยเรียก gpt-image-2 ติดเลยสักครั้ง
ต้นเหตุคือ fallback ที่กลืน error แล้วเดินต่อเงียบ ๆ — ทำให้ระบบ "ทำงานได้" แต่ทำงานผิดตัว

→ แก้แล้วให้คืน `attempts` ออกมาทุกครั้ง จะได้เห็นว่าภาพมาจากโมเดลไหนจริง ๆ
และคืน `usage` ด้วยเพื่อรู้ต้นทุนจริงต่อใบ
