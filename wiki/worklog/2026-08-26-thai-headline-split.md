# ตัดพาดหัวไทยไม่ได้ — ต้นเหตุจริงของโปสเตอร์ที่ "ล้าสมัย"

เจ้าของบอกมาหลายรอบว่าโปสเตอร์ **"โครงสร้างยังเป็นรูปแบบเดิม ๆ ล้าสมัยมาก"**
แล้ว workflow ออกแบบเทมเพลตใหม่ 3 แบบก็ยังแก้ไม่ได้ — เพราะต้นเหตุไม่ได้อยู่ที่เทมเพลต

## วัดของจริงก่อน

คอนเทนต์จริง 34 ชิ้นใน `marketing_content`:

| | |
|---|---|
| พาดหัวยาวเกิน 42 ตัว | 31 ชิ้น |
| `split_caption()` ตัดได้ | 14 |
| **ตัดไม่ได้** | **17** |

พาดหัวไทย 100+ ตัวที่ตัดไม่ได้ ในคอลัมน์กว้าง ~500px = **6 บรรทัด**
ไม่มีเทมเพลตไหนช่วยได้ ต่อให้ออกแบบสวยแค่ไหน

เดิมตัดได้แค่ที่ `!` `?` แต่พาดหัวยาวที่สุด 3 อันในฐานข้อมูล**ไม่มีเครื่องหมายพวกนี้เลย**

## กุญแจที่โค้ดเดิมมองข้าม

คอมเมนต์เดิมเขียนถูกครึ่งเดียว:

> ⚠️ ห้ามตัดตามจำนวนตัวอักษรแล้วหาช่องว่างที่ใกล้ที่สุด — ภาษาไทยไม่เว้นวรรค
> ระหว่างคำ ช่องว่างที่เจอมักเป็นช่องว่าง "ในชื่อภาษาอังกฤษ" ผลคือตัดกลาง
> "One Piece" เป็น "...การ์ด One" / "Piece ไม่ใช่..." (เกิดจริงกับคอนเทนต์ #16)

ข้อสังเกตถูก แต่ข้อสรุป "จึงห้ามตัดที่ช่องว่างเลย" กว้างเกินไป

**ภาษาไทยไม่เว้นวรรคระหว่างคำ แต่เว้นวรรคที่ขอบเขตวลี** → ช่องว่างที่มีอักษรไทย
ประกบสองข้างคือขอบเขตวลีจริง ตัดได้ปลอดภัย 100% ส่วน `One Piece` มีละตินสองข้าง
จึงไม่เข้าเงื่อนไข ไม่โดนแตะตั้งแต่แรก

## จุดตัด 4 ระดับ

| ระดับ | จุดตัด | ตัวอย่าง |
|---|---|---|
| 1 | จบประโยค `! ? 。` | เดิมมีอยู่แล้ว |
| 2 | เครื่องหมายคั่น `— – · : …` | `...กระแสกำลังขึ้น **—** โชว์ของในซอง` |
| 3 | ช่องว่างไทย-ไทย | `นิ้วโป้งค่อยๆ **⎵** ดันการ์ดใบหลังสุดออกมา` |
| 4 | คำเชื่อมขึ้นต้นอนุประโยค | `...รอบเดียว **แต่**ช่อง FB-09 ยุบไว...` |

แล้วเลือกจุดที่ได้พาดหัวใกล้ 40 ตัวและไม่เกิน 56

## ⚠️ กับดักที่เจอตอนทดสอบ — เกือบทำพลาดแบบเดียวกับที่โค้ดเดิมกลัว

รอบแรกไม่ได้บังคับว่าคำเชื่อมต้องมีช่องว่างนำหน้า ผลคือ:

```
#36  แฟ้มในมือสั่นตั้ง / แต่ดึงซองสุดท้ายออกจากช่องตู้     ← 'ตั้งแต่' เป็นคำเดียว!
#26  ...นาทีนี้บอก / เลยว่าต่างกันชัดเจน                  ← 'บอกเลยว่า' เป็นวลีเดียว
```

**ภาษาไทยไม่มีขอบเขตคำ `แต่` จึงโผล่กลาง `ตั้งแต่` ได้** — คือการตัดกลางคำแบบเดียวกับ
ที่คอมเมนต์เดิมเตือนไว้ ต่างกันแค่เกิดกับคำไทยแทนชื่ออังกฤษ

แก้สองข้อ:
1. คำเชื่อมต้องมี**ช่องว่างนำหน้า** (แปลว่ามันเริ่มวลีใหม่จริง)
2. ถอด `เลยว่า` ออกจากรายการ — มันเป็น**หาง**ของวลี ไม่ใช่หัว

> 💡 ถ้าทดสอบแค่กับพาดหัวที่นึกเอง จะไม่มีวันเจอสองเคสนี้
> ต้องทดสอบกับ **ข้อความจริงทุกชิ้นที่มี** ถึงจะเจอ

# เฝ้า RLS อัตโนมัติ

RLS ไม่เคยถูกเปิดตั้งแต่สร้างโปรเจกต์ และไม่มีใครรู้จน Supabase ส่งอีเมลเตือน
**Supabase สร้างตารางใหม่มาโดยไม่เปิด RLS เป็นค่าเริ่มต้น** → ตารางที่เพิ่มทีหลัง
จะเปิดโล่งทันทีโดยไม่มีคำเตือน พึ่งความจำไม่ได้

เพิ่ม `.github/workflows/rls-guard.yml`:
- ทุกวันจันทร์ 09:00 น. ไทย (ต้นสัปดาห์ มีเวลาแก้)
- ทุกครั้งที่ push แตะ `backend/database/migrations/**`
- รั่วเมื่อไหร่ → Telegram หาเจ้าของ + workflow แดง

## ⚠️ เกือบสร้างตัวเตือนหลอกอีกตัว

ตอนแรกใช้ `continue-on-error` + เช็ก `outcome == 'failure'` ซึ่งจะทำให้กรณี
**"ยังไม่ได้ตั้ง secret"** ยิงแจ้งเตือนว่าฐานข้อมูลรั่ว ทั้งที่แค่รันไม่ได้

→ แยกรหัสออกเป็น **3 สถานะ**: `0` ปลอดภัย · `1` รั่วจริง · `2` ขาด config
แจ้ง Telegram เฉพาะรหัส 1 · รหัส 2 แค่เตือนใน log ว่าต้องตั้ง secret
ทดสอบครบทั้ง 3 กรณีแล้ว

> 💡 นี่เป็นเรื่องเดิมที่กลับมาเป็นครั้งที่ 4 ของวัน — **เตือนหลอกทำให้คนเลิกเชื่อ
> การแจ้งเตือนทั้งระบบ** เครื่องมือตรวจต้องแยก "ปลอดภัย" กับ "ตรวจไม่ได้" เสมอ

# ภาคต่อ — ย่อฟอนต์ให้พอดี 2 บรรทัด + เก็บกวาดเทมเพลต

เจ้าของกดสร้างโปสเตอร์ใหม่แล้วส่งผลมาให้ดู 3 รอบ แต่ละรอบเจอปัญหาต่างกัน

## รอบ 1 — ตัดได้แล้วแต่ยังไม่ถึงเป้า

พาดหัวลงจาก 6 เหลือ 3 บรรทัด แต่ `art_direction.json` ข้อ 7 กำหนดไว้ที่ **2 บรรทัด**

ต้นเหตุ: `head_size()` เดาขนาดฟอนต์จาก `len(text)` เป็นช่วง ๆ (≤28 ตัว → 82px)
แต่ **ความกว้างตัวอักษรไทยเดาจากจำนวนตัวไม่ได้** สระบน/ล่าง/วรรณยุกต์กว้าง 0
วัดจริง: พาดหัว 27 ตัวที่ฟอนต์ 82px ในคอลัมน์ 520px ได้ ~10 ตัว/บรรทัด = 3 บรรทัด

**Chromium รู้ความกว้างจริงอยู่แล้ว — ถามมันตรง ๆ แม่นกว่าสูตรใด ๆ**
เพิ่ม `fit_headline()` หลัง `set_content`: วัดจำนวนบรรทัดจาก
`boundingRect.height / lineHeight` แล้วย่อทีละ 3px จนได้ ≤2 บรรทัด
เพดานล่าง 52px (ต่ำกว่านี้หลุดเกณฑ์แบรนด์ที่ว่าพาดหัวต้อง ≥5% ของ 1080 = 54px)

⚠️ ต้องเรียก**หลัง**รอฟอนต์โหลด ไม่งั้นวัดจากฟอนต์ fallback ที่ความกว้างคนละเรื่อง

## รอบ 2 — "ยังคงมีเลข 12 สาขา อยู่ซึ่งยังคงเป็นรูปแบบเดิม ๆ"

ไล่ดูแล้วเจอ 3 จุด **ทั้งหมดอยู่ในเทมเพลตหลัก ไม่ใช่ไฟล์แนวคิด** จึงโผล่ทุกใบ
ตำแหน่งเดิมข้อความเดิม ไม่ว่าจะสุ่มได้แนวคิดไหน — นี่คือคำตอบว่าทำไมรู้สึกว่าเหมือนเดิม

**1. เหรียญ "N สาขา" ขัดกฎของตัวเอง**
`art_direction.json` ข้อ 27 เขียนไว้ว่า *"Never place a branch count in the artwork"*
แต่เทมเพลตมี `<div class="medal">{{BRANCHES}} สาขา</div>` มาตลอด → เอาออก

**2. แถบมนเปล่าใต้บรรทัดรอง**
`.body` มี padding + background + ขอบ พอ `{{BODY}}` ว่างเลยเหลือแถบเปล่าลอยอยู่
**เป็นผลข้างเคียงจากการแก้ของตัวเองเมื่อวาน** — ตอนนี้เกือบทุกใบมีบรรทัดรอง
แล้ว `build_html` ใส่ body เฉพาะตอน*ไม่มี*บรรทัดรอง → body ว่างแทบทุกใบ
เพิ่ม `.body:empty { display: none }`

**3. โลโก้ถูกตัดครึ่ง เห็นแค่ตัว D** (เฉพาะแนวคิด `viral`)
`viral.css` ค้างกฎ `.crop img { width:131.5px; left:-25.9px; top:-24.4px }`
ซึ่งเขียนไว้ตอนใช้ `logo.png` ที่มีคำว่า DIVISION X CARD อยู่ใต้ตรา DC จึงต้องซูมแล้วเลื่อน
แต่เทมเพลตหลักเปลี่ยนไป `logo-mark-white.png` (ตรา DC ล้วน) และเอากฎครอปของตัวเองออกแล้ว
**ไฟล์แนวคิดตกสำรวจ** → รูปกว้าง 131.5px ในกล่อง 74px ที่ `overflow:hidden` = โดนตัด

> 💡 รูปแบบเดิมอีกครั้ง — แก้ที่ส่วนกลางแล้วลืมไฟล์ที่ทับค่าไว้
> เหมือนเคส `vms_scraper.py` ตกรุ่นเมื่อวาน ต่างกันแค่เป็น CSS ไม่ใช่ Python

## รอบ 3 — "สร้างใหม่อีกคอนเทนต์นึงได้ออกมาเหมือนกันเลย"

**ไม่ใช่บั๊ก** โปสเตอร์สร้างผ่าน GitHub Actions ที่ดึงโค้ดจาก `main` ณ ตอนกด
ไล่เวลาแล้วตรงเป๊ะ (git log เป็นเวลาไทย · GitHub API เป็น UTC ต้องแปลงก่อนเทียบ):

```
14:31 UTC  กดสร้าง #40  → commit 9bba37c  (มีแค่ตัวตัดพาดหัว)
14:37 UTC  push ตัวย่อฟอนต์
14:45 UTC  กดสร้าง #33  → commit c1fe07d  (พาดหัว 2 บรรทัดแล้ว · medal ยังอยู่)
14:57 UTC  push ตัวเอา medal ออก
```

เรนเดอร์ #40 ซ้ำด้วยโค้ดปัจจุบัน: พาดหัว **5 → 2 บรรทัด** (ย่อเหลือ 53px) · ไม่มี medal · ไม่มีกล่องเปล่า

> 💡 **เวลามีคนบอกว่า "แก้แล้วยังเหมือนเดิม" ให้เช็กก่อนว่าเขาเห็นผลจากโค้ดเวอร์ชันไหน**
> อย่าเพิ่งไปไล่หาบั๊ก — รอบนี้เกือบเสียเวลาแก้ของที่ไม่ได้พัง
