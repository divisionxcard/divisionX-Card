# EB-05 ลงตู้แล้วแต่ไม่มีใน `skus` — ซิงค์สต็อก VMS ล้มทั้งชุด

เจ้าของส่งภาพแจ้งเตือนจากบอทในห้อง DVX_Owner: **"ซิงค์รอบ 10:00 ไม่สำเร็จ"** ลองครบ 2 ครั้ง
ยอดขายผ่านทุกยี่ห้อ · สต็อก WW/Payif ผ่าน · **สต็อก vms ล้ม**

## ต้นเหตุ

รันซ้ำในเครื่อง (`scripts/sync_local.py --stock --brand vms`) ได้ข้อความตรง ๆ:

```
machine_stock violates foreign key constraint "machine_stock_sku_id_fkey"
Key (sku_id)=(EB 05) is not present in table "skus".
```

แอดมินตั้ง `One Piece EB - 05` เข้าช่อง 039–040 ของ [[chukes01]] / [[chukes02]] / [[chukes03]]
ตัวแปลงชื่อได้ `EB 05` ถูกต้อง (regex รับเลขชุดอะไรก็ได้อยู่แล้ว) แต่**ไม่มีใครเพิ่มแถว `EB 05` ใน `skus`**
→ เคสเดียวกับ [[2026-08-25-op17-missing-sku]] เป๊ะ — ไม่ใช่ mapper พัง

ต่างจากรอบ OP-17 ตรงที่ครั้งนี้**ล้มดังทั้งรอบ**แทนที่จะเงียบ:

| ตัว | มีด่าน `null_unknown_skus` | ผลเมื่อเจอ sku ที่ไม่รู้จัก |
|---|---|---|
| `worldwide_stock_sync.py` | ✅ | sku NULL · เก็บชื่อไว้ · รอบผ่าน |
| `payif_stock_sync.py` | ✅ | เหมือนกัน |
| `vms_stock_sync.py` | ❌ (ก่อน 566561b) | **FK ตีกลับทั้ง 240 ช่อง** · สต็อกหน้าตู้ VMS ค้าง |

## ที่หนักกว่าที่เห็น — ยอดขายที่ตู้ WW หล่นเงียบ ๆ มา 2 วัน

EB-05 ลง [[wwv01]] / [[wwv08]] ตั้งแต่ 14 พ.ย. (เติมจริง) · [[wwv03]] / [[wwv06]] ตามมา
`worldwide_sales_api.filter_unknown_skus()` **ทิ้งรายการขายทั้งแถว** (sales.sku_id NOT NULL FK)
ตาราง `sales` ไม่มี EB-05 สักแถว ทั้งที่ช่องในตู้ลดลงจริง — สัญญาณเดียวคือแจ้งเตือน "ยังจับคู่ SKU ไม่ได้"

ถ้าไม่ล้มที่ฝั่ง VMS ก่อน เรื่องนี้จะเงียบไปเรื่อย ๆ

## ผลข้างเคียงของรอบที่ล้ม: รายการ "เติมของ" ซ้ำ

`slot_tracking` เขียน `slot_refill_events` **ก่อน** save machine_stock และเทียบกับ machine_stock เดิม
→ รอบที่ล้มทุกรอบบันทึก event ชุดเดิมซ้ำ (บอท 2 รอบ + ที่ผมรันทดสอบ 1 รอบ = 3 ชุด × 60 แถว)
ถ้าปล่อยไว้ ตัวเลขการเติมรอบนี้จะนับ 4 เท่าในหน้ารอบเติม
→ ลบ 3 ชุดที่มาจากรอบที่ล้ม เก็บชุดของรอบที่ผ่าน · สำรองไว้ `backups/slot-refill-dupes-2026-11-16/` (นอกรีโป)

> 💡 ด่านเดียวกันนี้กันได้ทั้งสองปัญหา — sku ที่ไม่รู้จักกลายเป็น NULL ก่อนขั้นที่เขียนตาราง FK
> รอบจึงไม่ล้ม และไม่มีการลองซ้ำที่สร้าง event ซ้ำ
