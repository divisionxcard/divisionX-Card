# Chrome profile Research ใช้ร่วมกับ AssetX — กุญแจกลาง (3 พ.ย.)

ต่อจาก [[2026-10-28-social-ig-reddit-first-run]] (ตัวเฝ้าเพจ) · สกิล `social-research` ที่ยกไปให้ AssetX เมื่อ 2 พ.ย.

## เจ้าของขอ
"เบื้องต้นอาจจะใช้ร่วมกันไปก่อน แต่ของ AssetX จะใช้ในการดูเฟซบุ๊กเป็นหลัก ส่วนช่องทางอื่นของ AssetX สามารถดูจากแหล่งอื่นได้
และช่วยเขียนให้รู้ว่า 2 ระบบนี้ต้องทำงานร่วมกันอย่างไร และมีข้อจำกัดอย่างไรบ้าง ให้อีกโปรเจกต์หนึ่งทราบด้วย"

## ทำไมต้องมีกุญแจ
บัญชีสำรอง + ส่วนเสริม OpenCLI + Chrome profile มีชุดเดียวบนเครื่องเจ้าของ · ตัวเฝ้าเพจของเรารันเวลาไม่แน่นอน
(07:03 ปกติ · เปิดเครื่องสาย = ชดเชยตอนเปิด · `/ideas` กดได้ทุกเวลา) → แยกด้วยเวลาอย่างเดียวไม่พอ ·
ของเราปิด session `dvxwatch` ตอนจบรอบ · ถ้าอีกฝั่งเจอ checkpoint แล้วไม่บอก เราจะอ่านต่อจนบัญชีเสี่ยงโดนปิด

## ทำอะไร
### `deploy/agents/shared_browser.py` (ใหม่ · ไม่มี dependency)
ไฟล์ประสานงานที่ `%USERPROFILE%\.research-browser\` (นอกรีโปทั้งสอง)
- `lock.json` — สร้างแบบ O_EXCL · token · แตะ mtime ก่อนทุกคำสั่ง OpenCLI · เงียบเกิน 10 นาที = ยึดได้
  (rename → ดู mtime ซ้ำ → ยังสดให้ `link` คืนที่เดิม) · หลุดมือ = `LostLock` (ไม่ใช่ลูกของ `WatchError` จะได้ไม่วนเพจต่อ)
- `state.json` — พักร่วมต่อแพลตฟอร์ม 3 วัน · เขียนเฉพาะตอนถือกุญแจ (atomic replace)
- `usage.jsonl` — จด**ทีละเพจก่อนเปิด** + แถวสรุปตอนจบ (`pages` ว่าง) · เพดานนับจาก `pages` ทุกแถววันนี้
### `social_watch.py`
- วางแผน → ตรวจของร่วม (ไม่มีอะไรให้อ่าน = ไม่รอกุญแจ) → ถือกุญแจ (รอ ≤ 8 นาที) → ตรวจซ้ำ → bridge → อ่าน → ปิด session → แถวสรุป → ปล่อย → ส่งคิว
- เพดาน FB: รวมบัญชี 12/วัน · ของเรา 8 (`own_daily_cap` — กันที่ให้ AssetX 4 · 22 ต.ค. เราเคยเปิด 12 เพจในวันเดียว)
- งบทั้งรอบรวมรอกุญแจ 1200 วิ (`run_budget_sec`) — จบเองก่อนบอทฆ่าที่ 1500 วิ (โดนฆ่า = ไม่มี finally)
- `--target` ข้ามพักร่วม/เพดาน (ตรวจเพจด้วยมือ) แต่ถือกุญแจ จดการใช้ และไม่เกิน `max_targets_per_run`
- `--dry-run` ไม่เขียนของเรา แต่ยังถือกุญแจและจดของร่วม (การใช้บัญชีจริงต้องนับ)
### สกิล `social-research` (นอกรีโป)
- `profiles/shared-browser-dvx-assetx.md` — ข้อตกลง 10 ข้อ: ใช้ร่วม/แยก · ใครใช้เมื่อไหร่ · โปรโตคอล · ลำดับต่อรอบฝั่ง AssetX (โค้ดตัวอย่าง)
  · dry-run/ทดสอบ/คำสั่งที่พิมพ์เอง · ข้อจำกัด · ใครทำอะไรเมื่อมีปัญหา · วิธีเรียก OpenCLI จาก Node · เช็กลิสต์ก่อนเปิด · เมื่อไหร่ควรแยกบัญชี
- `references/shared-browser.mjs` + `.test.mjs` — ตัวเดียวกันฝั่ง Node ให้ AssetX ก๊อปไปใช้

## เจอระหว่างทดสอบจริง
### ต้นเหตุที่ตัวเฝ้าเพจข้ามทุกรอบ 31 ต.ค.–3 พ.ย. = OpenCLI daemon ไม่ได้รัน (`044e59c`)
- เจ้าของเปิด Chrome profile Research แล้วก็ยังต่อไม่ได้ · `opencli doctor` บอก daemon ไม่ได้รัน → ส่วนเสริมไม่มีที่ให้ต่อ
- หลังเปิดเครื่อง daemon ไม่ขึ้นเอง และ `profile list` ที่ `ensure_bridge` ใช้ถาม **ไม่สตาร์ตให้** — เดิมเปิด Chrome อย่างเดียว จึงข้ามเงียบ ๆ ทุกวัน
- แก้: `bridge_info()` คืน daemonRunning ด้วย · ไม่รัน = `daemon restart` (ทดสอบแล้วว่าสตาร์ตจากสถานะหยุดได้ · ส่วนเสริมต่อทันที) ·
  ทดสอบจริง: stop daemon → `ensure_bridge` สตาร์ตเอง → ต่อได้ · เพิ่มขั้นนี้ในข้อตกลงข้อ 4.5 ให้ฝั่ง AssetX ด้วย
- ข้อค้าง 2 พ.ย. ที่ให้เจ้าของ "เปิด Chrome ค้างไว้" จึงแก้ไม่ตรงจุด (ผมวินิจฉัยครึ่งเดียว)
