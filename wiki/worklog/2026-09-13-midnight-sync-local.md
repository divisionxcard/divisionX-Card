## ทำไมใส่ไว้ในบอท ไม่ใช่ Task Scheduler

บอทซิงค์รันค้างอยู่แล้ว 24 ชม. บนเครื่องนี้ ถือ token · รู้ห้องที่ผูกไว้ ·

## ของจริงที่ต่างจาก cron: เครื่องอาจปิดอยู่

cron บนเซิร์ฟเวอร์ยิงตรงเวลาเสมอ แต่เครื่องนี้เป็นคอมของเจ้าของ ถ้าดับอยู่
ตอนเที่ยงคืนแล้วยิงตามนาฬิกาอย่างเดียว = วันนั้นข้อมูลหายถาวร

จึงไม่ใช้ "ตอนนี้ 00:10 หรือยัง" เป็นเงื่อนไข แต่ใช้ **"วันนี้ซิงค์ไปหรือยัง"**

```python
def auto_due(now, state):
    if now.strftime("%H:%M") < at:              return False
    if state.get("auto_done_date") == วันนี้:    return False
    return True
```

ผลคือเปิดเครื่องตอน 9 โมงเช้า บอทก็ซิงค์ชดเชยให้ทันที · ขาดหลายวันก็ไล่เก็บ
ย้อนหลังโดยซอยเป็นช่วงละ ≤5 วัน (sync_local ปฏิเสธช่วงยาวกว่านั้น เพราะ VMS
ตัดข้อมูลถ้าดึงทีเดียวเยอะ) · เซฟความคืบหน้าทีละช่วง ล้มกลางทางไม่ต้องเริ่มใหม่

เลือกเวลา 00:10 ไม่ใช่ 00:00 เป๊ะ เผื่อให้หลังบ้านตู้ปิดยอดของวันเรียบร้อยก่อน

## 🐛 บั๊กที่เจอเพราะดันไปทดสอบของจริง (ตัวสำคัญที่สุดของวันนี้)

ตั้งใจให้รอบอัตโนมัติยิงทันทีตอน 19:26 เพื่อดูว่ามันทำงานจริงไหม — **มันล้ม**

```
UnicodeEncodeError: 'charmap' codec can't encode characters in position 0-9
  File "scripts\sync_local.py", line 134, in main
    print(f"ช่วงวันที่: {frm} → {to} · ยี่ห้อ: ...")
```

`sync_local.py` พิมพ์ไทยล้วน แต่ Python บน Windows เลือก encoding ของ stdout
จาก **ACP ของเครื่อง** ซึ่งเครื่องนี้คือ `cp1252` (วินโดวส์อังกฤษ) เข้ารหัสไทยไม่ได้
พอบอทเรียกแบบดักเอาต์พุต (`capture_output=True` = ต่อ pipe ไม่ใช่คอนโซล)
ก็ตายตั้งแต่บรรทัด print แรกของ `main()`

**แล้วทำไมปุ่มที่กดกันมาตั้งแต่ 11 ก.ย. ถึงไม่เคยพัง?** เพราะบังเอิญล้วน ๆ:

```
[Environment]::GetEnvironmentVariable("PYTHONIOENCODING","User")    → (ว่าง)
[Environment]::GetEnvironmentVariable("PYTHONIOENCODING","Machine") → (ว่าง)
$env:PYTHONIOENCODING                                               → utf-8:surrogateescape
```

ค่านี้มีเฉพาะใน process tree ของ Claude Code — และบอทตัวที่รันอยู่ตั้งแต่
11 ก.ย. 16:01 ก็ถูกสตาร์ตจากเซสชันนั้น เลยรับมรดกตัวแปรนี้มาโดยไม่มีใครรู้

⚠️ **แปลว่าถ้ารีบูตเครื่องเมื่อไหร่ บอทจะขึ้นเองจาก Startup โดยไม่มีตัวแปรนี้
แล้วปุ่มซิงค์ทุกปุ่มจะพังทันที** — ระเบิดเวลาที่รออยู่ ไม่เกี่ยวกับงานเที่ยงคืนเลย
แต่เจอเพราะงานเที่ยงคืนบังคับให้ต้องทดสอบในสภาพที่ไม่มีมนุษย์คอยดู

แก้ที่ต้นตอใน `sync_local.py` สองชั้น:

```python
for _s in (sys.stdout, sys.stderr):          # ชั้นแรก: ตัวเอง
    _s.reconfigure(encoding="utf-8", errors="replace")
os.environ.setdefault("PYTHONIOENCODING", "utf-8:replace")   # ชั้นสอง: ลูก ๆ
```

ต้องมีสองชั้นเพราะ `reconfigure` แก้ให้เฉพาะ process ตัวเอง **ไม่ตกทอดถึงลูก** —
สคริปต์ scraper ที่ถูกเรียกต่อก็พิมพ์ไทยและเขียนลง pipe เดียวกัน ต้องส่งผ่าน env เท่านั้น

บทเรียนเดียวกันโผล่ซ้ำในวันเดียวกันถึงสามที่ (`telegram_sync_bot.py` ตอน redirect log,
`sync_local.py`, และสาย scraper) — **ทุกสคริปต์ที่พิมพ์ไทยแล้วมีโอกาสถูกเรียกแบบ
ไม่มีคอนโซล ต้องตั้ง encoding เอง ห้ามพึ่งค่าปริยายของเครื่อง**

## ตัวเฝ้า — เพราะบอทตายแล้วเงียบสนิท

เดิมบอทเป็นแค่ปุ่มอำนวยความสะดวก ตายก็แค่กดไม่ได้ คนรู้ทันที
ตอนนี้มันถือหน้าที่ซิงค์รายวัน **ตายแล้วยอดขายหยุดเข้าโดยไม่มีสัญญาณอะไรเลย**

- `start_sync_bot.vbs` เช็ค WMI ก่อนว่ามีบอทรันอยู่ไหม มีแล้วออกเลย (บอทสองตัว
  จะแย่งกัน `getUpdates` — Telegram ให้ตัวเดียวเท่านั้น กดปุ่มแล้วเงียบเป็นครั้งคราว)
  ⚠️ ต้องกรอง `Name LIKE 'python%'` ด้วย ไม่งั้น shell ที่เคยพิมพ์ชื่อไฟล์นี้ก็เข้าข่าย
  แล้วตัวเฝ้าจะเห็นว่า "ยังอยู่" ทั้งที่ตายไปแล้ว (เจอจริงตอนทดสอบ นับได้ 5 process)
- งาน Task Scheduler `DVX Sync Bot Watchdog` เรียก .vbs ทุก 15 นาที ไม่มีกำหนดจบ

ยังเหลือข้อจำกัด: ทั้งหมดนี้ผูกกับ **การล็อกอินของเจ้าของ** ถ้ารีสตาร์ตแล้วไม่ล็อกอิน
บอทไม่ขึ้น (แก้ได้ด้วยการตั้ง task แบบ "run whether user is logged on or not"
ซึ่งต้องเก็บรหัสผ่านวินโดวส์ไว้ — ยังไม่ทำ)

## คำสั่งใหม่ในห้อง

| พิมพ์ | ได้อะไร |
|---|---|
| `/auto` | สถานะ: เปิด/ปิด · เวลา · ข้อมูลถึงวันไหน · วันนี้รันยัง |
| `/auto off` / `/auto on` | ปิด/เปิดรอบอัตโนมัติ |
| `/auto 00:30` | เปลี่ยนเวลา |

กดปุ่ม "ซิงค์ทั้งหมด" เองระหว่างวัน = นับเป็นรอบของวันนั้น บอทจะไม่รันซ้ำให้เปลือง
แต่กดเฉพาะสต็อกหรือเฉพาะยอดขายไม่นับ เพราะยังขาดอีกครึ่ง
