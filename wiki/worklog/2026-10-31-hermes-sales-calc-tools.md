# Hermes เข้าใจระบบคำนวณยอดขาย — tool คิดให้เสร็จ (31 ต.ค.)

ต่อจาก [[2026-10-30-daily-digest-costs-abyss-eye]] (สูตรกำไร + ต้นทุนตามช่วงเวลา)

## เจ้าของขอ
"เพิ่มระบบการคำนวณที่เกี่ยวกับยอดขายของเราให้ Hermes เข้าใจทั้งหมด — แอดมินในกลุ่มไม่รู้ว่าเบื้องหลังโปรเจกต์
คำนวณได้ถึงขั้นไหน จึงมีคำถามเชิงวิเคราะห์ค่อนข้างเยอะ"

## เจออะไร (อ่านประวัติกลุ่ม DVX_Admin 30 ต.ค. จาก state.db ของ Hermes)
แอดมินถาม 5 ข้อติดกัน Hermes ผิด 4:
1. **"กำไรเท่าไหร่"** → Hermes ใช้ `execute_code` คูณยอดขาย × 20% (ไม่มี tool คิดกำไร เลยแต่งสัดส่วนเอง)
2. **"7 วันล่าสุด"** → `days=7` ของ tool เดิมนับรวมวันนี้ (ยังขายอยู่) แล้วเอาไปเทียบกับ 7 วันเต็มของเดือนก่อน
3. **"เดอะมอลล์บางกะปิ"** → ไปดึง `wwv02` ที่ปิดตั้งแต่ 19 ส.ค. แล้วตอบว่ายอด 0 "เพราะยังไม่ซิงค์"
   (SOUL.md ยังเขียนว่ามี 13 ตู้ · ตัวหาตู้เดิมไม่รู้จักสถานะตู้)
4. **"ขายไม่ออกทั้งเดือน"** → ดึงยอดรายสินค้า + สต็อกมาเทียบเอง นับของที่ขายได้ 4 ตัวเป็นขายไม่ออก
   และตก Yu-Gi-Oh The Rivals (ชื่อในระบบสะกด `YGH The Revals`)

ต้นเหตุร่วม: tool ส่งแค่ข้อมูลดิบ แล้วปล่อยให้โมเดล (gpt-5.4-mini) คิดเลข/เทียบรายการเอง

## ทำอะไร
### ชั้นข้อมูล `deploy/agents/dvx_data.py`
- **กำไรใน `get_sales` ทุกครั้ง** — import `Costs` · `KSHER_FEE` · `thai_day` จาก
  `daily_sales_digest.py` ตรง ๆ (ไม่เขียนสูตรชุดที่สาม) → ตัวเลขเท่าสรุปยอดบอท DVX Job ทุกบาท
  (เทียบจริงแล้ว: รายวัน 29–30 ต.ค. + รายสัปดาห์ 19–25 ต.ค. ตรงทั้งยอดรวม รายตู้ และรายสาขา)
- ตัดสาขาด้วยชื่อที่ลูกค้าเห็น (`config.branch.display_name`) — ตู้เก่า wwv02 สะกดห้างใน location ขาด ล
  ใช้ location แบบสรุปยอดแล้วบางกะปิแตกเป็น 2 สาขาเมื่อถามช่วง พ.ค.–ส.ค.
  ส่ง `profit` = กำไรสุทธิ · margin · ค่าธรรมเนียมรวม · ต้นทุนรวม · เคลม · ยอดที่ไม่มีทุน — **ไม่ส่งทุนต่อซองรายสินค้า**
- มุมมองใหม่: `group_by` = branch (รวมตู้ห้างเดียวกัน) · franchise · weekday (มียอดเฉลี่ยต่อวัน + จำนวนวันนั้นในช่วง) ·
  hour · day ใส่วันที่ยอด 0 ด้วย · กรองสินค้า/ค่ายด้วย `sku` · หลายตู้คั่น `,`
- `data_status` — synced_at ล่าสุดของแถวขายต่อยี่ห้อ → เตือนเมื่อช่วงที่ถามยังไม่ครบ/รวมวันนี้
- `machine_notes` — ตู้ปิดแล้วบอกวันปิด + เหตุผล "ยอด 0 เพราะไม่มีตู้"
- **`compare_sales`** — previous · last_week (เลื่อนเป็นสัปดาห์เต็ม ไม่ซ้อน) · last_month (31 → วันสุดท้ายเดือนก่อน) ·
  last_year · custom + สินค้าขายเพิ่ม/ลดเรียงตามบาท + เตือน: ยาวไม่เท่ากัน · เสาร์-อาทิตย์ไม่เท่ากัน · ฐานไม่ถึง 1,000 บาท
- **`get_unsold_skus`** — ของในตู้ตอนนี้ที่ขายได้ ≤ N ซอง แยก `unsold` / `new` (swap_in หลังวันเริ่มช่วง จาก
  `slot_refill_events`) / `empty` (ช่องไม่มีของ) + วันขายล่าสุด + ชื่อหน้าตู้ + ตัวที่ขายไม่ออกหลายสาขา
- ตัวหาตู้: ตรงทั้งตู้ปิดกับตู้ใช้งาน → เอาตู้ใช้งาน · ห้างเดียวกันหลายตู้ (พระราม 2) = ทั้งสาขา · ข้ามสาขา ("บางแค") = ฟ้องพร้อมตัวเลือก
- ทาง MCP: `days` = วันครบวันล่าสุดจบเมื่อวาน · ผู้เรียกเดิม (idea_collector · dvx_query) ไม่ส่งอาร์กิวเมนต์ใหม่ = พฤติกรรมเดิม
- ดึงยอดขายใส่ `&order=id` ทุกที่ (ดึงทีละหน้าไม่เรียง = แถวซ้ำ/หายได้)

  และปฏิเสธบอกทุนต่อซอง
- **ตรวจอิสระรอบ 1** (workflow · agent คิดเลขเองจากตารางดิบ ไม่เรียกฟังก์ชันใหม่) — ตัวเลขตรงทุกข้อ:
  กำไรตู้เดียว · ทุกสาขาทั้งเดือน · รายสัปดาห์ (= สรุปยอด) · ราย SKU · เทียบเดือน · รายชั่วโมง/วันในสัปดาห์ ·
  ขายไม่ออกทุกตู้ทั้งเดือน (ชุด SKU ตรงทุกตู้ · วันขายล่าสุดตรง 63/63)
- **รีวิวโค้ดรอบ 1 เจอ 8 ข้อ ยืนยันจริงทั้ง 8 → แก้แล้ว:**
  1. ถาม "บางกะปิ" ย้อนหลังช่วงที่ wwv02 ยังเปิด → ได้แค่ wwv08 ยอดหายเงียบ ๆ → รวมตู้ที่ปิดแล้วของห้างเดียวกันเมื่อช่วงที่ถามย้อนถึงก่อนวันปิด
  2. เทียบเดือนก่อนแบบทั้งเดือน (ก.ย. → ส.ค.) ทิ้ง 31 ส.ค. โดยไม่เตือน → จบสิ้นเดือน = จบสิ้นเดือนก่อน
  3. ย้ายช่อง/หลังบ้านเปลี่ยนชื่อในรอบซิงค์เดียว (swap_out + swap_in เวลาเดียวกัน) ถูกนับเป็น "เพิ่งลงตู้" → ข้าม
  4. "OP 1" กลายเป็น OP 10–17 → เทียบรหัสแบบเติมศูนย์ · คำค้นลงท้ายตัวเลขที่ไม่ตรงตัวไหน = ฟ้อง ไม่เดา
  5. สต็อก "พระราม 2" ฟ้อง error (2 ตู้) → `get_stock` รับหลายตู้/ทั้งสาขา
  6. Payif ตู้เดียว วันที่ขายไม่ได้ → เตือนหลอกว่ายอดไม่ครบ → ใช้เวลาซิงค์สต็อกเป็นหลักฐานรอง
  7. ลงตู้กลางช่วงนานแล้ว (50+ วัน) ยังได้ "new" → new เฉพาะมีของไม่ถึง 14 วันในช่วง · นับช่องว่างจนเติมจาก 0 ด้วย
  8. % เปลี่ยนเมื่อช่วงก่อนติดลบ เครื่องหมายกลับ → ไม่มี % (เท่าสรุปยอด)
  + แถวราย SKU ถูกตัด top และปัดเศษทีละแถว → `breakdown_note` บอกให้ใช้ยอดรวมด้านบน · รายชั่วโมงใส่ 10–22 ครบ
- **รีวิวรอบ 2 (หลังแก้) เจอ 20 ข้อ ยืนยันจริงทั้ง 20** — ส่วนใหญ่เป็นตัวหาขายไม่ออกกับคำถามย้อนหลัง
  → **เขียนตัวหาขายไม่ออกใหม่ทั้งตัว** แทนการไล่ปะทีละเคส:
  - สร้างไทม์ไลน์รายช่องจาก `slot_refill_events` (VMS รายช่อง · WW/Payif รวมทั้ง SKU) — อยู่ในตู้ระหว่าง swap_in–swap_out ·
    swap_out+swap_in รอบเดียวกัน = ย้ายช่อง/เปลี่ยนชื่อ · เพิ่มช่องให้ของเดิม = ไม่ใช่ลงใหม่
  - ช่องว่างนับเฉพาะเมื่อมีหลักฐาน (รอบก่อนเป็น 0 หรือขายจนหมด) — WW เปลี่ยนชื่อสินค้าแล้วเลขก่อนเติมเป็น 0 ทั้งที่ของเต็ม
  - นับ "วันที่มีของให้ขาย" จากภาพตอนเที่ยงของแต่ละวัน · ตัดสินโดยมองย้อนอย่างน้อย 14 วันเสมอ (ถาม 7 วันก็ไม่เพี้ยน)
  - สถานะ `unsold` / `short` (มีของไม่ถึง 14 วัน) / `empty` (อยู่ในตู้แต่ว่างทั้งช่วง) · ไม่อยู่ในตู้ช่วงนั้นเลย = ไม่นับ ·
    ของที่ถอดออกแล้วยังนับในช่วงที่เคยอยู่ · ตู้ที่ปิดแล้วข้าม · to_date เลยวันนี้นับถึงวันนี้
  - ถามทุกตู้ส่งเฉพาะ unsold ตู้ละ 10 ตัว (เดิมทั้ง 12 ตู้ยาวเกินแสนตัวอักษร)
  - อื่น ๆ: หาสินค้าด้วยชื่อเต็ม/รหัสสั้น/ชื่อไทย/ id เก่า โดยไม่ตัดกลางตัวเลข · เทียบเดือนก่อนขยายถึงสิ้นเดือนเฉพาะถามเป็นเดือน ·
    เลิกใช้เวลาซิงค์สต็อกพิสูจน์ว่ายอดครบ (workflow สต็อกข้ามขั้นยอดขายที่ล้มได้) · แถวสาขาบอกเฉพาะตู้ที่มียอด ·
    ยอดรวม/รายสาขาบวกจากรายตู้ลำดับเดียวกับสรุปยอด (เดิมต่าง 1 บาทเมื่อกำไรลงท้าย .5) · ช่วงเทียบไม่มียอด = เตือนห้ามสรุปว่าโต ·
    CLI `dvx_query sales --by day` กลับมาบอก "ยังไม่ได้ sync"
- **ถาม Hermes จริงรอบ 3 เจอ 3 เรื่อง → แก้ที่ tool:** ตอบ "ขายไม่ออก" ด้วย `max_packs=2` แล้วเรียกตัวที่ขายได้ 2 ซองว่าขายไม่ออก
  → เพิ่มสถานะ `slow` (ขายได้บ้าง) แยกจาก `unsold` · เทียบช่วงเขียนลูกศรกลับด้าน (ยอดช่วงนี้ → ยอดช่วงก่อน แต่บอก % บวก) → เรียงฟิลด์
  ช่วงก่อนมาก่อน + กฎใน SOUL · "12 สาขา" ที่จริงคือ 12 ตู้ → ฟิลด์ `in_several_machines.machine_count` + หมายเหตุ
- **รีวิวรอบ 3 เจอ 9 ข้อ (ร้ายแรง 2) ยืนยันจริงทั้ง 9 → แก้แล้ว:** รอบสองของตัวหาขายไม่ออกกรองประวัติช่องทิ้ง
  → ของที่ลงตู้หลังช่วงที่ถามกลับมาเป็น "ขายไม่ออกทั้งเดือน" (OP 17 ที่ chukes01 เดือน ก.ค.) · ขายหมดแล้วถอดทีหลัง
  (swap_out ตอนเหลือ 0) ยังนับว่ามีของ · ลงช่องด้วยจำนวน 0 · ตู้เปิดกลางช่วงนับก่อนตู้มีจริง (wwv08 ก.ค.) ·
  SKU หลายช่องใช้เวลาว่างผิดช่อง · ยอดรวมบวกแบบ `+=` ต่างจาก `sum()` ของ Python 3.12 (ต่าง 1 บาทได้) ·
  ชื่อสินค้าซ้ำหลังเปลี่ยน id · from_date อนาคต · `get_stock` ตู้ที่ปิดแล้วบอกว่าไม่พบตู้
  ตรวจซ้ำกับข้อมูลจริง: กำไรตรงสรุปยอดทุกวันของ ต.ค. (30/30 วัน ทั้งยอดรวมและรายตู้)
