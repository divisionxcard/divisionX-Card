# สถานี 1 — ระบบหาไอเดียคอนเทนต์

## บริบท (why)
หน้า /marketing เฟส 1+2 เริ่มต้นที่ "ร่างคอนเทนต์รออนุมัติ" เลย — **ขั้นหาไอเดียหายไปทั้งขั้น**
คนยังต้องนั่งคิดเองว่าจะทำคอนเทนต์เรื่องอะไร ซึ่งเป็นงานที่กินเวลาที่สุด

สถานีนี้เปลี่ยนจาก "นั่งคิดเอง" เป็น "AI ไปหามาวางบนโต๊ะให้เลือกทุกเช้า"

## เลือกแหล่งข้อมูลจากการทดสอบจริง ไม่ใช่จากที่คิดว่าน่าจะได้

ทดสอบก่อนออกแบบว่าแหล่งไหนดึงได้จริงโดย**ไม่ต้องมี API key** (เงื่อนไขสำคัญ —
ถ้าต้อง key จะรันบน GitHub Actions ไม่ได้ และต้องรอ approval):

| แหล่ง | ผล |
|---|---|
| Google News RSS ไทย | ✅ 55KB · ได้ข่าวตรงประเด็นมาก |
| YouTube channel RSS | ✅ 31KB · ใช้ `channel_id` ไม่ต้องมี key |
| Bandai One Piece TCG RSS | ❌ 404 — ตัดทิ้ง |
| คอมเมนต์ FB/YT | ⛔ ต้องขอ permission Meta → เฟส 3 |

**แหล่งที่ 3 คือข้อมูลขายของเราเอง** — แหล่งที่คู่แข่งลอกไม่ได้ เพราะไม่มีใครมีข้อมูลนี้

## ผล dry-run จริง (34 ไอเดียใหม่)

```
5.56 [internal] Pokemon Ninja กำลังมาแรง — ยอดโต 78%
5.50 [news    ] 10 อันดับ การ์ดวันพีช ที่ราคาแพงที่สุดในตลาด TCG
5.25 [internal] One Piece OP-13 กำลังมาแรง — ยอดโต 63%
4.70 [news    ] เปิดแล้ว! One Piece Card Game Pop-Up Store Bangkok แห่งแรกในไทย
3.90 [internal] One Piece OP-11 ยอดตก 45% — ควรกระตุ้น
```

ข่าว Pop-Up Store กรุงเทพฯ คือตัวอย่างที่ชัดว่าระบบมีประโยชน์จริง — เป็นกระแสที่เกี่ยวกับ
ธุรกิจโดยตรงและถ้าไม่มีตัวเก็บก็คงไม่รู้

## จุดตัดสินใจ

- **ให้คะแนนแบบ rule-based ไม่ใช้ LLM** — นับคำที่ตรงกับแฟรนไชส์ที่เราขายจริง
  (ดึงจากตาราง `skus` ไม่ hardcode) + คำบอกเจตนา (เปิดตัว/วางจำหน่าย/pop-up)
  เหตุผล: รันฟรี · ได้ผลเหมือนเดิมทุกครั้ง · และ Ollama รันบน Actions ไม่ได้อยู่แล้ว
- **แยกฟิลด์ `angle` กับ `relevance`** — `angle` คือมุมที่จะเล่า `relevance` คือทำไมเกี่ยวกับเรา
  สองอันนี้ทำให้สแกนแล้วตัดสินใจได้โดยไม่ต้องเปิดอ่านข่าวเต็ม (หลักการเดียวกับ `source_reason`
  ในกล่องอนุมัติ)
- **แหล่งข้อมูลอยู่ในไฟล์ JSON** (`deploy/tasks/idea_sources.json`) ไม่ใช่ในโค้ด —
  เพิ่มคำค้น/ช่อง YouTube ได้เองโดยไม่ต้องแก้ Python
- **"เริ่มทำคอนเทนต์" สร้างร่างสถานะ `draft` ไม่ใช่ `pending`** — เพราะตัวเขียนแคปชั่นจริง
  ใช้ Ollama ที่รันในเครื่องเท่านั้น เว็บทำได้แค่ตั้งโจทย์ให้ · กล่องอนุมัติจึงโหลด `draft,pending`
  แล้วติดป้าย **"ยังไม่มีแคปชั่นจริง"** กันเผลออนุมัติโจทย์แทนแคปชั่น
- **`external_key` unique** กันเก็บข่าวเดิมซ้ำข้ามรอบ · สัญญาณภายในผูกกับวันที่
  (`hot:OP 13:2026-08-04`) จึงเสนอได้วันละครั้ง ไม่รก

## ค้าง
