# โพสต์ขึ้นเพจ Facebook ได้จากหน้าเว็บ (auto-posting ระดับ 3)

## ทำไมเลือกทำอันนี้ก่อน — ตัวเลขชี้เอง

สำรวจสถานะระบบก่อนตัดสินใจ:

| | |
|---|---|
| ไอเดีย | 93 ชิ้น · มุมครบ 258 มุม |
| คอนเทนต์ | 19 ชิ้น (pending 10 · rejected 8) |
| **โพสต์จริง** | **1 ชิ้น** |

คอขวดไม่ได้อยู่ที่ "คิดคอนเทนต์ไม่ออก" — ของล้นอยู่แล้ว
มันอยู่ที่ **ขั้นตอนเอาไปโพสต์** ที่ต้องทำมือ 5 ขั้น: ก๊อป → เปิดเพจ → วาง → แนบรูป → กลับมากดยืนยัน

เจ้าของเคยชี้ heroaiengine ว่า *"ทำงานได้ครบวงจร ทั้งคิดคอนเทนต์ สร้างรูป โพสต์เฟสอัตโนมัติ"*
เรามี 2 ใน 3 แล้ว ขาดข้อสุดท้าย — และข้อสุดท้ายคือข้อที่ตัวเลขบอกว่าคือคอขวด

## ยิงเช็กเอกสารก่อนเขียน ไม่ได้เดา

บทเรียนจากเรื่องโควตา Gemini ([[2026-08-10-angle-picker-and-variants]]) ที่เดาผิด 2 รอบ
รอบนี้ยืนยันทุกข้อกับเอกสาร Meta ก่อนลงมือ:

| สิ่งที่ต้องรู้ | ของจริง |
|---|---|
| พารามิเตอร์แคปชั่นของ `/photos` | `caption` — `message` ถูก deprecate ไปแล้ว |
| ทดสอบยังไงไม่ให้ขึ้นเพจ | `published=false` อัปแล้วไม่เผยแพร่ อยู่ ~24 ชม. **ไม่ต้องมี** `scheduled_publish_time` |
| Page token หมดอายุไหม | ถ้าแลกผ่าน long-lived user token → **ไม่มีวันหมดอายุ** (`expires_at=0`) |
| ต้องผ่าน App Review ไหม | **ไม่ต้อง** ถ้าใช้กับเพจตัวเองในโหมด Development |

**ข้อสุดท้ายสำคัญมาก** — [[auto-posting-plan]] ที่เขียนไว้เดือน มิ.ย. บอกว่าระดับ 3 ต้อง
"ขอ Page token/app review" ทำให้ดูใหญ่กว่าจริงจนถูกเลื่อนออกไป
เอกสาร Meta เขียนตรง ๆ ว่า *"If your app will only be used by app users who have a role
on the app itself, App Review is not required."* → งานนี้เล็กกว่าที่แผนเดิมประเมินไว้มาก
แก้ในคู่มือใหม่แล้ว

## สิ่งที่ระวังเป็นพิเศษ — โพสต์แล้วลบไม่ได้

ต่างจากทุกปุ่มก่อนหน้าในระบบ ปุ่มนี้ทำสิ่งที่ **ย้อนกลับไม่ได้และคนนอกเห็น**
จึงกันไว้ 5 ชั้น:

1. **กล่องยืนยัน** โชว์แคปชั่น + บอกว่ามีรูปไหม ก่อนกดจริง
2. **`post_id` กันซ้ำ** — Facebook ไม่กันโพสต์ซ้ำให้ ยิง 2 ครั้งได้ 2 โพสต์จริง ๆ
   เช็กจาก `post_id` ไม่ใช่ `status` เพราะ status แก้ด้วยมือได้จากหน้าเว็บ
3. **ต้อง `approved` ก่อน** — route กันเอง ไม่พึ่งว่าปุ่มอยู่ในโซนไหน
4. **ช่องว่างค้าง** `{ชื่อสาขา}` → ปุ่มกดไม่ได้ + route ปฏิเสธซ้ำอีกชั้น
5. **โพสต์ติดแต่เขียน DB พัง** → คืน `post_id` กลับมาพร้อมคำเตือน *"อย่ากดซ้ำ"*
   ไม่ใช่ error เปล่า ๆ · ถ้าคืนแค่ error คนจะกดใหม่แล้วได้โพสต์ซ้ำบนเพจจริง

## ที่ทดสอบได้โดยไม่มี token

ยิง Graph API จริงด้วย token ปลอม — Meta คืน `code 190` ของจริงกลับมา
ใช้ยืนยันได้ว่า:
- ตัวแปล error ทำงาน → ได้ *"Page Access Token ไม่ถูกต้องหรือถูกเพิกถอน — ออกใหม่ด้วย scripts/fb-token.mjs"*
  แทนข้อความอังกฤษดิบ ๆ ที่ไม่บอกว่าต้องไปทำอะไรต่อ
- **แคปชั่นไทย 2,073 ตัวอักษร + emoji ส่งผ่านได้** — ส่งเป็น form ไม่ใช่ query string
  ถ้าใส่ใน URL จะชนลิมิตความยาวตั้งแต่แคปชั่นยาวปานกลาง
- ด่านกันพลาดที่ไม่ต้องยิง API ทำงานครบ (แคปชั่นว่าง / dryRun ที่ไม่มีรูป / ไม่ได้ตั้ง env)

## 🔴 ขั้นตอนตั้งค่ากินเวลาเป็นชั่วโมง — และผมพาหลงทาง 3 รอบ

เขียนคู่มือจากเอกสาร Meta ไว้ก่อน พอเจ้าของทำจริง **หน้าจอไม่ตรงกับเอกสารเลย**
Meta เปลี่ยนขั้นตอนสร้างแอปเป็นระบบ *กรณีการใช้งาน* แล้ว แต่เอกสารยังไม่อัปเดตตาม

ด่านที่ติดจริง (เขียนลง [[auto-posting-level3-setup]] ครบแล้ว):
1. สมัครนักพัฒนา — SMS ส่งไม่ออก เพราะบัญชียังไม่มีเบอร์ยืนยัน ต้องไปเพิ่มที่ศูนย์บัญชีก่อน
2. 6 กรณีการใช้งานที่ Meta "แนะนำ" ไม่มีอันที่ต้องใช้เลยสักอัน
3. **`Invalid Scopes: pages_read_user_content`** — ด่านหลัก ขึ้นซ้ำทุกทางที่ลอง
4. แอปแบบใหม่เป็น Facebook Login for Business ซึ่ง **เลิกใช้ `scope` แล้ว**

### บทเรียนของผมเอง — ไล่แก้ทีละอาการแทนที่จะหาสาเหตุ

ข้อ 3 ผมเดาไป 3 รอบก่อนจะไปอ่านเอกสาร: เดาว่ามันไม่บล็อก · เดาว่าให้เอาสิทธิ์ออก ·
เดาว่าอยู่ในการกำหนดค่า — ผิดทั้งหมด กว่าจะเจอว่าต้องกด **"+ เพิ่ม"** ที่หน้า
*ปรับแต่งกรณีการใช้งาน* ก็พาเจ้าของไปตั้ง redirect URI / โดเมนของแอป / สร้างการกำหนดค่า
ซึ่งไม่ได้เกี่ยวกับสาเหตุจริงเลย

**สิ่งที่ตัดจบได้เร็วกว่ามาก คือขอดูหน้าจอที่ยังไม่เคยเห็น** — พอเจ้าของส่งภาพหน้า
ปรับแต่งมา เห็นทันทีใน 5 วินาทีว่า `pages_read_user_content` ขึ้น `—` พร้อมปุ่ม `+ เพิ่ม`
ขณะที่ตัวอื่นขึ้น "พร้อมทดสอบ"

เป็นบทเรียนเดียวกับเรื่องโควตา Gemini เมื่อวาน ([[2026-08-10-angle-picker-and-variants]])
ที่เดาผิด 2 รอบทั้งที่คำตอบอยู่ใน error — **หยุดเดา แล้วไปดูของจริง**

## ✅ ผลทดสอบกับเพจจริง — ไม่มีอะไรโผล่บนหน้าเพจ

```
เช็กการเชื่อมต่อ   ✅ Division X Card · id=1016536371546877 · ผู้ติดตาม 79
อัปรูปไม่เผยแพร่    ✅ PNG 2.8 MB · photoId=122123698262914175 · published=false
```

ข้อสองสำคัญกว่าที่คิด — มันเดินเส้นทางเดียวกับตอนโพสต์จริงทุกประการ (ส่งแคปชั่นไทย +
ให้ Facebook ไปดึงรูปจาก Supabase Storage เอง) ต่างแค่ไม่กดเผยแพร่
พิสูจน์ได้ว่าโพสต์พร้อมรูปทำได้จริง **โดยไม่ต้องเสี่ยงโพสต์อะไรลงเพจธุรกิจจริง**

## 🐛 บั๊กที่เจอตอนตั้งค่าเสร็จ

พอเจ้าของตั้งค่าครบแล้วกลับเช็กไม่ได้ว่าต่อติดไหม — เพราะแถบสถานะการต่อเพจ
ถูกวางไว้**ข้างใน**กล่องรายการที่รอโพสต์ และตอนนั้นคิวว่าง (approved 0)
= ต้องมีของรอโพสต์ก่อนถึงจะรู้ว่าต่อเพจได้ ซึ่งกลับหัวกลับหาง
ย้ายออกมานอกเงื่อนไข + เพิ่มจำนวนผู้ติดตามให้เห็นว่าต่อ **ถูกเพจ** ไม่ใช่แค่ต่อติด

## ปุ่ม "ทดสอบ (ไม่ขึ้นเพจ)" — เจ้าของขอเองก่อนกล้าโพสต์จริง

โหมด `dryRun` มีในระบบตั้งแต่วันแรกแต่ **ไม่มีปุ่ม** = ผู้ใช้กดไม่ถึง เท่ากับยังไม่มีอยู่จริง
พลาดแบบเดียวกับตอนทำปุ่มโปสเตอร์ที่ทางใช้ได้ไม่มีปุ่มอยู่ 2 รอบ ([[2026-08-08-poster-builder]])

**จุดที่ตั้งใจออกแบบ: โชว์รูปที่ดึงกลับมาจากเซิร์ฟเวอร์ Facebook ไม่ใช่รูปต้นทางจาก Supabase**
ถ้าโชว์รูปต้นทาง ต่อให้ส่งไม่ถึง Facebook ก็ยังเห็นรูปสวย ๆ อยู่ดี = ทดสอบแล้วไม่ได้อะไร
จึงเพิ่ม `photoImage()` ขอ URL ไฟล์จริงบน fbcdn ผ่าน Graph API มาแสดง

### ได้ข้อมูลแถมที่ไม่ได้ตั้งใจหา
```
อัป PNG 2.8 MB  →  Facebook แปลงเป็น JPEG 361 KB
```
**Facebook บีบรูปเสมอ ไม่ว่าต้นทางจะคมแค่ไหน** — เกี่ยวโดยตรงกับเรื่องคุณภาพโปสเตอร์
ที่เจ้าของเคยติงไว้ ([[2026-08-10-marketing-ui-restructure]] · งานโปสเตอร์)
เพิ่มความละเอียดต้นทางเกินจุดหนึ่งไปก็ไม่ช่วย เพราะปลายทางบีบทิ้งอยู่ดี
ทีหลังถ้าจะปรับคุณภาพโปสเตอร์ ควรไปเน้น **องค์ประกอบ/ความคมของตัวอักษร** มากกว่าขนาดไฟล์
