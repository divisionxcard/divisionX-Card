# โพสต์ขึ้นเพจ Facebook ได้จากหน้าเว็บ (auto-posting ระดับ 3)

## ทำไมเลือกทำอันนี้ก่อน — ตัวเลขชี้เอง

สำรวจสถานะระบบก่อนตัดสินใจ:

| | |
|---|---|
| ไอเดีย | 93 ชิ้น · มุมครบ 258 มุม |
| คอนเทนต์ | 19 ชิ้น (pending 10 · rejected 8) |
| **โพสต์จริง** | **1 ชิ้น** |

คอขวดไม่ได้อยู่ที่ "คิดคอนเทนต์ไม่ออก" — ของล้นอยู่แล้ว
มันอยู่ที่ **ขั้นตอนเอาไปโพสต์** ที่ต้องทำมือ 5 ขั้น: ก๊อป → เปิดเพจ → วาง → แนบรูป → กลับมากดยืนยัน

เจ้าของเคยชี้ heroaiengine ว่า *"ทำงานได้ครบวงจร ทั้งคิดคอนเทนต์ สร้างรูป โพสต์เฟสอัตโนมัติ"*
เรามี 2 ใน 3 แล้ว ขาดข้อสุดท้าย — และข้อสุดท้ายคือข้อที่ตัวเลขบอกว่าคือคอขวด

## ยิงเช็กเอกสารก่อนเขียน ไม่ได้เดา

บทเรียนจากเรื่องโควตา Gemini ([[2026-08-10-angle-picker-and-variants]]) ที่เดาผิด 2 รอบ
รอบนี้ยืนยันทุกข้อกับเอกสาร Meta ก่อนลงมือ:

| สิ่งที่ต้องรู้ | ของจริง |
|---|---|
| พารามิเตอร์แคปชั่นของ `/photos` | `caption` — `message` ถูก deprecate ไปแล้ว |
| ทดสอบยังไงไม่ให้ขึ้นเพจ | `published=false` อัปแล้วไม่เผยแพร่ อยู่ ~24 ชม. **ไม่ต้องมี** `scheduled_publish_time` |
| Page token หมดอายุไหม | ถ้าแลกผ่าน long-lived user token → **ไม่มีวันหมดอายุ** (`expires_at=0`) |
| ต้องผ่าน App Review ไหม | **ไม่ต้อง** ถ้าใช้กับเพจตัวเองในโหมด Development |

**ข้อสุดท้ายสำคัญมาก** — [[auto-posting-plan]] ที่เขียนไว้เดือน มิ.ย. บอกว่าระดับ 3 ต้อง
"ขอ Page token/app review" ทำให้ดูใหญ่กว่าจริงจนถูกเลื่อนออกไป
เอกสาร Meta เขียนตรง ๆ ว่า *"If your app will only be used by app users who have a role
on the app itself, App Review is not required."* → งานนี้เล็กกว่าที่แผนเดิมประเมินไว้มาก
แก้ในคู่มือใหม่แล้ว

## สิ่งที่ระวังเป็นพิเศษ — โพสต์แล้วลบไม่ได้

ต่างจากทุกปุ่มก่อนหน้าในระบบ ปุ่มนี้ทำสิ่งที่ **ย้อนกลับไม่ได้และคนนอกเห็น**
จึงกันไว้ 5 ชั้น:

1. **กล่องยืนยัน** โชว์แคปชั่น + บอกว่ามีรูปไหม ก่อนกดจริง
2. **`post_id` กันซ้ำ** — Facebook ไม่กันโพสต์ซ้ำให้ ยิง 2 ครั้งได้ 2 โพสต์จริง ๆ
   เช็กจาก `post_id` ไม่ใช่ `status` เพราะ status แก้ด้วยมือได้จากหน้าเว็บ
3. **ต้อง `approved` ก่อน** — route กันเอง ไม่พึ่งว่าปุ่มอยู่ในโซนไหน
4. **ช่องว่างค้าง** `{ชื่อสาขา}` → ปุ่มกดไม่ได้ + route ปฏิเสธซ้ำอีกชั้น
5. **โพสต์ติดแต่เขียน DB พัง** → คืน `post_id` กลับมาพร้อมคำเตือน *"อย่ากดซ้ำ"*
   ไม่ใช่ error เปล่า ๆ · ถ้าคืนแค่ error คนจะกดใหม่แล้วได้โพสต์ซ้ำบนเพจจริง

## ที่ทดสอบได้โดยไม่มี token

ยิง Graph API จริงด้วย token ปลอม — Meta คืน `code 190` ของจริงกลับมา
ใช้ยืนยันได้ว่า:
- ตัวแปล error ทำงาน → ได้ *"Page Access Token ไม่ถูกต้องหรือถูกเพิกถอน — ออกใหม่ด้วย scripts/fb-token.mjs"*
  แทนข้อความอังกฤษดิบ ๆ ที่ไม่บอกว่าต้องไปทำอะไรต่อ
- **แคปชั่นไทย 2,073 ตัวอักษร + emoji ส่งผ่านได้** — ส่งเป็น form ไม่ใช่ query string
  ถ้าใส่ใน URL จะชนลิมิตความยาวตั้งแต่แคปชั่นยาวปานกลาง
- ด่านกันพลาดที่ไม่ต้องยิง API ทำงานครบ (แคปชั่นว่าง / dryRun ที่ไม่มีรูป / ไม่ได้ตั้ง env)

## ยังทดสอบไม่ได้ — ต้องรอเจ้าของ

โพสต์จริงยังไม่เคยเกิดขึ้น เพราะยังไม่มี Page Access Token
**และผมจะไม่ยิงโพสต์แรกเอง** — โพสต์ขึ้นเพจสาธารณะของธุรกิจจริง เจ้าของต้องเป็นคนกด
แผนคือให้ทดสอบด้วย `dryRun` ก่อน (อัปรูปแต่ไม่เผยแพร่) แล้วค่อยกดจริง
