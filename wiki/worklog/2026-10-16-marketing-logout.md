# เข้าเว็บหลักด้วยบัญชีแอดมินแล้วยังถูกพาไป /marketing

เจ้าของ (16 ต.ค.): *"ตอนนี้พอเข้าไปที่หน้านี้ https://division-x-card.vercel.app/ มันเปลี่ยนเป็นหน้านี้เลย …/marketing"*
→ ตอบว่าเบราว์เซอร์ยังเป็นบัญชีการตลาด ให้ออกแล้วเข้าแอดมิน → *"เข้าเว็บหลักด้วยบัญชีแอดมินแล้วยังถูกพาไป /marketing"*

## ที่ตรวจ (อ่านอย่างเดียว)

| จุด | ผล |
|---|---|
| Auth `last_sign_in_at` | แอดมิน `divisionxcard` = **12 ต.ค. 23:38** (วันนี้ยังไม่มีการเข้าด้วยรหัสผ่านที่สำเร็จ) · `aomeiei` (role marketing) = **14 ต.ค. 13:23** |
| ทางที่ "/" พาไป /marketing | มีทางเดียว: `MarketingOnlyScreen` ตอน `profile.role === "marketing"` · `getProfile` กรองด้วย id ของเซสชัน — ไม่มี middleware / redirect ใน next.config / vercel.json / service worker · เมนู "การตลาด" ของแอดมินเป็นลิงก์ธรรมดา |
| ปุ่มออกจากระบบ | **มีที่เดียวในแถบเมนูของแอปหลัก** ซึ่งบัญชีการตลาดไม่เคยเห็น · `MarketingOnlyScreen` · /marketing · /video ไม่มีเลย มีแค่ "← กลับหน้าหลัก" ที่พากลับไปเด้งอีกรอบ |

**สาเหตุ:** เบราว์เซอร์เครื่องนั้นยังถือเซสชันของ aomeiei (เข้าครั้งแรก 14 ต.ค. หลังแก้ username — [[2026-10-12-user-aomeiei-login]])
และ**ไม่มีทางออกจากระบบจากบัญชีการตลาดเลย** → เปิด "/" กี่ครั้งก็ถูกพาไป /marketing ใน 2 วินาที ฟอร์มล็อกอินไม่เคยโผล่
จึงเข้าบัญชีแอดมินจากเครื่องนั้นไม่ได้ (ตรงกับ `last_sign_in_at` ของแอดมินที่ไม่ขยับ) · เซสชัน Supabase ต่ออายุเองไม่มีวันหมด รอเฉย ๆ ไม่หาย

ช่องโหว่เดียวกันในมุมความปลอดภัย: พนักงานการตลาดที่ใช้เครื่องร่วม (เครื่องร้าน) ออกจากระบบไม่ได้ — ใครมาเปิดเครื่องต่อก็เป็นบัญชีเธอ

## ที่แก้

- `lib/supabase.js` → `signOutAndGoHome()`: ออกจากระบบ**เฉพาะเครื่องนี้** (`scope: "local"`) แล้วพาไป "/"
  · ล้มเมื่อไหร่ (เน็ตหลุด · Auth 5xx · ช้าเกิน 5 วิ) **ลบเซสชันในเครื่องเอง** — ดู "กับดัก" ข้างล่าง
- หน้า "/" `MarketingOnlyScreen`: ปุ่ม **ออกจากระบบ / เข้าบัญชีอื่น** — หยุดตัวพาไป 2 วินาทีก่อน ไม่งั้นเด้งไป /marketing กลางทาง
- /marketing (`MarketingOS` → `Shell`) และ /video (`VideoStudio` → `Frame`): ปุ่ม **ออกจากระบบ** ที่หัวหน้า ทั้งตอนเข้าได้และตอน "เฉพาะผู้ดูแลระบบ"
  (ไม่โชว์ตอนยังไม่ล็อกอิน) · มือถือเหลือแต่ไอคอน + ซ่อนคำโปรยใต้ชื่อหน้า (หัว /video เดิมถูกบีบจนคำโปรยตกเป็น 6 บรรทัด)
- จอ "ต้องเข้าสู่ระบบก่อน" ทั้งสองหน้า: ปุ่ม "ไปหน้าเข้าสู่ระบบ" เป็น `signOutAndGoHome` แทนลิงก์ `/`
  — API ตอบ 401 (เซสชันถูกเพิกถอน/หมดอายุ) ทั้งที่เซสชันในเครื่องยังค้าง ลิงก์เฉย ๆ เจอเซสชันเดิม บัญชีการตลาดวนกลับมาจอนี้

## กับดัก (เจอตอนตรวจคู่ขนาน — ยืนยันด้วยการจำลองกับ auth-js 2.102.1 ที่ติดตั้งอยู่)

- **`signOut()` ค่าปริยายคือ `global`** = เด้งบัญชีนี้ออกจาก*ทุกเครื่อง* · เจ้าของกด "เข้าบัญชีอื่น" บนเครื่องร่วม มือถือพนักงานหลุดตาม
  แล้วหน้า /marketing บนมือถือเธอได้ 401 → เข้าจอวนข้างบน → ปุ่มนี้ใช้ `local` (ยังลบเซสชันของเครื่องนี้ฝั่งเซิร์ฟเวอร์ด้วย)
- **auth-js ลบเซสชันในเครื่องเฉพาะตอน `/logout` สำเร็จหรือได้ 401/403/404** — เน็ตหลุด/500/503 เซสชันยังอยู่
  และ `signOut({scope:"local"})` ก็ยิง `/logout` ตัวเดิม (ลองซ้ำไม่ช่วย — รุ่นแรกของ fix นี้พลาดตรงนี้)
  · ออฟไลน์ + โทเคนหมดอายุ signOut ลองต่ออายุนาน ~30 วิ ก่อนตอบ
- จำลอง 7 กรณี (204/401/403/500/503/เน็ตหลุด/ตอบช้า 8 วิ) ด้วยโค้ดจริงจากไฟล์: รุ่นใหม่ล้างเซสชัน+พากลับ "/" ครบทุกกรณี (ช้าสุด 5 วิ)
  · รุ่นแรกค้างเซสชัน 3 กรณี (500 · 503 · เน็ตหลุด) = ตัวจำลองจับบั๊กได้จริง

## เจอแต่ไม่ได้แก้ (ของเดิม นอกเรื่องนี้)

- `GET /api/marketing/content/publish` ส่งต่อ 401/403 ของ Facebook ตรง ๆ และ `MarketingOS.api()` ตีความ 401/403 ทุกตัวเป็น "ไม่มีสิทธิ์"
  → วันไหนโทเคนเพจหมดอายุ หน้า /marketing จะขึ้น "เฉพาะผู้ดูแลระบบ" กับทุกคน (รวมแอดมิน) · route proof/poster ก็ส่งต่อ 401/403 ของ OpenAI/GitHub แบบเดียวกัน
  ทางแก้: ให้ `lib/apiAuth.js` ติดป้าย 401/403 ของเราเอง แล้วหน้าเว็บสลับสถานะเฉพาะที่มีป้าย
